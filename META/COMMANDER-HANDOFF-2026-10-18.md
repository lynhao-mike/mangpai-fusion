#### 0.0.2 ⚠ p-series「完整性漂移」定性被推翻 —— 是行尾假漂移，不是数据被改

上一节 0.8 判定「预测文件与队列清单在冻结后被改动过」「该分类器相关历史指标不得再
作为冻结基线引用」。**实测推翻该定性**：

```
冻结记录值 == git HEAD blob sha256 == LF 归一化后的工作区 sha256   （三者完全相等）
工作区原始字节 != 冻结记录值                                      （仅差行尾）
```

- `tr -d '\r' < 文件 | sha256sum` 与冻结记录值**完全相等**（两个文件均如此）
- `diff`（去 CR 后）为空，字节数差 = 行数 × 1（每行多一个 CR）
- git 中两个文件只有一次提交 `c76d0031`（2026-08-07 snapshot），**冻结日 07-31 之后无任何提交改过**
- 成因：`core.autocrlf=true` + 无 `.gitattributes` → Windows 检出把 LF 转 CRLF

**含义（重要）**：
1. **p-series 历史指标仍然有效**，可作为冻结基线引用。0.8 的「不得再引用」结论作废。
2. 该分类器真实 balanced_accuracy = **0.3625**，确实 < 0.425 基线 → 门禁判定
   「不达标」是**正确的**，只是原来的失败原因被漂移掩盖了。
3. **这是环境问题，不是数据问题。** 门禁 fail-closed 行为本身正确。

同类问题**不止 2 个文件**：全仓扫描发现 **12 处**记录是这种假漂移
（freeze-v1/v2/v3 的 predictions+manifest、score-v1/v2/v3 的 freeze_sha256、
prediction-freeze-v1 的两个、cohort-v2 的 source_manifest_sha256）。

## 六、关键认知

### 6.1 项目真实目标

用户原话：「不管使用哪个流派，至少能把八字分析正确」。
盲测准确率是**唯一能验证这件事的指标**。
**最新严格准确率：第 1–3 批 54.8%（115/210）；含第 4 批全 42 例 53.3%（137/257）。仍然不可用。**
**更关键的是：五道前置关没有提升准确率（第 4 批 46.8%，低于第 1+2 批 56.6%），判平率反而从 20.0% 升到 27.7%。**

### 6.2 三条必须坚持的原则

1. **真值必须来自明确陈述，不能来自沉默**（反馈没提 ≠ 没发生）
2. **指令必须双向对称**（只收紧一侧会致另一侧膨胀，已实际发生两次：
   过凶→过吉；判平→判凶；**合成盘双轮是第三次**）
3. **数字不可信就明说**（本会话作废了 5 个数字，每次都主动标注）
