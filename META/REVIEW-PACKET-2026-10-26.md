> 用法：把下面「一、可直接复制的提示词」整段复制给对方；它自带全部事实，对方**不需要也不能**读仓库。

## 一、可直接复制的提示词

```text
你是八字分析系统「mangpai-fusion」的外部架构审阅者。你看不到仓库，下面是全部事实。
请只依据这些事实回答；不要编造数字，不要假设能读代码，不要重述背景。

【产品目标】
用户原话：「我的目的是能将真实八字分析准确」。目标用户是命理师，主线是咨询交付，
准确率是可靠性门槛而不是唯一目标。系统价值 = 证据链可追溯；假阳性比没有功能更糟。

【已裁决、不要重新讨论的方向】
1. Agent 负责裁决与表达；引擎负责确定性事实 + 可求值断语候选 + 结构性护栏。
2. 断语（claim）是带条件的候选，不是结论；必须带前置条件、失效条件、证伪条件、时间窗、来源锚点。
3. 记分：交付评分（主）+ 准确率（副）+ 一票否决（编造事实 / 悬空引用 / 假阳性证据 / 结果泄漏）。
4. 流派先路由后发言（lead / co_lead / evidence_only / abstain），不允许「多派都发言再事后追认适用性」。
5. 不做全局加权平均、不做固定权重。

【实测事实（2026-10-26）】
· 规则 3699 条：A 类盲派候选 1658（高 630 / 段 428 / 杨 400 / 任 200）；
  B 类生产规则 2041（子平 933 / 滴天髓 1108）。
· A 类只有 414 条有触发条件字段，且内容是中文散文（段 239 / 杨 145 / 任 30 / 高 0）；
  其余 1244 条无触发条件。
· B 类 100% 有触发条件，但只有 8–10 个不同谓词；子平 455 条是 always（恒真）、滴天髓 40 条恒真。
· 现行谓词库 16 个，全部是「整盘级」布尔（如「盘里有冲」「有墓库」），没有一个能指向具体柱位或关系边。
· 规则门禁的兜底只剩 3 个布尔：正文出现「冲刑穿破克」→ 只问盘里有没有冲；「墓/库」→ 有没有辰戌丑未；
  「做功」→ 有没有能量层。结果：1658 条规则在 6 张真实盘上只产生 3 种通过集合（理论上限 8 种）。
· 带行号锚点、能机器回读原文的规则：1433 / 1658（高 405/630，段/杨/任 100%）。
· 具备六要素（条件/排除/反条件/结论模板/证伪/来源）的生产断语：16 条。
· 盲测基线：18 例 / 232 判断点 / 170 个记录年，严格口径 45.3%（77/170）。
  错误构成：59 个方向翻转（过吉 37 > 过凶 22）、34 个「判平」回避（其中 31 个真值有明确方向）。
  6 个错误的逐条归因：6/6 是「条件未齐就开火」（规则边界问题），0 条是真值疑云；
  同时该分析者引用的关系边编号全部错位（引用事故）。
· 职业二分类指标：balanced_accuracy 0.3625，门槛 0.425 / 0.60，未通过。
· 验证资产：cases/ 共 527 个案例，484 个有反馈，482 个有性别；
  其中反馈含 ≥3 个年份事件的 48 个（≥5 个的 14 个），1–2 个的 108 个，0 个的 328 个。
  另有「铁口箓」题库 284 期（有客观选择题答案），其中 36 期已补性别（大运顺逆必需）。
· 一次小样本探针（6 例 / 57 题，同一份六源理论包）：给全量引擎事实 29.8%、
  给薄事实 33.3%、只给四柱 37.5%。样本太小，不能定论。
· 默认测试门禁当前是红的：测试依赖 `.workbuddy-ai/make_bundle_v2.py`，该目录被 gitignore 且本机不存在，
  收集阶段直接报错；排除该文件后 238 passed。另有 tests/r10 4 failed / 60 passed。

【当前设计（已写进 ADR 与契约，但尚未实现）】
L0 确定性事实 → L1 局面画像（盘势，不出吉凶）+ 流派路由 → L2 条件化断语候选
→ L3 结构合法性（框架依赖否决）→ L6 裁决与表达。
断语条件用三值逻辑（真/假/未知，未知不得折叠成假），原子谓词表 v1 共 42 个，要求带盘面地址；
条件化结果放独立文件（因为 index.yaml 是自动生成物），构建期合并；编译器三态（可编译/不可编译/需人工）。
第一批计划 120 条（婚姻/事业/学历/家境 × 四派）。

【请只回答以下 7 个问题】
每个问题：先给一句结论，再给理由、风险、证伪条件、最小验证。每问不超过 300 字。
不要罗列所有可能性，不要给「都重要」的答案。最后一节写：如果只能做一件事，是哪件，为什么。

Q1 顺序：断语条件化（自下而上，逐条补条件）与局面判定/路由（自上而下）互为前提。
   先做哪个？还是先做一个最小的局面画像再条件化？

Q2 谓词粒度：42 个「带地址」的原子是否够？三值逻辑是否够，还是需要强度打分？
   如何避免阈值（如「印 ≥3 个」）拍脑袋？

Q3 编译器：用大模型把中文断语编译成条件树 + 人工复核，如何度量「语义漂移」
   （编译出的条件看起来合理、但原文并不支持）？是否需要「反编译」（条件树 → 中文 → 与原文比对）？

Q4 框架依赖：像段派「做功」必须先定体用宾主、子平「用神」必须先定格局成败，
   这些「框架命题」应由引擎的结构化判定产出，还是允许 Agent 判定并标注？
   如果引擎暂时产不出（例如滴天髓气势），应该弃权还是允许 Agent 判？

Q5 验证与统计：48 例（约 170 个判断点）+ 36 期客观选择题，够不够支撑「改动是否变准」的判断？
   在 45% 基线、n≈170 下，能可靠检测到多大的提升？需要多少样本才能区分 45% 与 55%？

Q6 重构顺序：默认测试门禁已红（缺 `.workbuddy-ai/make_bundle_v2.py`）、r10 有 4 个失败、
   v5 只剩度量链作用（8 个生产工具依赖它）。先修门禁、先动规则、还是先砍 v5？
   顺序上有什么坑？

Q7 存放与合并：条件化数据放独立文件、构建期合并进 index.yaml，还是运行期合并（不改生成物）？
   哪种更不容易被下一次重建覆盖或产生双事实源？
```

## 二、给外部模型的补充说明（不要复制给模型，供你自己判断）

### 每个问题的「我的倾向」与「判定证据」

| 问题 | 我的倾向 | 什么结果说明我错了 |
|---|---|---|
| Q1 | 先插入 1 天的最小局面画像（只用现有事实，不加新计算），再跑批次 1；否则条件化出的断语没有路由可挂 | 若最小画像无法在 1 天内产出可用路由，则先纯条件化 |
| Q2 | 地址级 + 三值；强度只做排序，不做门槛 | 若大量断语必须靠强度才能区分（同一条件下强弱结论相反），则三值不够 |
| Q3 | 大模型编译 + 强制行号锚点 + 三态 + 抽样语义复核；不追求 100% 自动 | 若抽样语义支持率 <70%，说明编译器不可用，改人工模板 |
| Q4 | 框架命题必须由引擎结构化判定；缺则降 `evidence_only`，不允许 Agent 自证 | 若引擎长期产不出关键框架，则产品只能做「事实 + 参考语句」，不能做断语 |
| Q5 | 主基准 48 例，辅基准 36 期，分开记分；先算统计功效再定样本目标 | 若 48 例连 10 个百分点都测不出，则必须扩样本，否则所有 A/B 对比都是噪声 |
| Q6 | 先修门禁（恢复或 vendor 脚本），再动规则；v5 保留到 B 指标有替代 | 若修门禁需要改测试（保护区），则需先拿到授权，不能先动规则 |
| Q7 | 独立文件为唯一事实源，构建期合并；生成物中的字段不手改 | 若构建链无法稳定合并（每次重建丢字段），则改运行期合并 |

### 三个必须由你（用户）拍板、不适合外部模型决定的事

1. **是否授权改测试**：默认门禁的修复可能涉及 `tests/tools/test_bundle_pii.py`（保护区）。
2. **第一批 120 条的域优先级**：婚姻/事业/学历/家境，哪个先做？这取决于你近期咨询的实际需求。
3. **铁口箓剩余性别的补充节奏**：36 期够做小样本，但要支撑统计结论需要更多。

## 三、外部意见回来之后怎么处理

1. 只采纳能落到「可验证动作」的建议；纯观点不写进 ADR。
2. 与 ADR 冲突的意见，先记 `META/arbitration-log.md`，再由你裁决，不直接改 ADR。
3. 每条采纳的建议必须绑定一个验收指标（见契约 23 §八），否则视为未采纳。
