**反面读法**：「X 入 Y 墓」是位移句，句法主语是入库方 X，但动词是「入」，没有对 Y 的施力；Y 是处所（Y 之墓／Y 库）。
把位移主语当 actor，就会把「被收藏方」写成「收藏方」。所以：**只引位语句时 actor=null（标证据缺口），不得据「入」赋向**。

## 3. 四条逐条

### 3.1 P1-H13 · 壬辰 壬寅 己丑 戊辰（乾）

- 答案：`a=辰`、`b=丑`、`actor=辰`；quote「二是丑入辰墓， 为食伤库入了财库」；`L2294`。
- 原文两句并存（**同一行**）：
  - 入墓句：「二是丑入辰墓， 为食伤库入了财库」→ 主语 **丑**（日支、食伤库），处所 **辰**（时支、财库）；
  - 定向句：「**辰墓了丑**」→ 主语 **辰（库）**，宾语 **丑**；又「为别人大 自 己小」——辰是别人（戊劫财）的财库、丑是自己的食伤库，库大者得控。
- 语义：入库方＝丑（己之食伤库，主位）；库＝辰（己之财库）；力向＝**辰→丑**。
- 判定：**`engine_wrong`**。标注 `a=辰、actor=辰` 与同行「辰墓了丑」一致；引擎墓用候选一律写 `actor=入库方`，方向相反。
- 应填：**a=辰 / b=丑 / actor=辰（不变）**；应改：引擎（见 §5）。
- 证据等级：`same_line`。建议 quote 补「辰墓了丑」。
- 引擎现状（另一个缺口）：引擎**有**墓用候选，但没有一条跨 `a=辰 / b=丑`——丑→辰 因两端皆体（丑=比肩、辰=劫财）被 `_crosses` 过滤
  （`structure_check.py:381-382,500`），引擎实际发出的是 壬→辰（财入墓）三条，与答案端点无关；`relations.muku` 命中 `D.b->Y.b`、`D.b->H.b`，
  基线 `direction=no_edge`。**这不是 actor 反向，是端点候选覆盖缺失**（T-179）。

## 4. 总判定与两个「为什么不」

**与 T-174 口径的关系**：T-174 验收写「入墓 → `actor=null`，**除非原文是「库墓X」定向句**」（`tasks/T-174/BRIEF.md` §4.3）。
本次四条正落在这个例外里：H13/H15 的定向句在同一行（「辰墓了丑」／「被辰所控制」），H14 在同页通句（「丑也有墓酉之象」），
H16 有定义句（`L2274`）+「被墓之神」（`L4099`）。所以本次不是推翻 T-174，而是把它的例外条款落到四条上；
真正被推翻的是「入墓→null 一律适用」这个过宽读法。

| 判定值 | 条数 | 说明 |
|---|---:|---|
| `label_wrong` | **0** | a=库、actor=库 与原文力向一致，标注方向没错 |
| `engine_wrong` | **4** | 墓用候选 `members=(入库方,库)、actor=入库方`，应翻转为 `(库,入库方)、actor=库` |
| `convention_conflict` | **0** | 入墓句与库墓句不是两条力向；前者只给位移，后者才给施力 |

**为什么不是 `label_wrong`**：`label_wrong` 的前提是「标注把库当施力方」为错。但 `L2274` 墓＝得到/控制/拥有/占据、
`L2288`「未墓寅」、`L2294`「辰墓了丑」、`L2326`「被辰所控制」、`L2338`「丑也有墓酉之象」、任派 `L21/L23`「墓库…表示制」
全部把库写成施动/控制方。把库当施力方是原文的读法，不是标注的发明。

**为什么不是 `convention_conflict`**：`convention_conflict` 要求原文对**同一力向**有两种读法。这里两种句式承担不同语法功能：
「入」给位移、「墓」给施力，二者可同时成立（X 进入 Y 的墓，且 Y 的库控制 X）。力向唯一，故不成立。
真正的冲突是工程约定：标注的 quote 取了入墓句，引擎的 actor 取了入库方。前者是证据缺口，后者是 bug。

## 7. 规则表覆盖与缺口

`docs/specs/actor-rules-v1.md` 覆盖九类：**合 / 冲 / 刑 / 穿 / 破 / 克 / 生 / 化 / 墓**，每类都有：
`source_ref` + 正例 + 反例 + 引擎映射 + 未知时取值（全部 `null`）。

- **方向类**：克（克者）、生（生者）、化（化者）、墓（库）——engine 的 `ke`/`sheng` 边 members 顺序已对，`墓用` 候选反了。
- **对称类**：合 / 冲 / 刑 / 穿 / 破——engine 现状 `actor=null`（`structure_check.py:475-482` 只有 `ke` 给 actor），**符合本表，保持不动**。
- **缺口**：①九类之外（三合/半合/三会/暗合/自合/伏吟/拱局）本表按无向处理，要做方向须另立卡；②「制」是复合语义，本表只给底层
  mechanism 的 actor，不替调用方折算；③支克干/支-支生仍是不建边的推得关系（G3），本表不改该约定；④墓的「应期/条件」用法
  （冲开墓库）不是做功方向，`actor=null`，不得把开库的冲/刑字当墓的施力方。
