## 1. 一句话

从 `sources/duan/` 的段派教材案例中取出 **20 个有原书完整做功推演的命例**，
把「模型可见的盘面」（四柱/性别/大运/来源定位）与「答案」（原文推演、主功、
体用宾主、成败、救应、应期）**物理拆成两个文件**，每个答案字段都能回到原文的
`path + line + quote`。

## 3. 筛选标准（以及为什么最后是这些例）

进入集合必须同时满足：

1. **原书给出四柱**，且四柱能过 `engine` 回读（干支一字不差；OCR 讹字须有正文自证）；
2. **原书给出大运**（`运：…`／`大运 …`／大运表），并与 `engine` 顺逆排一致
   （书表常以**月柱起首**，与 engine 序列相差首位，本卡统一以 engine 为准，逐例核对，见 §6）；
3. **原书对主功有明确说法**（「伤官去官格」「化用结构」「墓用做功」「解了穿」等），
   不是只有断语；
4. **原书对成败有明确说法**（成局或破局），**最好还有应期**；
5. **四类可归类**，且不与已选命例重复（同盘不重复入集）。

因此被**排除**的典型：

- 只有断语、没有推演过程的《盲派批命案例集》条目（如「例1 乾：己丙丁甲／卯子未辰」后
  直接给婚姻结论，未写体用宾主与做功路径）；
- 无大运序列的纯理论举例（如开山之作「己未 癸酉 壬寅 庚子」虽明标墓用结构，
  但只作 G20-015 保留，`timing` 记 `null`）；
- 同一造两书互见但**时柱打架**者（戊申 甲子 甲寅 丙寅／甲寅：21 与 35 书作丙寅，
  23 书作甲寅，取多数版本并记入 `curator_notes`，未另立一例）；
- 只有「应期」没有「主功」的纯冲合题库例。

## 5. 缺口（如实报，不凑）

1. **化用类的应期缺口**：四类里化用最薄。原书《盲派初级命理学》就写「这种结构比较少」。
   本集 4 例化用中只有 2 例（G20-007、G20-008）原书给了大运吉凶；G20-009（毛泽东造）、
   G20-010（木匠造）原书只给结构判断，`timing` 记 `null`。若按「必须含应期」严卡，
   化用 = 2 例，未达 3 例线——**这是真实缺口，不是筛选失误**。
2. **派别单一**：20 例全部来自段派（`sources/duan/`）。`sources/yang/`、`sources/ren/`
   的命例普遍**不列大运序列**（全书 145 处「大运」里带完整干支表的案例几乎都集中在段派讲义），
   而「制用／化用／墓用／救应」本身是段派做功体系的原生术语。按卡上「每例必须有大运序列」
   的硬标准，杨派与任派无法产生合规样本——**跨派样本缺失**。
3. **起运年龄**：18/20 例原书未写起运，`dayun_start_age = null`；只有 G20-006、
   G20-019 两例书上有岁数表可核。
4. **同造双解**：G20-013（乙酉 己卯 乙未 癸未）在原书 L910–912 与 L926–928 有两套不同读法
   （墓库牢狱 / 两未制财）。本集只取前者，`curator_notes` 已标明，**该例只宜作弱对照**。
5. **OCR 残损**：G20-014 日支原文作「屈」，正文自证为「主位辰」，四柱按 辰 复原；
   G20-016 原文「戍」即「戌」。引用一律保留原字，未改原文一个字。
6. **未作结构绑定（按 T-169 约束处理）**：本版答案只锚定原书文本，`struct_refs.status`
   全为 `book_text_only`，`edge_ids` / `candidate_ids` 为空数组。理由与约束：
   - `--dayun-index/--liunian` 叠加后 `edge_id` 会**全量重编号**（T-169 实测：同一字
     `e012` 从 `liuhe[M.b,D.b]` 变 `ke[M.s,LN2026.s]`，边数 16→39），所以**任何边号
     都必须挂 `chart_snapshot{chart_id, dayun_index, liunian_year}`**，裸边号一律不写；
   - `duan_zuogong.candidates` 只扫「体用相交 + 指定 kind」，**不是关系边全集**
     （T-169 实测三张盘夫妻宫关键边分别漏 3/4/1 条），所以引用主功时必须
     `candidate_id` 与 `relations.edge_id` 两路都给，只给 candidate 的标 `candidate_only`。

   本卡因此**不冒充已绑定结构**：每条答案给了原局 `chart_snapshot.chart_id` 作为可 join 的
   入口，结构绑定留给 T-169 的五元组断语卡层。**风险：若下游误把本集当"已绑定结构"的
   金标，会高估覆盖——请按 `struct_refs.status` 判断。**

## 6. 大运核对结论

逐例把原书大运表与 `engine`（四柱＋性别顺逆排）比对：

- 14 例书表与 engine **逐字一致**；
- 6 例（G20-003、005、011、012、018、020）书表首项多出**月柱**一项，
  去掉该首项后与 engine 前十步逐字一致——属于教材排表体例（月柱起首），不是错误。

盲测输入里的 `dayun` 一律取 engine 的十步，`dayun_direction` 取 engine 的顺/逆。

## 7. 下游须知（schema）

**盲测输入**（`META/golden-20-v1.json`）

```json
{"case_id":"G20-001","school":"duan","four_pillars":"庚午 乙酉 庚子 壬午","gender":"乾",
 "dayun_start_age":null,"dayun_direction":"顺","dayun":["丙戌","…（共10步）"],
 "source":{"path":"sources/duan/…md","locator":"L253-L259"}}
```

- 只含 8 个键，**不含** `original_analysis / core_work / role_direction / adjudication /
  rescue / timing / category`；
- `source` 只留路径与行号，**不含正文**。

**答案**（`META/golden-20-answers-v1.json`）

```json
{"case_id":"G20-001","category":"制用","four_pillars":"…","gender":"乾",
 "original_analysis":"…","core_work":"…","role_direction":"…","adjudication":"…",
 "rescue":null,"timing":["…"],
 "chart_snapshot":{"chart_id":"cf-…","dayun_index":null,"liunian_year":null},
 "struct_refs":{"addresses":[],"candidate_ids":[],"edge_ids":[],"status":"book_text_only"},
 "source_refs":[{"field":"core_work","path":"sources/duan/…md","line":257,"quote":"…"}],
 "curator_notes":"…"}
```

- 每个非 null 字段至少 1 条 `source_refs`，`quote` 是该行**逐字子串**（有测试断言）；
- 多句应期用数组，单句用字符串；无判断写 `null`；
- `category` 只在答案侧出现，**不进盲测输入**（否则等于把类别提示给模型）；
- `chart_snapshot` 一律是**原局快照**（`dayun_index`/`liunian_year` 为 `null`）；
  下游若叠加岁运，必须新建快照，不能沿用本 `chart_id` 下的边号；
- `struct_refs.status`：`book_text_only`（本版全部）/ `candidate_only`（只有候选、
  未拿到对应边）/ `edge_confirmed`（candidate + edge 双路齐全且挂快照）。
  测试 `test_structural_refs_carry_a_snapshot_and_never_a_bare_edge_id` 会挡裸边号。
