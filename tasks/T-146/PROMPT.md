# T-146 · 铁口箓评测管道：本项目第一把「正确性」尺子

- 状态：🔵 Ready for Execution
- 优先级：**P0（最高，先于一切新能力建设）**
- 创建：2026-10-28（中枢）
- 决策依据：ADR-007 之后的新裁决（见本卡 §1）

## 1. 为什么这是最高优先级

项目做了几个月，所有验收指标——开火率、未知率、锚点准确率、可求值率、pytest 通过数——**全是内部自洽性指标**。一条完全错误的断语，可以开火率漂亮、未知率合理、锚点全对。

**从来没有测过一次「断语说得对不对」。**

仓库里其实已经有答案集，一直没人用：`tiekoulu_1507_to_1428.json` —— 铁口箓 284 期，自带标准答案的单选题库。其中 **36 期有性别**（可用于婚姻/子女/职业等判断），这 36 期共 **299 道题**。

本任务把这份答案集变成可复跑的评测管道，量出**第一个真实分数**。

**248 期无性别，不得用于婚姻/子女/大运判定**，只能用若有中性题（如父母）时另议。本卡只做 36 期。

## 3. 要建什么

### 3.1 数据解析

- 从 `line1_solar` 与 `line3_true_solar` 解析出出生时刻。
- **口径按 ADR-005**：优先用 `line3_true_solar`（已校正），`time_basis = true_solar`；解析失败时回退 `line1_solar` 并标 `clock_beijing`。
- 解析失败的期数**必须逐条列出来**，不许静默跳过、不许 `except: pass`。

### 3.2 排盘与断语求值

- 用 `engine.api.analyze_facts`（不是 `engine.cli`，避免 15KB 投影）逐期排盘。
- 用 `engine.claims.condition_ir` 对**当前所有 `compile_state == compiled` 的断语**求值，记录每期每条的 `state`。
  - 断语来源：`theory/claims/conditions-v2/pilot-20.yaml`（当前 12 条 compiled）。
  - **不要修改任何断语**。本卡只测量，不改进。

### 3.3 出分：三层指标，缺一不可

**第一层 · 基线（最重要）**
对每类题计算**多数类基线准确率**：假设永远选该题出现最多的选项，能得多少分。这是「瞎猜」的上限，也是任何断语必须超过的门槛。

**第二层 · 断语命中率**
每条断语在 36 期上的命中数（`state == candidate`）。**命中数为 0 的断语直接标「无法验证」。**

**第三层 · 断语与答案的关联度**
对每个（断语, 题目）组合，比较「该断语命中的期」与「未命中的期」在正确答案分布上的差异。给一个简单、可解释的统计量（例如两组的多数类占比之差，或卡方），并给样本数。

**明确禁止**：不许为了分数好看去调阈值、改断语、挑题。本卡是**测量**，不是优化。第一次跑出来的分数再难看也要如实报。

## 6. 回报格式

报五个数：**36 期解析成功率**、**婚姻/子女/学历的基线准确率**、**有几条断语命中数 >0**、**最高关联度是多少（哪条断语对哪类题）**、**你的结论：现有断语是否超过基线**。

最后一条必须直说。如果全部断语的关联都不超过基线，就写「现有断语未超过瞎猜」——这是本卡最有价值的结果，不许美化。
