## 0. 一句话

定义「什么算分析一张八字」：七段工作流、每段必须带宫位/十神/关系地址、3 张真实盘、
一张可判真假的判定表。**只交规格文档，不写代码、不建模型、不改 engine。**

## 1. 第一性原则

产品的最小存在单元是**一张盘的可复核分析**，不是「10 条规则的正确率」。
如果 3 张真实盘的分析报告被判定为「模板/泛泛」，这个产品形态就不成立；
如果被判为「真分析」，再从报告里挑 1 条断语做预注册验证。

## 2. 「分析」的操作定义（必须写进规格）

一条结论算「分析」，当且仅当同时满足：

1. **有盘面地址**：宫位（年/月/日/时）+ 十神 + 关系边（冲/合/刑/穿/害）或制用候选的 actor/target；
2. **有作用方向**：谁作用于谁（克/生/制/化/合/墓），不能只有 `count`；
3. **有原文/理论锚点**：指向 `theory/` 的具体条目或原文行；
4. **有适用边界**：在什么条件下成立、什么条件下不成立；
5. **可回查**：能按 edge_id / 地址在 `python -m engine.cli all` 的输出里逐项对上。

只有 1–2 条（如「日支被冲」）不叫分析；4–5 条全缺的是模板句。

## 3. 七段工作流（规格主体）

| 段 | 输入事实 | 输出（必须带地址） | 失败模式 |
|---|---|---|---|
| ① 排盘 | `engine.cli chart` | 四柱/十神/宫位/空亡/大运 | 心算/编造 |
| ② 宾主 | 四柱 + 十神 + 宫位 | 哪一宫/哪一神为主、哪为宾；理由 | 只列十神，不定主宾 |
| ③ 体用 | 日主/印/禄/比劫 vs 财/官杀；食伤双属 | 体是什么、用是什么、边界 | 把「用」写成子平用神 |
| ④ 做功 | `duan_zuogong.candidates` + `relations.edges` | 制/化/生/泄/合/墓，每条带 actor/target/edge；无方向要标 `actor=None` | 只有 count（`active_path_count=3`） |
| ⑤ 成败/救应 | ④ 的做功 + 党势/根气/合解 | 成局 / 破局 / 逢救应化解；三态，不许压成布尔 | 把「救应」当「没发生」 |
| ⑥ 取象/落事 | ②–⑤ + 宫位象/十神象/宾主象 | 1–2 句具体、可对照盘面的话；不许模板 | 输出「可能有风险」这类空话 |
| ⑦ 不确定 | 缺口（`actor=None`、合开墓库、无配偶星等） | 哪些能说、哪些不能说、为什么 | 把「不知道」写成「没有」 |

**硬规则**：④–⑥ 每条结论必须能回查；不能回查的，降级为「假设」或删掉。

## 4. 输出 schema

### 4.1 人读报告骨架（`META/single-chart-report-skeleton-v1.md`）

```text
# 单盘分析：<case_id> / <四柱> / <乾|坤>

## 1. 盘面事实（只列事实，不解释）
## 2. 宾主
## 3. 体用
## 4. 做功路径（逐条：宫位 + 十神 + 边/地址 + 方向 + 原文锚点）
## 5. 成败/救应（三态；每条给依据）
## 6. 取象/落事（1–2 句；给可对照的盘面依据）
## 7. 这张盘不能说什么（缺口/不确定性）
## 8. 证据索引（edge_id / 地址 / 原文行）
```

### 4.2 机器 schema（JSON 字段说明，不要求实现）

每条结论至少：`claim_id`、`palace`、`ten_god`、`relation`（kind/edge_id/members）、
`direction`（克/生/制/化/合/墓）、`statement`、`source_ref`、`boundary`、`confidence`
（高/中/低/未知）、`unknowns`。

## 5. 3 张盘

从 `META/timing-eval-set-v1.json` 或 `cases/` 选真实案例（不用合成），必须覆盖：

1. **乾造**：结构完整、做功候选 ≥2；
2. **坤造**：配偶星/夫妻宫有可查地址；
3. **边界盘**：晚子时 / 无配偶星 / 39 例 boundary_warnings 之一 / 多冲。

每张给：case_id、四柱、选择理由、当前事实层能拿到什么、缺什么（G2 `actor=None` 等）。
**选中后写 `META/single-chart-cases-v1.json`。**

## 6. 判定表（给人类用）

### 6.1 单条结论

| 等级 | 定义 |
|---|---|
| **有依据** | 地址/边/原文锚点齐全，能回查，方向明确 |
| **泛泛** | 有地址但只到「某支被冲」，没有作用方向/主体 |
| **错** | 地址或方向与 `engine.cli` 不符，或原文锚点不支持 |
| **无法判** | 事实缺口（`actor=None`、合开墓库等），应降级为「假设」 |

### 6.2 整份报告

| 判定 | 标准 |
|---|---|
| **真分析** | ≥3 条「有依据」，且 ⑥ 的落事能对上盘面；⑦ 诚实列出缺口 |
| **模板** | 多数结论是「泛泛」/模板句；地址只在标题出现；没有方向 |
| **不可用** | 关键地址/方向错误，或把「不知道」写成「没有」 |

### 6.3 Kill criterion

**3 份报告里 ≥2 份被判「模板」→ 这个产品形态停**，不用更多测量掩盖；
要么回到理论建模（需领域专家），要么停项。
