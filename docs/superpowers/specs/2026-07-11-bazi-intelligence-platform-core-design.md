## 2. 核心判断与目标

### 2.1 当前系统定位

当前系统不是通用智能推理系统，而是由以下部分组成的手工工程化专家系统：

1. 以 [`engine/energy/`](../../../engine/energy/)、[`engine/picture/`](../../../engine/picture/)、[`engine/yingqi/`](../../../engine/yingqi/) 和 [`engine/pangzheng/`](../../../engine/pangzheng/) 为主体的手写领域逻辑；
2. 以 [`theory/`](../../../theory/) 为主体的流派知识与原文规则库；
3. 以 [`engine/v5/`](../../../engine/v5/) 和 [`engine/decision/`](../../../engine/decision/) 为主体的五派命题、结构图、仲裁与学习契约骨架；
4. 以 [`tools/render_report.py`](../../../tools/render_report.py) 为主体的统一报告视图和归档链路。

系统已经具备可靠的命盘计算、领域分析、证据记录、报告归档和反馈基础设施，但核心判断质量主要来自手工写入的领域经验，而不是可组合、可学习的通用推理内核。

### 2.2 目标系统

目标不是继续扩展一个规则程序，而是建设一个逐层分权、可解释、可证伪、可校准、可持续迭代的八字智能推理平台：

```text
输入事实
→ 流派适用性
→ 独立命题
→ 结构审查
→ 事件落地
→ 应期概率
→ 冲突仲裁
→ 报告表达
→ 反馈归因
→ 校准治理
```

平台的核心能力不是“规则更多”或“报告更长”，而是：

> 在某类命盘、某类任务、某种时间尺度、证据完整度达到某水平时，识别哪些方法能够提供经过校准且具有增量价值的判断，并让不适用的方法主动退出决策。

这就是“什么八字该用什么法”的工程定义。

## 3. 非谈判原则

### 3.1 知识与代码分离

命理知识、适用条件、反证条件、事件映射和可学习参数必须进入结构化知识对象；Python 代码只实现稳定的谓词、执行、仲裁、校准和持久化机制。新增一条命理经验原则上不应要求修改通用执行器。

### 3.2 规则必须具有判别力

生产规则必须至少包含：

- 可计算或可验证的适用条件；
- 明确的排除条件或反证条件；
- 结构化输出命题；
- 证据引用；
- 可反馈或可证伪口径。

无条件普遍触发的规则不得作为生产决策规则。经典原文可以作为知识来源或解释材料，但原文转录本身不是可执行规则。

### 3.3 置信度属于具体命题

不得使用“某流派对婚姻置信度为 85%”这类全局表达。置信度必须绑定到具体命题、具体命盘、具体任务、具体时间窗和具体证据条件。

流派只能拥有分层统计意义上的能力后验，不能拥有一个脱离上下文的全局置信度。

### 3.4 可证伪才可概率化

只有事件定义明确、时间窗明确、反馈标签明确的命题才允许进入概率层。性格气质、格局审美、宽泛画像等不可稳定反馈的判断可以给出证据强度和不确定性说明，但不得伪装成精确事件概率。

### 3.5 流派必须允许克制

每个流派 runner 对任一任务必须支持三种合法输出：

1. `claim`：满足适用条件并形成命题；
2. `abstain`：知识覆盖该任务，但当前命盘证据不足或不满足适用条件；
3. `unsupported`：该流派当前知识库不覆盖该任务。

不得强迫每个流派在每个领域输出固定数量的断语。

### 3.6 预测与反馈严格隔离

预测输出冻结前，runner、路由器和仲裁器不得读取真实经历、既有反馈、反馈校准后的报告段落或其他形式的答案信息。若发现标签泄漏，相关实验批次整体失效。

### 3.7 决策权必须由条件化能力证据支持

教材篇幅、口诀数量、业内印象、专家声望和架构师指定只能形成冷启动弱先验，不能证明某流派擅长某领域。生产决策权必须由条件化能力后验、校准表现和增量价值共同支持。

### 3.8 角色化融合而非平权投票

不同流派可以承担结构主判、事件落地、时间触发、细节取象和反证审查等不同角色。融合不是少数服从多数；最适合正面判断的流派也未必最适合发现该判断的错误。

## 4. 十层分权目标架构

### 4.1 输入事实层

职责：接收出生信息、性别、历法、大运流年等输入，产生唯一标准命盘对象和确定性派生事实。

边界：只陈述可计算事实，不产生事业、财富、婚姻等解释性结论。

### 4.2 流派适用性层

职责：根据任务、命盘原型、证据完整度和历史能力后验生成路由计划。

边界：决定谁获得本次分析机会与决策权，不替流派产生命题，也不修改流派原始结论。

### 4.3 独立命题层

职责：每个流派只读取同一份命盘事实和路由任务，独立输出 `claim / abstain / unsupported`。

边界：流派之间不得读取中间命题；不得直接生成最终报告。

### 4.4 结构审查层

职责：把事实、命题、证据、反证和依赖关系组织为结构图，识别结构冲突、事件冲突、时间冲突、程度冲突和表达冲突。

边界：不以自然语言相似度代替结构关系，不直接决定最终事件概率。

### 4.5 事件落地层

职责：把结构命题映射为可观察的现实事件类型，区分同一命理信号的多种现实表现。

边界：不得把宽泛结构倾向直接等同于唯一现实事件。

### 4.6 应期概率层

职责：对白名单事件估计概率区间、时间窗、触发条件和反证口径。

边界：不允许伪精确概率；不允许对不可反馈命题概率化。

### 4.7 冲突仲裁层

职责：分别完成结构合法性、事件落地、概率应期三段裁决，保留胜出观点、少数派观点和冲突理由。

边界：不得仅按规则数量、流派票数或静态权重决定胜负。

### 4.8 报告表达层

职责：只消费仲裁结果、预测账本和必要的可展示证据，生成统一报告 ViewModel。

边界：报告层不得反向修改推理结论，不得读取 runner 私有中间态，不得泄露内部 ID 和学习索引。

### 4.9 反馈归因层

职责：把反馈映射到具体命题、流派、规则、任务、命盘原型、预测及时间偏差。

边界：不能把一次总体反馈粗暴分摊给所有参与规则；无法归因时必须标记 no_data 或进入人工审查。

### 4.10 校准治理层

职责：维护规则后验、流派条件化能力后验、校准曲线、漂移检测、人工裁决、版本冻结和回滚。

边界：小样本不得自动重写核心规则；任何生产权重更新必须可追溯、可复现、可回滚。

## 5. 核心领域对象

### 5.1 Chart

标准命盘对象，包含四柱、性别、历法、大运流年和输入完整性元数据。它是所有流派共享的唯一出生事实输入。

### 5.2 Fact

由确定性计算得到的原子事实，例如干支关系、十神、旺衰候选、冲合刑害、宫位关系和大运流年触发。每个 Fact 必须记录来源算法和版本。

### 5.3 ExecutableRule

可执行知识单元，至少包含：

```text
rule_id
school_id
task_scope
required_facts
optional_facts
exclusions
prerequisites
conclusion_template
counter_conditions
falsifier
source_refs
lifecycle_state
```

### 5.4 Task

统一可评估任务。领域必须进一步拆为可验证问题，例如婚姻领域拆成晚婚、离婚/再婚、关系压力、配偶职业、婚恋时间窗和配偶画像。

### 5.5 ChartPrototype

用于描述方法适用性的稳定命盘结构原型。原型必须由可计算 Fact 组成，不得仅依赖专家自由文本标签。

### 5.6 ApplicabilityProfile

描述某次分析中流派与任务的适用性，包含适用条件、证据完整度、能力后验引用和路由理由。

### 5.7 Claim

流派独立命题。必须包含命题类型、立场、证据、反证、时间线索、置信度来源、可证伪口径和适用性快照。

### 5.8 ClaimGraph

连接 Chart、Fact、Rule、Claim、Task、Event 和 Timing 的结构图。关系至少包括 supports、weakens、conflicts、prerequisites、targets 和 timed_by。

### 5.9 ArbitrationResult

三段仲裁结果：结构合法性、事件落地、概率应期。每段记录主结论、少数派观点、支持与反对证据、冲突类型、置信度和理由。

### 5.10 Prediction

可反馈事件预测，包含事件标签、概率区间、时间窗、触发条件、反证条件、校准备注和反馈状态。

### 5.11 FeedbackObservation

从真实反馈得到的标准化观察，记录标签来源、可信等级、时间、冲突状态和是否可量化。

### 5.12 LearningSignal

反馈到知识和能力模型的归因结果。它只能表达“哪些对象应被统计或审查”，不能直接修改生产规则。

### 5.13 CapabilityPosterior

流派在特定条件下的能力后验。最小身份维度为：

```text
school_id
task_id
chart_prototype_id
claim_type
time_horizon
evidence_completeness_band
```

最小统计字段为：

```text
coverage_rate
discrimination_score
accuracy_score
calibration_error
incremental_gain
posterior_mean
credible_interval
N_eff
evidence_grade
last_evaluated_at
```

## 6. 流派能力认定原则

### 6.1 五维能力模型

一个流派“有置信度”不等于它“擅长”。能力至少拆成五项：

| 维度 | 含义 |
|---|---|
| 覆盖率 Coverage | 是否经常能够对该任务形成有效命题 |
| 判别力 Discrimination | 判断是否能区分不同命盘，而非普遍适用 |
| 准确率 Accuracy | 在可验证事件上的实际表现 |
| 校准度 Calibration | 声称概率与实际频率是否一致 |
| 增量价值 Incremental Value | 加入该流派后是否改善已有融合结果 |

某派可以覆盖广但不准确，可以准确但置信度虚高，也可以单独准确但不提供融合增益。只有在特定任务和命盘原型下表现出稳定、校准且不可替代的增益，才构成生产意义上的专长。

### 6.2 条件化能力张量

不得以“流派 × 领域 → 固定权重”的二维表作为长期路由模型。目标模型是：

```text
流派 × 任务 × 命盘原型 × 命题类型 × 时间尺度 × 证据完整度
→ 覆盖率、判别力、准确率、校准误差、增量价值、不确定性
```

领域级权重只能作为样本不足时的上层先验。

### 6.3 能力证据等级

```text
E0 专家共识先验
E1 历史回看
E2 历史盲测
E3 前瞻盲测
E4 真实生产预测
```

E0 只能用于冷启动；历史案例即使盲测，也可能受到规则开发时见过案例的污染。只有 E3/E4 证据可以把“暂定专长”升级为稳定生产路由依据。

### 6.4 增量价值实验

每个流派至少接受四组对照：

```text
A. 只使用该流派
B. 使用所有流派
C. 使用所有流派但移除该流派
D. 基础事实模型加该流派
```

核心指标：

```text
incremental_gain = Score(全流派) - Score(移除该流派)
```

规则数量、理论篇幅和单派表面命中率不得替代增量实验。

### 6.5 层级 Bayesian 收缩

能力模型按以下层级组织：

```text
全局流派能力
→ 流派 × 领域
→ 流派 × 任务
→ 流派 × 任务 × 命盘原型
```

样本不足时，细分后验必须向上级均值收缩；样本增长后，细分能力才逐渐获得独立决策权。路由决策应惩罚不确定性，不得只比较后验均值。

## 7. 推理、路由与仲裁原则

### 7.1 正确决策顺序

```text
命盘事实
→ 识别任务与命盘原型
→ 查询各流派条件化能力后验
→ 排除 unsupported
→ 对低适用性流派请求 abstain
→ 选择一至两个主力流派及至多一个反证流派
→ 独立产生命题
→ 构建结构图并识别冲突
→ 三段仲裁
```

### 7.2 路由输出

路由计划至少包含：

```text
primary_schools
counter_school
abstain_candidates
unsupported_schools
route_rationale
capability_snapshot_id
```

如果没有任何流派达到最低证据要求，系统必须输出“证据不足”，不得依赖静态权重强行选出赢家。

### 7.3 主力与反证角色

主力流派负责形成正面判断，反证流派负责寻找结构、气势、事件或时间上的否决条件。反证流派不是装饰，也不因少数地位被自动降权。

### 7.4 不确定性传播

命题置信度、仲裁置信度、事件概率、能力后验和反馈可信度必须分离。上游不确定性必须对下游设置上限，任何环节不得凭自然语言表达强度把低置信命题提升为高置信结论。

## 8. 学习与治理原则

### 8.1 统一任务和反馈口径

不同任务使用不同评分协议：

- 二元事件：概率评分；
- 多分类事件：分类概率评分；
- 时间窗：命中与时间偏差；
- 等级预测：有序误差；
- 画像判断：双盲标签一致度；
- 不可证伪命题：不进入准确率统计。

不得以单一“命中率”评价所有命题。

### 8.2 克制行为治理

`abstain` 应在证据不足时得到合理奖励，在本可做出高价值判断时受到机会成本惩罚。`unsupported` 只描述知识覆盖，不参与准确率竞争。

### 8.3 高风险断语

健康灾厄、死亡、重大疾病、离婚和重大财务损失等高风险断语必须采用更高假阳性成本、更严格概率门槛和更清晰风险声明。

### 8.4 人工裁决边界

以下情况必须进入人工裁决：

- 反馈来源互相矛盾；
- 反馈无法映射到具体命题；
- 样本漂移或异常批次；
- 规则后验变化可能影响多个领域；
- 生产路由权重发生大幅变化；
- 发现潜在标签泄漏。

### 8.5 版本冻结与复现

每次正式运行必须保存：

- 输入和 Fact 版本；
- 规则库版本；
- 能力后验快照；
- 路由计划；
- runner 输出；
- 仲裁结果；
- 预测冻结时间。

任何反馈学习不得改变历史运行快照。

## 9. 成功定义

目标平台成功不以规则数量、模块数量或报告长度衡量，而以以下能力衡量：

1. 同一输入、同一版本可重复产生一致推理轨迹；
2. 生产规则具有可测判别力；
3. 结论可追溯到 Fact、Rule、Claim 和仲裁结果；
4. 概率预测经过校准；
5. 流派路由在特定任务和命盘原型上优于固定领域权重；
6. 流派的增量价值可由移除实验验证；
7. 系统能在证据不足时主动克制；
8. 反馈能准确归因且不会污染历史预测；
9. 新知识和新权重经过盲测与前瞻验证后才进入生产；
10. 随案例增加，条件化路由和事件预测在独立评估集上持续改善，而不是只在已知案例上拟合。

## 10. 禁止事项

- 禁止把原文转录直接当作生产规则；
- 禁止无条件触发规则参与生产决策；
- 禁止手工写入伪装成统计结果的 posterior；
- 禁止用反馈校准后的报告评价预测能力；
- 禁止强迫每个流派对每个领域发言；
- 禁止用规则数量或多数票替代仲裁；
- 禁止把全部命理判断概率化；
- 禁止让报告模板生成推理层不存在的结论；
- 禁止让静态领域权重冒充已验证专长；
- 禁止在没有能力快照的情况下复用历史结论；
- 禁止小样本自动改写核心生产规则；
- 禁止为兼容内部旧实现牺牲目标架构边界。

## 11. 与现有权重的关系

[`engine/domain-weights.yaml`](../../../engine/domain-weights.yaml) 应被理解为专家书写的领域专长假设，只能用于历史解释或冷启动研究，不构成专长证明。

[`engine/expert-weights.yaml`](../../../engine/expert-weights.yaml) 是当前三专家运行时权重事实源，可以继续承担兼容流程的冷启动先验，但其固定数值不得被解释为实验测得能力。未来条件化能力后验应使用独立事实源，不能继续塞入静态领域权重文件。

## 12. 第一推进原则

本文批准后，第一推进单元不是全面重构，而是建立流派能力评估协议与最小盲测数据包，先验证“流派专长是否真实存在、存在于什么颗粒度”。只有该能力假设获得证据后，才实现复杂的适用性路由器。

具体假设、实验、阶段门禁、失败处理和迁移顺序见 [`plans/bazi-intelligence-platform-roadmap.md`](../../../plans/bazi-intelligence-platform-roadmap.md)。

## 附录 A：2026-07-12 as-built 审计与评估框架落地

> 本附录记录一次代码级审计的稳定结论，用于把“目标架构”与“当前真实实现”之间的差距钉死为可执行判断。附录只陈述结论性事实与由此产生的架构原则；易变的阶段状态、样本量与门禁进度仍以 [`plans/bazi-intelligence-platform-roadmap.md`](../../../plans/bazi-intelligence-platform-roadmap.md) 为准。

### A.1 as-built 真实实现结论

审计区分了“契约与词汇”与“真正运行的内核”，结论如下：

1. **主干仍是串行管线，而非多流派并行竞争。** [`engine/application/pipeline_runner.py`](../../../engine/application/pipeline_runner.py) 的实际路径是 `energy(段) → picture(杨) → yingqi(任) → pangzheng(高) → integrate`，各派承担不同工序，彼此不就同一命题竞争或否决。这是工位流水线，不是专家会诊。
2. **v5 五派并行是骨架，命题多为人工写入。** [`engine/v5/runner.py`](../../../engine/v5/runner.py) 自述“只建立最小闭环”；案例中的 school-claims 带有人工手写 ID 与整段命理话术（如 `v5-034-ziping-structure-001`）。据此评估准确率，评估的是人的水平而非系统能力。
3. **理论规则以原文转录为主。** [`theory/ziping/index.yaml`](../../../theory/ziping/index.yaml)、[`theory/tiaohou_ditiansui/index.yaml`](../../../theory/tiaohou_ditiansui/index.yaml) 的 `claim` 字段是整段古籍原文；三盲派多为 `promoted` 但缺可判别 `trigger`；高派规则大量停留在 `candidate`。违反 §3.2 判别力原则。
4. **L6 仲裁无命理逻辑。** [`engine/decision/l6_arbitration.py`](../../../engine/decision/l6_arbitration.py) 仅按置信度差距选 winner/coexist/unresolved，`arbitration_rule` 字段存的是说明性文字而非可执行逻辑；未实现 §4.7 的结构/事件/应期三段裁决。
5. **L1 路由静态、L9 学习线性。** [`engine/decision/l1_school_router.py`](../../../engine/decision/l1_school_router.py) 的 `SCHOOL_PROFILES` 是硬编码领域分配 + 全局命中率降权；学习闭环仅做 rule/family 两级 alpha/beta 线性加减，无 §6.2 的条件化能力张量更新。
6. **反馈数据尚未成型。** 多数案例 `feedback.md` 的标注位仍为空 `[ ]`，学习闭环缺乏真实标签燃料。

### A.2 差距的四个致命项

对照 §4 十层目标，以下四层是决定“能否越来越懂什么八字用什么法”的核心缺口，须优先补齐：

- **L1 适用性不可学习**（最核心）：系统无法根据命局类型动态决定信谁。
- **L2 命题非引擎推导**：命题人工写入，导致学习闭环从源头失真。
- **L6 仲裁缺命理逻辑**：只比数字，不做分段裁决与矛盾对撞。
- **L9 学习是“拧螺丝”非“学模型”**：线性微调规则权重，学不到条件化适用性。

### A.3 评估框架已落地（合并入 main）

流派能力盲测评估框架已作为第一推进单元完成并合并（见路线 §15）：

- 位置 [`engine/evaluation/`](../../../engine/evaluation/) 与只读 CLI [`tools/school_capability_baseline.py`](../../../tools/school_capability_baseline.py)；
- 覆盖盲测冻结、任务型评分、六维条件化能力后验、四组增量实验、报告门禁重算；
- 经七任务 + 三轮整体验收，147 项 evaluation 测试通过；
- 它是本平台**唯一的能力验收基座**：后续每个升级阶段“是否真的变准了”，都由它的六维能力后验与盲测门禁裁定。

### A.4 由 as-built 结论新增的架构原则

**A.4.1 命局特征向量是全平台脊椎。** L1 分型、L6 加权、L9 条件化学习必须共享同一份由 Fact 组成的结构化命局特征向量（对应 §5.5 ChartPrototype 的可计算化落地）。没有它，“什么八字用什么法”无法工程化。

**A.4.2 能力回流飞轮是最高杠杆动作。** 评估框架产出的六维能力后验（§5.13）必须存在一条通往 L1 路由的回流通道：`评估六维后验 → L9 条件化更新 → L1 分型权重`。当前该通道完全断开；接通它是把“称”变成“会自我改进的厨师”的关键。任何升级排序都应优先保证该飞轮闭合。

**A.4.3 命题引擎化是评估有效性的前提。** 在 L2 命题仍由人工写入期间，能力后验只反映人工水平；因此 L2 引擎化必须先于或同步于 L1 学习化，否则飞轮学到的是噪声。
