## 0 · 一句话

**`actor` 只回答一个问题：这句话的施力方是谁。** 答案只能来自原文的句法（主动句主语、被动句的施动方），
不能来自「金克木」这类五行流向，也不能来自十神角色（伤官制官）。句法没给 → `actor=null`，并在标注里记 `evidence_gap`。
**对称关系一律不赋向**；`墓` 的施力方是**库**，不是入库方（T-178 审计结论）。

## 1 · 字段与定义

| 字段 | 定义 | 约束 |
|---|---|---|
| `a` | 施力方；救应类为解救方 | 指向盘面地址或原文单字 |
| `b` | 受力方；救应类为被作用/威胁方 | 与 `a` 不同 |
| `actor` | 原文明确指出的施力方 | **必须等于 `a`**；无明示则 `null` |
| `kind` | 四类主功：制 / 化 / 墓 / 救应 | 见 hold-out schema |
| `mechanism` | 底层机械关系：制/合/冲/穿/克/刑/墓/化/生 | 与 `kind` 分开记 |

术语：

- **句法主语**：所引句（quote）里做主语的成分。被动式（「被 X 所 Y」「X 受 Y」「X 被 Y 穿倒」）的施动方是 `被` 后那一方，不是句首主语。
- **位移句**：「X 入 Y 墓 / X 入 Y 库 / X 入墓于 Y」。主语是**入库方**，Y 是处所；句中没有施力动词 → 不给 `actor`。
- **定向句**：「Y 墓 X / Y 合去 X / Y 冲制 X / X 被 Y 所化 / Y 穿了 X」等有施动方的句子 → `actor` = 施动方。
- **对称关系**：合（五合/六合/暗合/自合）、冲、刑、穿（害）、破。`A B 合`「相冲」「互破」「三刑」「自刑」不区分施受。
- **力向**：非对称关系（克/生/化/墓）从施力方指向受力方的方向。
- **`evidence_gap`**：原文有力向但所引句/所引行没有明示；标注保留原 `actor`，但必须记缺口等级（见 §4.10）。

三条硬规则：

1. **只认明示**：`actor` 必须是所引句（或所引 `path:line` 行内）写出来的施力方，不由 reviewer 补。
2. **对称不赋向**：合/冲/刑/穿/破没有施受，`actor=null`；要谈谁得利，用体用/宾主，不用 `actor`。
3. **不用五行流向代替句法主语**：引擎的 `ke`/`sheng` 边按五行定源（§5），这是机械关系；但**给原文句子标 `actor` 时必须用句法**，
   不得因为「金克木」就把句中的木写成施力方，也不得因为「水生木」把被生的一方写成生者。

## 4 · 逐类细则

### 4.1 合（五合 / 六合 / 暗合 / 干支自合）

- 判据：合是**对称**关系。`A合B` 只说明两者结合，不说明谁施力；只有在句子给出及物谓语时才给 `actor`：
  「己劫**合杀**」（己合甲杀，己是施动方）、「丁火偏星…**被壬水合去**」（壬水是施动方）。
- 正例（定向）：
  - `sources/duan/MinerU_markdown_28.命理指要_2056045424658808832.md:L2142`「喜年干透己劫合杀」——己（劫）合甲（杀），`actor=己`。
  - `sources/duan/MinerU_markdown_23.盲派中级命理学_2056045463376420864.md:L4083`「又被壬水合去」——`actor=壬水`。
- 反例（对称，不得赋向）：
  - `sources/duan/MinerU_markdown_22.盲派初级命理学_2056045493286002688.md:L2408`「丙辛合意在去财。 为劫去财。」——「丙辛合」本身无施受；
    方向由「为劫去财」（丙是劫、辛是财）给出，属十神角色，不是合句的 `actor`。
  - `sources/duan/MinerU_markdown_19.《盲派高级班面授班笔记》卜文(段建业)_2056045264046317568.md:L489`「乙庚合，偏财被克」——合句与克句分开，合句 `actor=null`。
- 陷阱：把「合」当「合去」。合去/合杀/合绊是**结果**，不是合句的句法；没有「合去」谓语的合句一律 `null`。
- 引擎：`wuhe`/`liuhe`/`zhi_anhe`/`ganzhi_zihe` 的 members 按柱序，`structure_check.py:481-482` 对 `_HE_KINDS` 给 `actor=None`——**符合本表，保持**。

### 4.2 冲（六冲 / 天干冲）

- 判据：对称。`A冲B`／`A冲制B` 或被动 `B被A冲制` 才给 `actor`。
- 正例：`22:L2704`「壬被丙冲制， 子被午冲制」——`actor=丙`（冲壬）、`actor=午`（冲子）。
- 反例：`23:L5727`「卯酉冲制官了」——复合主语「卯酉」共同作「冲制」的主语，没有单一施力方；答案若写 `酉`，是根据
  「伤官（酉）制官（卯）」的十神角色补的，**不是所引句明示**。
- 陷阱：按书写顺序取第一个字当 `actor`。反例里顺序是「卯酉」，真正的制方是酉——顺序不承载方向。
- 引擎：`chong`/`stem_chong`，`actor=null`（`structure_check.py:475-478` 只对 `ke` 给 actor）——**符合，保持**。

### 4.3 刑（三刑 / 自刑 / 子卯刑）

- 判据：刑通常是**成组**关系（寅巳申、丑戌未、子卯、辰午酉亥自刑），成组即无单一施力方 → `null`。
  只有单字主语「A刑B」或岁运句「A刑开B」才给 `actor=A`。
- 正例：`33:L942`「卯刑子主官司」——`actor=卯`；`墓__穿:L9`「戌年正好刑开丑库」——`actor=戌`（岁运）。
- 反例：`16:L2767`「子卯刑，刑坏寿元星」——成组，`null`；`33:L710`「未戌刑」——成组开墓，`null`。
- 陷阱：把「刑开墓」的主语当墓的施力方。开库是**应期条件**，不是墓用的力向（§4.9）。
- 引擎：`xing`（含 `zixing`/`huxing`/三刑组），`actor=null`——**符合，保持**。

### 4.4 穿（六穿 / 害）

- 判据：对称，但原文常写及物式「A穿了B」「A穿倒B」「B被A穿」→ `actor=A`。
- 正例：`22:L2252`「戌酉穿， 羊刃穿了官杀库」——`actor=酉`（羊刃）；`墓__穿:L109`「子被未穿」——`actor=未`。
- 反例：`墓__穿:L104`「酉戌穿,丑午穿」——并列列举，无施动方，`null`。
- 陷阱：把并列的第一字当 `actor`。同一条 H02 里，句首是「戌酉穿」，真正的穿方是酉。
- 引擎：`chuan`，`actor=null`——**符合，保持**。

### 4.5 破（六破 / 段派破）

- 判据：对称。`A破B` 给 `actor=A`；「互破」`null`。
- 正例：`33:L942`「卯破午主破財」——`actor=卯`；`19:L1017`「前造卯破午」——`actor=卯`。
- 反例：`22:L2346`「子卯互破」——`互`字明示双向，`null`。
- 陷阱：破有两套表（`_PO_CLASSIC` 与 `_PO_DUAN`，`relation_graph.py:55-56`）；两套都只决定「是不是破」，**不决定 actor**。
- 引擎：`po`，`actor=null`——**符合，保持**。

### 4.6 克

- 判据：克是非对称。主动句取克者；被动句（`被`/`受`）取施动方，**句首主语是受方，不能当 `actor`**。
- 正例：`28:L2114`「有时上午火,紧克申金,救应寅木」——`actor=午`；`22:L2286`「官杀来克身」——`actor=官杀`。
- 反例（句首主语是受方）：`17:L171`「日干身弱被官杀克」——`actor=官杀`，不是「日干」；`16:L581`「丙印被癸财克坏」——`actor=癸财`。
- 陷阱：藏干克（支克干）没有直接的边，`structure_check.py:433-448` 推得 `(支, 干)`，`actor=支`（宫制星）；标注时要写清「via 藏干」，
  不得因为「支不建克边（G3）」就说没有克。
- 引擎：`ke` members=(克者,被克者)（`relation_graph.py:190-200`），`actor=members[0]`（`structure_check.py:475-478`）——**符合，保持**。

### 4.7 生（含泄）

- 判据：生是非对称。主动句取生者；受生句（`受…之生`）的句首是受方。
- 正例：`22:L2186`「巳化尽旺杀生身」——`actor=巳`（化杀、生身）；`墓__穿:L125`「庚金生坐下子水和年干壬水」——`actor=庚`。
- 反例：`应期:L206`「原来癸受天干庚辛之生」——句首「癸」是受生方，`actor=庚辛`。
- 陷阱：链式句「杀生印、印生身」有两个生者，不能并成一条 `actor`；按子句拆。
- 引擎：`sheng` members=(生者,被生者)（`relation_graph.py:193-196`），`actor=members[0]`——**符合，保持**；
  支-支生不建边（G3），由 `_derived_sheng` 以本气推得（`structure_check.py:415-430`），`actor=源端`。

### 4.8 化（官杀→印；合化另计）

- 判据：化是非对称。`A化B`／`A化尽B`／`B被A化`／`B被A所化` → `actor=A`。
- 正例：`23:L3055`「甲寅七杀被旺火所化」——`actor=旺火`（午）；`19:L127`「财子水被寅化」——`actor=寅`；`22:L2186`「巳化尽旺杀」——`actor=巳`。
- 反例：「合化成局」与「自化」不是单字施力：
  - `16:L469`「用神被合化成忌神」——化的是三合局整体，`actor=null`；
  - `16:L1527`「杀印相生自化」——`自化` 无外部施力方，`actor=null`。
- 陷阱（T-181）：化的力向与生相反——**被化者（生端）→ 化者（受生端）**；化者＝把来力消化／转化为己用的一端。
  引擎用 `sheng` 边承载化（无「化」kind），**不得**因此把 `actor` 写成生者（被化者）；只翻 `mode=化用` 候选，`sheng`/`生泄用` 不动。
- 引擎：`mode=化用` 候选（官杀→印）members=(化者,被化者)、`actor=members[0]=化者`；`sheng`/`生泄用` 候选仍为
  (生者,被生者)、`actor=生者`（T-181）——**符合，保持**；引擎无「化」kind（freeze v2 映射 化→sheng）。

### 4.9 墓（muku）

- **力向：库 → 入库方。** `库` 收藏、控制、拥有入库方；入库方是被收藏方。
- 正例（原文定向句/控制句）：
  - `22:L2288`「未墓寅， 就是此造的做功方式」——`actor=未`（库）；
  - `22:L2294`「辰墓了丑」——`actor=辰`（库）；
  - `22:L2338`「当然丑也有墓酉之象」——`actor=丑`（库）；
  - `22:L2326`「被辰所控制」、`22:L2328`「最后被主位的辰土控制」——`actor=辰`；
  - `任:L23`「我们把地支墓库看作八字中一种重要的作用方式」（紧接下句「也表示『制』的意思」）——墓＝制，制者为库。
- 反例（只给位移，不给力向）：
  - `22:L2300`「酉入坐下的丑库」——主语是入库方酉，`actor=null`；
  - `任:L29`「寅、申、巳、亥见各自的墓库为入墓库」——条件句，`actor=null`。
- 判据落地：
  1. 有定向/控制句（`Y墓X`、`X被Y所控制`、`X被墓之神`）→ `actor=Y`（库），`a=Y`、`b=X`；
  2. 只有位移句 → `actor=null`，记 `evidence_gap`，**不得**把「入」的主语写成 `actor`；
  3. 墓作应期/条件（冲开墓库、库不开）→ 不是做功方向，`actor=null`，不得把开库的冲/刑字当墓的施力方。
- 引擎：墓用候选现状 `(入库方, 库)`、`actor=入库方`——**错**（T-178 审计 4/4 `engine_wrong`），应改为 `(库, 入库方)`、`actor=库`；`relations.muku` 事实层不动。

### 4.10 证据分级（`evidence_gap`）

| 等级 | 含义 | 处理 |
|---|---|---|
| `same_line` | 定向句与 quote 在同一 `path:line` | 正常入分母 |
| `same_page_other_case` | 定向句在同页另一造（同一本书的通用句） | 入分母，标缺口；最严口径可转 sensitivity |
| `doctrine_only` | 只有定义句/通用句式，本造无定向句 | 入分母，标缺口；最严口径可转 sensitivity |
| `gap` | 原文无任何定向线索 | `actor=null`，不得赋向 |

### 5.3 `actor` ≠ 宾主方向

`actor` 是关系的施力方；`binzhu.direction` 是体用两端在主/宾位上的正向反向。二者独立：

- 不得因为 `actor` 落在宾位就改判正向/反向；
- 也不得因为体用是「用克体」就把 `actor` 补成用方——那是十神角色推断，不是句法。

### 5.4 实现纪律

1. **只按表**：`structure_check.py` 的 actor 逻辑只实现本表；不得为 hold-out/dev 的某条 case 打补丁。
2. **不改断言让红变绿**：修 actor 时若测试失败，改实现或按 ADR-004 重写测试的**构造**，不得放宽断言。

4. **未知即 null**：表未覆盖的 kind/句式，`actor=null`，并在 `notes` 写明「规则表未覆盖」。
