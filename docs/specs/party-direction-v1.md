## 2 · 计数口径（写死，不接受运行时改动）

### 2.1 计数单位

- 单位是 **「项」**：一个整数 `1`。没有 `0.5`、没有小数、没有百分数、没有比值、没有权重系数。
- 位置集合固定为**八位**：`Y.s M.s D.s H.s`（四天干）+ `Y.b M.b D.b H.b`（四地支）。
  地址编码沿用引擎（`docs/agent_tools.md` §地址编码）。
- 八位**同权**：不因年/月/日/时、不因邻/隔、不因体/用而加减。

### 2.2 四类计数项

记 `n_F` = 火党计数，`n_W` = 金水党计数，初值均为 `0`。

| 项 | 名称 | 匹配对象 | 每匹配计 | 说明 |
|---|---|---|---|---|
| **A** | 天干位 | 4 个天干，逐字 | `1` | `戊`、`己` 记 **中立**（`0`），理由见 §2.4 |
| **B** | 地支本气位 | 4 个地支，逐字 | `1` | 取该地支**本气五行**；地支属土时按**地支燥湿**归党（§2.4） |
| **C** | 中余气透干位 | 每个「地支 × 非本气藏干」对，逐对 | `1` 或 `0` | 仅当该藏干**同字**出现在四天干之一时计 `1`；每个「地支 × 藏干」对**最多计 1**，不按透干次数倍增；藏干属土记中立 |
| **D** | 得令 | 月支 `M.b`，全盘至多一次 | `1` 或 `0` | 把 `1` 加给**月支本气所属的党**；土月支按燥湿 |

**本气不重复计**：地支本气只由 B 计 1 次；C 只处理**非本气**藏干。

**C 的「透干」是「同字」，不是「同五行」**：`甲` 透只证明 `甲` 透，不能证明 `乙` 透。
理由：同五行透干会把「同一五行」当成「同一个字」，引入一条未声明的等价；同字是字面可核的。
判别向量见 §2.8（V1a 中 `壬` 不使 `辰` 藏的 `癸` 透出）。

### 2.3 藏干固定表（只用于 C）

只列**非本气**藏干；本气由 §2.2 B 处理。集合顺序不承载权重，中气与余气**同权**。

| 地支 | 非本气藏干 | 说明 |
|---|---|---|
| 子 | （无） | 独癸 |
| 丑 | 癸、辛 | 本气己 |
| 寅 | 丙、戊 | 本气甲 |
| 卯 | （无） | 独乙 |
| 辰 | 乙、癸 | 本气戊 |
| 巳 | 庚、戊 | 本气丙 |
| 午 | 己 | 本气丁 |
| 未 | 丁、乙 | 本气己 |
| 申 | 壬、戊 | 本气庚 |
| 酉 | （无） | 独辛 |
| 戌 | 辛、丁 | 本气戊 |
| 亥 | 甲 | 本气壬 |

两条刻意的简化，必须写明：

1. **中气与余气同权**：原文没有给二者整数权重；区分它们就必须发明权重，违反「只允许整序数、禁止权重」。
   本规格因此把它们合并为「非本气藏干」，各计 `1` 且只在同字透干时计。
2. **藏干土一律中立**：`戊`/`己` 作为藏干被透出时也记 `0`。这条使「巳/申中是否藏戊」这类版本差异
   对计数**完全无影响**（戊本就不计），是本表对底本差异的免疫力来源。

### 2.4 党映射（二元党）

| 五行 / 字 | 归党 | 原文依据 |
|---|---|---|
| 木 | **F（火党）** | `22:L426`「木火可以一党」 |
| 火 | **F** | 同上；`22:L422`「势就是党」 |
| 燥土：地支 `戌`、`未` | **F** | `22:L426`「火与燥土可以为一党」 |
| 金 | **W（金水党）** | `22:L426`「金水可以一党」 |
| 水 | **W** | 同上 |
| 湿土：地支 `辰`、`丑` | **W** | `22:L426`「金与湿土可以为一党， 水与湿土也可以为一党」 |
| 天干 `戊`、`己` | **中立 N**（不计入任一方） | 见下 |
| 其他任何未列情形 | **N**，并在回执 `excluded` 里写明 | 不得猜 |

**天干土为什么中立**：原文的六党对只用「燥土／湿土」给土配党（`22:L426`），
天干 `戊`/`己` 没有可核的燥湿归属；给它发明一个归属，就是拿未声明的约定去定方向。
宁可少计一项，也不发明映射。

**本规格只实现二元党（F/W）**，不实现原文的六党对全集（木火／金水／**水木**／火与燥土／金与湿土／水与湿土）。
`木` 固定归 F，因此**「水木一党」在本版不成立**。这是已知缺口（§8 G1），不是笔误：
要支持多党，必须另立卡并解决「同一字同时属两党」的计数问题。

### 2.5 得令

- **唯一加权就是得令 +1**：把 `1` 加给**月支本气所属的党**（土月支按燥湿）。
- 月支本气本身已由 B 计 `1`，故月令对本党的净贡献是 `2`（B 的 1 + D 的 1）。这是**整数加倍**，不是倍率、不是权重。
- 月支的**中气/余气不另得令**；它们只按 C 的同字透干规则计一次。
- 除 D 之外，**不存在任何第二处加权**：不因日主、不因透干次数、不因紧贴、不因宫位、不因体用加减。

### 2.6 相邻 / 隔位 / 同柱 / 日主

| 问题 | 本规格的答案 | 理由 |
|---|---|---|
| 是否只计相邻 | **否**。八位全计，邻/隔同权 | 党是「势」的计数，不是作用可否发生的判据；作用是否发生由关系图 `distance` 记录，本规格不把它折成权重 |
| 隔柱是否计 | **计** | 同上 |
| 同柱干支是否计 | **各计 1 项**（干走 A、支走 B），**不加成** | 同柱不是第六类计数项；加成就是发明权重 |
| 同柱是否算「透干」 | **算**。藏干只要出现在四天干任一位置（含同柱）即为透 | 「透」是字面出现，不是「隔位出现」 |
| 是否计日主 | **按普通一位计入**：`D.s` 走 A，`D.b` 走 B；**不另加日主项** | 党势比较的对象是「一方之党」，不是身强；另加日主会让主位在每一对里都多一项 |
| 日支是否计 | **计**（走 B，土按燥湿） | 同上 |

### 2.7 比较与方向判定

```
n_F = A(F) + B(F) + C(F) + D(F)
n_W = A(W) + B(W) + C(W) + D(W)
delta = n_F - n_W          # 整数，可正可负可为 0
```

对两端的党作比较（仅用于地支—地支关系，§3）：

| 条件 | 判定 |
|---|---|
| `delta >= +1` | **火党严格大于**：方向 = 火党端 → 金水党端 |
| `delta <= -1` | **金水党严格大于**：方向 = 金水党端 → 火党端 |
| `delta == 0` | **打平 → `needs_judgment`** |

三条硬约束：

1. **「接近」的唯一操作定义是 `delta == 0`**。整数计数不存在「介于打平与严格大于之间」的取值；
   `delta == 1` 就是原文「二冲三冲一」的成势条件（`21:L2852`），**不得**再以「接近/差不多/略微」为由改判 `needs_judgment`。
2. **打平不得二次破平**：`delta == 0` 时，禁止用「谁得令／谁透干／谁在月令／谁紧贴」再判方向。这些因素已经计入 A–D，重复使用就是二次计权。
3. **禁止除法**：不得算 `n_F / n_W`、「占比」、「4:1」、「5:2」、「压倒性倍数」；不得设任何 `>= 2`、`>= 3` 的「强势」阈值。
   唯一的比较是「严格大于 0」。

### 2.8 回执（receipt）与可复现

任何一次党势比较都必须能逐项复算，因此断言必须带 `party` 回执：

```json
{
  "fire": 4,
  "water": 5,
  "delta": -1,
  "items": [
    {"addr": "Y.s", "char": "甲", "item": "A", "party": "F"},
    {"addr": "M.b", "char": "午", "item": "B", "party": "F"},
    {"addr": "H.b⊕辛", "char": "辛", "item": "C", "party": "W"},
    {"addr": "M.b", "char": "午", "item": "D", "party": "F"}
  ],
  "excluded": [
    {"addr": "M.s", "char": "戊", "reason": "天干土中立"}
  ]
}
```

校验式（必须逐条成立）：

1. `fire == sum(item.party == "F")`，`water == sum(item.party == "W")`，`delta == fire - water`；
2. 每一项的 `(addr, char, item)` 必须能在盘面上指认；`item ∈ {A,B,C,D}`；
3. 任何被计的字都必须出现在 §2.4 的党映射里；落不进映射的字必须进 `excluded`，不得静默丢弃；
4. **两次独立求和必须相等**（回执可重放）。

#### 合成算例 V1（**非任何真实盘**，只验算计数口径）

四支固定为 `Y.b=子、M.b=午、D.b=辰、H.b=戌`；天干见下。两支变体只差 `D.s` 一个字。

| 项 | V1a（`D.s=辛`） | V1b（`D.s=庚`） |
|---|---|---|
| A | `Y.s=甲`→F；`M.s=戊`→N；`D.s=辛`→W；`H.s=壬`→W | `Y.s=甲`→F；`M.s=戊`→N；`D.s=庚`→W；`H.s=壬`→W |
| B | 子 W；午 F；辰 W；戌 F | 同左 |
| C | 戌藏辛，`辛` 同字透干 → W（其余：午藏己不透；辰藏乙/癸不透；子无） | 无（`庚` 不使 `辛` 透；`壬` 不使 `癸` 透） |
| D | 月支午，本气火 → F | 同左 |
| **合计** | **F=4，W=5，delta=−1** | **F=4，W=4，delta=0** |
| **判定** | 金水党严格大于 → 方向 = 金水党端 → 火党端 | 打平 → `needs_judgment` |

V1a 的判别作用：若把「透干」误读成「同五行」，`壬`（水）会让 `辰` 藏的 `癸`（水）算作透出，W 变成 `6`、`delta` 变成 `−2`；
本规格取同字，故 W=`5`。**这一条必须由实现复现。**

## 3 · 关系类方向规则

每条规则给出：机制 → 方向判据 → `basis` → 默认 `state` → `source_ref` → 正例 → 反例。
`state` 的判据见 §4.5；`basis` 的枚举见 §4.2。

### 3.1 R1 · 子午卯酉冲（子午 / 卯酉）

- **机制**：`chong`，两端均为四正支。
- **端—党对应**：`子`→W、`午`→F；`卯`→F、`酉`→W。两对都是跨党对。
- **方向判据**：按 §2.7。`delta >= +1` → 火党端 → 金水党端；`delta <= -1` → 金水党端 → 火党端；`delta == 0` → `needs_judgment`。
- **basis**：`party_dominance`。
- **默认 state**：`needs_judgment`。党势只定「谁向谁」，不定「制不制净」（`d01:L249`）；仅当所引句明示结果时按 §4.5 填 `成`/`败`。
- **source_ref**：`22:L2872`；`21:L2852`；`d01:L240`。
- **正例**：`21:L2852`「子午卯酉寅申巳亥之冲一定要形成势力，如二冲三冲一或有生的旺冲衰，这样能冲伤冲去对方，形成制。」
  —— 「二冲一」就是 `delta == 1`，属于严格大于。
- **反例**：`21:L2852`「如一对一的冲双方力量差不多，叫做冲动为对抗之意没什么意义，只是动和消耗。」
  与 `22:L596`「成两个党， 谁也不制谁。」—— `delta == 0`，不得赋向。
- **禁止**：不得因「子午冲」三字自动判 `子→午` 或 `午→子`；不得用 `22:L2874`「中神相冲的力量不如长生相冲」
  当方向依据——那是**类内效率比较**，不是方向。

### 3.2 R2 · 巳申合（含午未合不制）

- **机制**：`liuhe`。`巳`→F、`申`→W，跨党对。
- **方向判据**：按 §2.7。金水党严格大于 → `申→巳`（申制巳）；火党严格大于 → `巳→申`（巳制申）；打平 → `needs_judgment`。
- **basis**：`party_dominance`。
- **默认 state**：`needs_judgment`；所引句明示「制死/制了」时按 §4.5 填 `成`。
- **source_ref**：`22:L2770`；`d01:L222`（M1-D-021 第 1 条）。
- **正例**：`22:L2770`「巳 申合的效率最高， 既可以金水有势， 申制 巳， 也可以木火有势 巳制 申 ， 都是将原神用神全能制死。」
  —— 两个方向都由「有势」定，且明示「制死」。
- **反例**：`26:L2293`「巳申合绊，将生水的原神绊住」—— 合成立，但结果是**合绊**不是制；
  `d01:L231`「合本身还可合绊、保护、闭气或改变作用方向，不能仅凭合名断为制。」
- **午未合单列**：`22:L2778`「午未合， 是两字相生， 不制。」—— 午未合**不适用本规则**，
  断言写 `direction=needs_judgment` 且 `no_control=true`（原文明确「不制」，不是「未判」）。
- **禁止**：不得把「巳申合」当方向本身；不得因为合关系存在就发「制」候选。

### 3.3 R3 · 辰戌丑未冲库（辰戌 / 丑未）

- **机制**：`chong`，两端皆土库。`辰`→W（湿）、`戌`→F（燥）；`丑`→W（湿）、`未`→F（燥）。
- **方向判据**：按 §2.7。
  - 金水党严格大于 → 湿土端坏燥土端：`辰` 坏 `戌`，`丑` 坏 `未`；
  - 火党严格大于 → 燥土端坏湿土端：`戌` 坏 `辰`，`未` 坏 `丑`；
  - 打平 → `needs_judgment`。
- **basis**：`party_dominance`。
- **默认 state**：`needs_judgment`（「谁坏谁库」是方向，「坏不坏成」是结果，须另有原文或逐案核对）。
- **source_ref**：`22:L2868`；`22:L1812`；`22:L614`。
- **正例**：`22:L2868`「以丑未、 辰戌冲库与丑戌刑库效率最高。 金水与湿土成势， 丑可坏未与戌库， 辰可坏戌库； 木火与燥土成势， 则未可以坏丑库， 戌可以坏辰库与丑库。」
- **反例**：
  - 打平：`22:L1812`「戌辰力量相当， 互相制不了 。」→ `delta == 0`，`needs_judgment`；
  - 方向对但结果败：`22:L614`「但戌冲辰制不了辰， 辰本在月令， 又有两个辰」——「火与燥土成势」仍制不了，
    说明党势方向 ≠ 制净成立。
- **记录一处未采用**：`22:L430`「辰戌冲， 一般是戌被辰制， （水制了火）， 但若火成势， 则戌制了辰。」
  给了「无势时戌被辰制」的**默认方向**。本规格**不采用**它作为默认，理由：
  ①它只覆盖辰戌，不覆盖丑未；②`22:L1812` 对一张具体辰戌盘明说「力量相当，互相制不了」；
  ③采用默认方向会绕过「只允许严格大于」的硬约束。该分歧记入 §8 G3，若中枢要采用，须新卡。

### 3.4 R4 · 穿制（**一律 `needs_judgment`**）

- **机制**：`chuan`；`kind=制` 时属本条。
- **方向判据**：**不判**。`direction = needs_judgment`，`state = needs_judgment`，`basis = source_text`。
- **source_ref**：`22:L2980`、`22:L2252`、`22:L2988`、`21:L2425`、`21:L3717`、`21:L3949`、`d01:L251–260`、`d01:L259`。
- **正例（可制说）**：`22:L2980`「六穿中 ， 只有酉戌穿、 卯辰穿、 子未穿、 丑午穿都可以相制。」
  同段又给条件：「相穿又相克的效率最高， 要想穿制做功， 一方必须有很强大的力量制另一方。」
- **反例（不可制说）**：`21:L2425`「穿制不了对方是一种坏，冲合克都可以制，唯有穿制不了。」
- **同书内部的三重冲突**（不择一句消去另一句）：
  1. `21:L2425` 说「唯有穿制不了」；
  2. `21:L3717` 说「子未，卯辰，酉戌，丑午相穿力量要大，穿也为制了，但必须要旺。」；
  3. `21:L3949` 直接列「⑷穿制。子未、酉戌、卯辰、丑午几种穿制。」。
- **为什么仍然一律 `needs_judgment`**（三条理由，缺一不可）：
  1. **语料冲突**：同一合集内「制不了」与「穿也为制了」并存（`d01:L251–260` 已把它记为原始转录的内部直接冲突）；
  2. **条件不可整数化**：即使采「可制」读法，条件「一方必须有很强大的力量」（`22:L2980`）没有整序数定义；
     要判就必须发明阈值，而本规格禁止发明阈值；
  3. **个案不能反推类规则**：`22:L2988`「卯与局中寅、 甲 、 戌结成一党， 占有绝对优势， 辰被穿制」
     是唯一给出「绝对优势 → 穿制」的个案，但其「结成一党」仍是定性描述，不能据此立类规则。
- **禁止**：引擎不得因出现 `chuan` 边就发「制」候选；标注不得把 `direction` 填成 `actor→target`。

#### 3.4.1 H02 的落点（**类规则的实例，不是专用规则**）

`P1-H02`（`癸巳 壬戌 庚申 乙酉`，`kind=制`、`mechanism=穿`、边 `e013`）按 R4 处理：

| 字段 | 值 |
|---|---|
| `direction` | `needs_judgment` |
| `state` | `needs_judgment` |
| `basis` | `source_text` |
| `syntax_subject` | `actor`（所引句的定向谓语「羊刃穿了官杀库」指向 `酉`） |
| `source_ref` | `22:L2252` |
| `verbatim_quote` | `戌酉穿， 羊刃穿了官杀库` |

说明：答案层记 `a=酉`、`actor=酉`，那是**原文句法**给出的施力方（穿句主语），不改；
预注册层判的是**「穿制是否成立」**，判 `needs_judgment`。两层不冲突（§5.3）。
**任何** `kind=制` + `mechanism=穿` 的断言同此处理；H02 只是第一个落点。

### 3.5 R5 · 刑（默认 `mutual`）

- **机制**：`xing`（含 `zixing` / 三刑组 / 子卯刑）。
- **默认判定**：`direction = mutual`（两败），`mutual = true`，`basis = source_text`。
  依据：`22:L2870`「戌未刑是两个都坏了 。」；组刑无单一施力方（`actor-rules-v1.md` §4.3）。
- **默认 state**：`needs_judgment`（「两败」是关系结果，不是做功成败）。
- **子类细则**：

| 子类 | 方向 | basis | 依据 |
|---|---|---|---|
| `未戌刑` | **固定 `mutual`**，**不比较党势** | `source_text` | `22:L2870` 已给对称结论 |
| `子卯刑` | `mutual` | `source_text` | `16:L2767`「子卯刑，刑坏寿元星」；成组无单一施力 |
| 自刑（辰午酉亥） | `mutual` | `source_text` | 自刑无第二端 |
| `寅巳申` 三刑 | `mutual` | `source_text` | 组刑 |
| `丑戌未` 三刑（三字齐） | `mutual` | `source_text` | 组刑；`22:L1968` 显示三字齐在党势下可定向，本预注册**不在三字齐时赋向**（§8 G4） |
| `丑戌刑`（仅两字） | **唯一例外**：按 §2.7 比较党势 | `party_dominance`（`delta≠0`）/ `source_text`（`delta==0`） | `22:L2868`：金水与湿土成势则「丑可坏未与戌库」；木火与燥土成势则「戌可以坏辰库与丑库」 |

- **正例（mutual）**：`22:L2870`。
- **反例（不得硬塞单一 actor）**：把 `丑戌未` 三刑写成单一 `actor`。三字齐时两端以上同时受损，
  单一 `actor` 无法表达「两个都坏了」；应写 `mutual`。
- **禁止**：不得把「刑开墓」的岁运字（如流年戌刑开丑库）当成本关系的施力方——开库是应期条件，不是刑的方向。

### 3.6 R6 · 克（方向固定，制净 `needs_judgment`）

- **机制**：`ke` / `zhi_ke` / `gan_ke_zhi`（后两者由 T-183 推得，不建边）。
- **方向判据**：**固定五行**，克者 → 被克者。不走党势，不比较 `n_F/n_W`。
- **basis**：`fixed_wuxing`。
- **默认 state**：`needs_judgment`。**克边的存在不等于制净成立**：
  `d01:L249`「是否制净仍须逐案核对目标残余、根气、保护和反制。」
  仅当所引句明示「制净/制死/制了」时填 `成`，明示「制不净/制不住」时填 `败`。
- **source_ref**：`22:L2924`、`22:L2926`、`23:L2179`、`d01:L243–249`。
- **正例（方向固定）**：`22:L2924`「克制就是如戌克亥、 子， 午克 申 、 酉之类， 克制的效率是比较低的」
  —— 方向由五行给出，与效率无关。
- **反例（有边 ≠ 成局）**：`23:L2179`「制官杀不干净」；`22:L2926`「克制中做功效率最高的方式是围克」
  —— 围克是**效率比较**，不能改写成「任何围克必制尽」。
- **禁止**：不得因 `ke` 边存在就把断言写成 `state=成`；不得用「克向」代替「制」。

### 3.7 R7 · 合绊 / 保护 / 闭气（`needs_judgment`）

- **机制**：`合`（五合/六合/暗合/自合）在**不作功**时的三种形态：合绊、保护、闭气。
- **方向判据**：`direction = needs_judgment`，`basis = source_text`，`state = needs_judgment`。
- **source_ref**：`19:L605`、`22:L1416`、`22:L1460`、`d01:L231`。
- **正例（合绊是定义句）**：`19:L605`「地支的六合比较简单，不管是命局、大运、流年的合都以合绊论」；
  `22:L1416`「4、 合绊： 力量想当 的两个字相合为合绊。」—— 「力量相当」正是 `delta == 0` 的语义。
- **反例（把闭气当制）**：`22:L1460`「闭气了就不能发挥作用」—— 闭气是「不能用」，不是「被制」；
  把闭气写成 `state=成` 是把「失效」当「做功」。
- **保护**：`d01:L231`「合本身还可合绊、保护、闭气或改变作用方向」—— 保护是第三态，不是方向。
- **禁止**：不得把「合」直接映射成「制」，也不得把「被合住」判成「被制净」。

### 3.8 表外类（本规格**不赋向**）

以下关系**不属于本预注册的赋向范围**，一律 `direction = needs_judgment`（除非另有专卡），
并在 `notes` 写明「表外」：

- `寅申巳亥` 冲（`21:L2852` 与子午卯酉同句给「成势」条件，但卡面未授权本类；§8 G2）；
- 三合 / 半合 / 三会 / 暗合（`zhi_anhe` 之外）/ 自合 / 伏吟 / 拱局；
- 破（`po`）；
- 生（`sheng`）、化（`mode=化用`）、墓（`muku`）—— 这三类的 actor 由 `actor-rules-v1.md` §4.7–4.9 管，本规格不改；
- 「制」的复合语义本身（`kind=制` 不等于 `mechanism` 之一）。

## 4 · 断言 schema

### 4.1 字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `assertion_id` | string | 是 | `PD-<case_id>-<nn>`；同一盘内唯一 |
| `case_id` | string | 否 | 有 hold-out / 盲集绑定时填 |
| `edge_id` | string \| null | 是 | 关系边 id；推得关系（无 `RelationGraph.edges`）填 `null` 并在 `notes` 写 `derived` |
| `mechanism` | enum | 是 | `冲/合/穿/刑/克/生/化/墓` |
| `kind` | enum | 是 | `制/化/墓/救应`（沿用 answers 口径） |
| `palace` | object | 是 | `{actor, target}`；值为 `年干/年支/月干/月支/日干/日支/时干/时支` 或 `null` |
| `ten_gods` | object | 是 | `{actor, target}`；十神名或 `null`（取引擎事实，不手算） |
| `addr` | object | 是 | `{actor, target}`；地址 `Y.s/Y.b/M.s/M.b/D.s/D.b/H.s/H.b` 或 `null` |
| `direction` | enum | 是 | `actor→target` / `mutual` / `needs_judgment` |
| `mutual` | boolean | 是 | 必须等于 `(direction == "mutual")` |
| `no_control` | boolean | 是 | 原文明确「不制/相生/不克」时 `true`（如午未合）；默认 `false` |
| `syntax_subject` | `"actor"\|"target"\|null` | 是 | 所引句**句法上**点名的施力端；`null` = 句法未点名。**这不是已判方向** |
| `basis` | enum | 是 | `fixed_wuxing` / `party_dominance` / `source_text` / `agent_anchor` |
| `state` | enum | 是 | `成` / `败` / `救应` / `needs_judgment` |
| `state_evidence` | string \| null | 条件 | `state != needs_judgment` 时必填：必须是 `verbatim_quote` 的子串 |
| `party` | object \| null | 条件 | §2.8 回执；凡 R1/R2/R3/R5 丑戌 必填，其余 `null` |
| `source_ref` | string | 是 | `path:Lnnn` |
| `verbatim_quote` | string | 是 | 所引行**逐字**片段（含 OCR 空格），必须能在 `source_ref` 行内检索到 |
| `notes` | string | 否 | 冲突说明 / `derived` / `表外` / 证据等级 |

### 4.2 枚举

| 枚举 | 取值 | 含义 |
|---|---|---|
| `direction` | `actor→target` | `palace.actor` 端施力于 `palace.target` 端 |
| | `mutual` | 两端互相损害，无单一施力方（刑的默认） |
| | `needs_judgment` | 预注册**不判方向**（打平 / 穿制 / 合绊 / 闭气 / 表外） |
| `basis` | `fixed_wuxing` | 方向由五行克定（R6） |
| | `party_dominance` | 方向由 §2.7 党数比较定（R1/R2/R3/R5 丑戌） |
| | `source_text` | 方向或「不判」由所引句直接给出（R4/R5/R7、午未合） |
| | `agent_anchor` | 端只能由 agent 标签（羊刃 / 劫财 / 官杀库 / 夫星）指认；**此类一律 `state=needs_judgment`**，agent 标签不构成党势判据 |
| `state` | `成` | 所引句明示「该关系的结果成立」（及物制句指向判定端；互毁句指向两端） |
| | `败` | 所引句明示「结果不成立 / 被反制 / 力量相当 / 谁也不制谁 / 无功」 |
| | `救应` | 所引句明示救应介入 |
| | `needs_judgment` | 以上皆无；或本条规则一律不判 |

### 4.3 不变量（校验器必须逐条检查）

1. `mutual == (direction == "mutual")`；
2. `direction == "needs_judgment"` 时 `mutual == false`；
3. `direction == "actor→target"` 时 `palace.actor != null` 且 `palace.actor != palace.target`；
4. `state != "needs_judgment"` 时 `state_evidence` 必须非空且是 `verbatim_quote` 的子串；
5. `party != null` 时：`delta == fire - water`，且 `fire`/`water` 与 `items` 逐项求和一致；
6. **全对象不得出现浮点数**：任何数值字段必须是整数；不得出现 `ratio`、`weight`、`score`、`percent` 字段；
7. `verbatim_quote` 必须能在 `source_ref` 指向行的行内检索到（逐字，含空格）；
8. `basis == "agent_anchor"` 时 `state` 必须是 `needs_judgment`。

```json
{
  "assertion_id": "PD-EXAMPLE-01",
  "edge_id": "e000",
  "mechanism": "冲",
  "kind": "制",

  "ten_gods": {"actor": "正印", "target": "正财"},

```

### 4.5 `state` 的判定程序

`state` 由**标注人**按所引句字面判定，不由引擎推断，也不由本规格的计数器推断：

1. 先看 `verbatim_quote` 有没有明示**结果**（不是方向）；
2. 有明示「成立」→ `成`；有明示「不成立/被反制/力量相当/无功」→ `败`；有明示救应 → `救应`；
3. 都没有 → `needs_judgment`；
4. 填 `成`/`败`/`救应` 时，必须把支撑短语写进 `state_evidence`（`verbatim_quote` 的子串）。

**禁止**：把「关系出现」当「结果成立」；把党势严格大于当 `state=成`；把 `needs_judgment` 当 `败`。

## 5 · 与下游的接口（只读契约，本卡不实现）

### 5.1 引擎侧（未来实现时必须满足）

1. 产出 §2.8 的 `party` 回执，逐项可复算；
2. 只对 R1/R2/R3/R5 丑戌 计算党势；其余关系不读 `n_F/n_W`；
3. 不得把 `party` 计数写进 `strength` / `can_control` 等既有旺衰字段（两套口径不得混用）；
4. `needs_judgment` 必须是**独立输出**，不得降级为 `actor=null` 后被下游当「无关系」。

### 5.2 评分器侧（未来实现时必须满足）

1. 新增 `needs_judgment` 结果枚举；**不得**记成 `ok` / `reversed` / `no_candidate`；
2. `needs_judgment` 不进方向分母的分子；是否进分母须由新卡预注册，本规格不规定；
3. 不得为了凑召回把 `needs_judgment` 改判为方向。

### 5.3 与 answers 层的关系

| 层 | 回答的问题 | 字段 |
|---|---|---|
| answers 层（已冻结） | 原文句法指出的施力方是谁 | `a` / `b` / `actor` / `quote` |
| 预注册层（本规格） | 用整数计数能否**可复现地**判出方向与成败 | `direction` / `state` / `party` |

两层结论可以不同：H02 的答案层 `actor=酉` 正确，预注册层仍判 `needs_judgment`。
**不得**因预注册层判 `needs_judgment` 就去改 answers、剔分母或放宽阈值。

### 6.2 H02 落点

见 §3.4.1。一句话：**`kind=制` + `mechanism=穿` → `needs_judgment`（方向与状态都不判）**；
答案层 `actor=酉` 不改。H02 不是专用规则，是 R4 的第一个实例。

### 6.3 H05 落点

`P1-H05`（`壬子 丙午 己巳 己巳`，`kind=制`、`mechanism=冲`）属 R1。

- 答案层（`META/p1-holdout-freeze-v4.json` 口径）：`a=午`、`actor=午`；不改。
- 预注册层：`n_F/n_W` **必须由实现现算**；本规格**不预写**该盘计数（预写=跑盘）。
- 三种可能落点，全部合法：
  - `delta >= +1` → `午→子`（与答案层同向）；
  - `delta == 0` → `needs_judgment`（评分器记 `needs_judgment`，不记 `reversed`）；
  - `delta <= -1` → `子→午`（与答案层反向，**如实记录**，不得改答案、不得调 R1）。
- **禁止**：为让 H05 变绿而改党映射、改 `delta` 边界、把 `needs_judgment` 记成 `ok`。

## 7 · 禁止项（逐条可检查）

1. 禁止比值：`4:1`、`5:2`、「占比」、「倍数」、「压倒性」等一切比值表述。
2. 禁止浮点：计数、阈值、比较中出现 `0.5`、`1.5`、百分数。
3. 禁止权重：除 D 得令 `+1` 之外，不得出现任何乘数、系数、加权项。
4. 禁止除法：不得用 `n_F / n_W`、`(n_F - n_W) / 8` 之类归一化。
5. 禁止「接近」自由裁量：唯一的非严格大于取值是 `delta == 0`；`delta == 1` 不得判 `needs_judgment`。
6. 禁止二次破平：`delta == 0` 时不得再用得令/透干/月令/紧贴改判方向。
7. 禁止为单条 case 加规则或调映射（含 H02、H05）。
8. 禁止把穿边、克边、合边自动判成「制」。
9. 禁止把 `needs_judgment` 记成 `ok`/`reversed`/`no_candidate` 以凑分母。
10. 禁止区分中气与余气的权重（二者同权，仅同字透干计 1）。
11. 禁止给天干 `戊`/`己` 发明燥湿归属。
12. 禁止把「水木一党」等其余党对混进本二元党。
13. 禁止跨关系类型比较效率（`d01:L236`：原文比较是类内比较）。
14. 禁止跑盘后改本规格；改动只能走 §9。
15. 禁止把 `party` 计数写进既有旺衰字段或 `can_control`。

1. **冻结后不改**：本正文 sha256 已写入 `META/party-direction-prereg-v1.json`；该 JSON 落盘即冻结。

   在 v2 里逐条说明「v1 的哪条、为什么错、原文反证是哪一行」。

5. **版本号只增**：不得原地改 v1 的正文或 JSON；不得覆盖旧 hash。
