# 人话写作与翻译规范 · `docs/analysis_human_touch.md`

> 用途：本规范规定 WP-8「让八字分析说人话」改造中**可读层（人话报告）的写法纪律**。
> 它是 [`templates/report-v7-human.md`](../templates/report-v7-human.md)（结构）与 [`tools/human_touch_linter.py`](../tools/human_touch_linter.py)（门禁）的共同依据。
> 配套执行流程见 [`agent_tools.md`](agent_tools.md) 的 **Step 6：裁决显式化与人话报告生成**。
> 版本：v7 契约（WP-8 v9 定稿，2026-10-17）

---

## 1. 定位：为什么需要这份规范

`engine.cli` 与 `tools.query_theory` 提供**确定性盘面事实**与**理论候选**，它们刻意不写死结论（见 [`AGENTS.md`](../AGENTS.md) 核心铁律）。因此：

- **代码算子的克制** ≠ **LLM 的骑墙**。引擎只出事实，是为了把判断权交给 Agent；
- Agent 的职责是在 Step 4–6 **拍板定案、翻译人话、给出具体生活/职场场景判断**；
- 但实际产物出现了反面倾向：每说半句盘面象义，就紧跟半句「但不能据此断发财 / 不等于必然升迁 / 机会与调整成本并存」——**一半篇幅在自我拆台**，读者拿不到任何可用判断。

本规范针对三种病灶立禁令，并给出翻译方法与裁决义务。

**一条界线必须说清**：本规范要求「敢拍板」，指的是**对有证据支撑的分歧给出主次取舍**，不是无据断言。Step 1–5 的事实纪律不放宽；没有工具证据的果断同样是违规。

配套铁律（承自 v1，继续有效）：

1. **事实纪律优先。** 盘面事实以 `engine.cli` 为准，理论以 `tools.query_theory` 命中为准；本规范只改变组织与表达，不放宽任何引用要求。
2. **不把候选写成定论。** 做功候选、格局要件、检索命中仍是候选；果断体现在「排序与站队」，不是「升格为事实」。
3. **保留可追溯性。** 关键结论保留地址（`M.b`）、边号（`e014`）及理论条目 ID；**边号注明对应哪次运行**（同号边不可跨调用互换）。

## 2. 先立主脑，再用三级置信

### 2.1 主脑

动笔前先用一句话回答：**这个命最核心的张力是什么？**

- 好主脑的形态：「脑子比脾气快，才华比运气先到」「命不苦，命紧——东西都在库里，得自己开」。
- 主脑必须由事实收敛而来（如：食伤成势 + 双戌库藏财官印 + 调候三件套齐），不是修辞包装。
- 全文所有章节都是主脑的展开；凡是跟主脑无关的边，删。

### 2.2 三级置信

| 级别 | 模板用语 | 适用范围 |
|---|---|---|
| **板上钉钉** | 「工具事实，我直接下结论」 | 原局结构、根气、月令格局底子、人元司令、墓库、旬空、神煞、起运 |
| **大概率** | 「我的判断是…」 / 「大概率发生在…」 | 多派证据收敛的结构性推断（事业类型、流年节奏、应期窗口） |
| **我不编** | 「本文未核验，不下结论」 | 精确月份、对象相貌特征、具体数字 |

规则：**每个重要章节至少要有一个「大概率」级判断**。全篇只剩「板上钉钉」和「我不编」的报告，就是旧版模棱两可的成因。

## 3. 写作纪律、翻译规范与引擎契约

### 3.1 三大病灶禁令

1. **禁概率词堆砌**：全文禁用 `或许`、`可能`、`也许`、`不宜妄断`、`难以定论`、`仅供娱乐`。
   > 注：`可能` 按子串匹配，「不可能」一并被拦截——这是**有意的**。要表达确定性否定，用「不会 / 绝不」替代。
   > 示例：❌「不可能离婚」 → ✅「不会离婚」。
2. **禁正文逐段自我拆台**：正文分析区（第一至五节）禁用下表所列话术：

   | 类别 | 禁用词 |
   |---|---|
   | 以「不能」开头的免责 | `不能据此直接断`、`不能据此断`、`不能直接裁成`、`不能只凭` |
   | 以「不」否定的骑墙 | `不等于必然`、`不代表必然`、`不决定吉凶` |
   | 以「不足以」退缩 | `不足以直接定为`、`不足以断` |
   | 以「尚」拖延 | `尚不能确认`、`尚不认定` |
   | 和稀泥式并列 | `机会与调整成本并存`、`机会与挑战并存`、`吉凶参半` |
   | 未完成句式 | `宜核验是否` |

   > **`不宜` 构成的正常否定不在本表。** 例：「不宜加杠杆」「不宜在这年冲动」——这是**有立场的判断**，正是本规范要保护的对象。「不宜妄断」已由 §3.1.1 单独拦截；虚词化的「宜重视 / 注意防范」由 §3.1.3 与 Linter 检查 3d 管。**不得把 `不宜` 加入本表**，那会误杀正文所有正当否定式结论。

   **替代写法**：把「但不能据此断发财」改成正反两面都讲实的判断。例：
   - ❌「财星透出，有机会进账，但机会与调整成本并存」
   - ✅「财星透出，这一年进账是主线；代价是要垫出去的钱变多，7 月前先把回款周期谈死」
3. **禁空洞正确的废话建议**：禁用 `宜重视`、`注意防范`、`谨慎行事`、`不宜盲目`、`注意风险`、`宜谨慎` 类**无动作虚词**。每条建议必须写成 **「动词 + 具体对象 + 场景 + 时限」**。

   | ❌ 错误 | ✅ 正确 |
   |---|---|
   | 宜重视沟通 | 每周五下午和直属上级过一次进度，把口头承诺落到邮件 |
   | 注意防范风险 | 签任何合同前让律师过一遍违约条款，尤其是 2027 年签的那份 |
   | 谨慎行事 | 这年不裸辞、不借钱给朋友；要动，等 2028 年立春后 |
   | 不宜盲目行事 | 分批投入，首笔不超过总预算三成，观察三个月再加 |

### 3.2 干支结构 → 人话场景翻译表（核心）

> 本表是**理解脚手架**，不是断语模板。最终断语仍须回到边号与理论触发条件，不得只凭表面对号入座。
> 每条翻译在报告里必须挂回至少一个 `地址 / 边号 / 规则 ID`，防止翻译变成发挥。

| 盘面结构 | 人话翻译 |
|---|---|
| 杀印相生 / 官印相生 | 扛责换权：靠专业资质、制度牌照、大平台背书吃饭，压力越大约能转化为职权与资历 |
| 食神制杀 / 伤官驾杀 | 靠硬核技术、方案输出或一线攻坚解决棘手难题，适合带业务团队或做专精特新业务 |
| 伤官见官（无救） | 跟死板规矩、顶头上司气场犯冲，看不惯形式主义 |
| 伤官见官（有印救） | 先破后立：靠专业实力让上面服气 |
| 伤官见官（有财救） | 用业绩和利益摆平人事摩擦 |
| 寅申冲 / 巳亥冲（驿马逢冲） | 坐不住冷板凳：业务跑动、跨城/跨部门调动、赛道切换或供应链折腾 |
| 子午冲 / 卯酉冲（四正逢冲） | 核心基本盘、岗位归属、合作主线或家庭居所的正面对撞与洗牌 |
| 六穿 / 六害（寅巳、子未、丑午、卯辰、申亥、酉戌穿） | 暗处消耗、计划外扯皮、被关联方连累或身体慢性暗损；比明冲更讲究防备身边人与隐性条款 |
| 入墓 / 闭库 | 资源沉淀、账户锁死、编制体制内 |
| 冲刑开库 | 资金盘活、资产变现、项目集中爆发兑现 |
| 合住库（他宫合住我宫之库） | 自己攒的成果被合作方或平台截留绑定 |
| 财星虚透 | 场面大、人脉广、会花钱办事、靠嘴皮子和才华流转资金，但账面难留财 |
| 财星入库 / 坐实 | 闷声攒资产、重实业、产权落袋 |

**补充翻译（v1 沉淀，继续有效）**：

| 结构事实 | 人话翻译 |
|---|---|
| 食伤成势不透财 | 你的钱不会自己找上门，得靠你把作品递出去 |
| 夫妻宫破刑 + 合并见 | 被稳的人吸引，处起来互相刺痛；老家的影子总在中间晃 |
| 财官印藏库逢空亡 | 你的东西都在库里，库门关着，不冲不开 |
| 伏吟 | 住处 / 工作 / 关系状态「重排」一次——是换挡，不是翻车 |
| 冲禄 / 冲根 | 根子被晃：归属感、老家、身体、单位，总有一头要动 |
| 暗合 | 暗中发展、见光慢；对方主导（大吃小） |
| 驿马年 | 走动中认识人、换环境 |

**用法示例**：工具返回 `e007` 寅申冲 + 驿马神煞命中，正文不写「寅申冲，主变动」，而写「你坐不住冷板凳——跨城/跨部门调动、赛道切换、供应链反复折腾是你的常态，硬按你在一个岗位上熬资历，双方都难受」。

### 3.3 流年断法三要素

每一年必须明确回答三个问题，缺一即不合格：

1. **动在什么事**——岗位 / 大额收支 / 合同 / 感情 / 身体，说清楚；
2. **主倾向是什么**——进账还是垫资、升权还是换岗、成局还是摩擦。**不准写「机会与成本并存」**；必须选一个主方向，另一方降为代价或条件；
3. **怎么操作**——一句具体可执行动作，符合 §3.1.3 句式。

### 3.4 裁决义务

展示各派分歧后**必须**给出「我采信 X 为主、Y 为辅，理由是……」的明确站队。

写「各有道理 / 尚难定论」**视为任务未完成**。

> **举证与呈现分歧不等于骑墙和稀泥。** 把各派依据摆出来是 Step 4 的功课；摆完之后给主次取舍，是 Step 6 的功课。两步都不能省。

### 3.5 引擎契约与变更免疫

本节说明「哪些内容与引擎无关、哪些需要同步」，以及引擎变更时的应对。

#### 3.5.1 两类内容，两种寿命

| 类别 | 内容 | 引擎变更后 |
|---|---|---|
| **永续层** | §3.1 三大病灶禁令、§3.2 翻译表、§3.3 流年三要素、§3.4 裁决义务、Linter 检查 1 / 2 / 3a / 3b / 3c / 3d、v7 模板的节结构与写作纪律 | **永久有效，无需任何改动**。这些约束的是「怎么写人话」，不是「盘面数据长什么样」 |
| **契约层** | Linter 检查 4 的地址正则、边号正则、规则 ID 正则；报告头部的 schema 指纹行 | **必须同步**。且由 `_contract_health()` 自检 + 契约测试双重保证「忘了同步会被发现」 |

**判断口诀**：一条规则如果只在**文字的写法**上作判断，它属于永续层；如果它需要**认识引擎输出的具体格式**，它属于契约层。

#### 3.5.2 引擎变更同步清单

当 `engine/` 或 `tools/query_theory.py` 发生下列变更时，按表同步：

| # | 引擎变更类型 | 是否影响契约层 | 必须同步的事项 |
|---|---|---|---|
| 1 | **地址格式变更**（如 `Y.s` → `year.stem`，或 `DY5.b` → 其他） | ✅ 严重影响 | ① 更新 `tools/human_touch_linter.py` 的 `ADDR_RE` / `DY_RE` / `LN_RE` 与 `SAMPLE_ADDRESSES`；② bump `ADDRESS_SCHEMA_VERSION`（`addr/v1` → `addr/v2`）；③ 跑 `pytest tests/tools/test_human_touch_linter.py::test_linter_contract_matches_live_engine` 确认转绿；④ 在报告头部指纹行使用新契约号 |
| 2 | **边号编号规则变更**（新增边类型导致整体后移；或边号格式由 `e\d{3}` 改为其他） | ✅ 严重影响 | 同 #1（更新 `EDGE_RE` 与 `SAMPLE_EDGE_IDS`）。**注意：边号无独立版本标记，`RelationGraph.schema_version` 不变也可能整体后移——这是最危险的静默失效场景，只能靠契约测试发现** |
| 3 | **新增边类型 / 关系种类，但编号格式不变** | ⚠️ 通常无害 | 契约测试应仍通过（新边号仍匹配 `e\d{3}`）。但需人工确认：旧报告引用的边号**语义是否漂移**（同号是否还指向同一关系）。若有漂移，旧报告须加注或重跑 |
| 4 | **新增事实字段**（如新的 strength 指标、新的 structures 状态） | ❌ 不影响 | 无需同步。报告可选择性引用新字段；Linter 不强制 |
| 5 | **`schema_version` 字符串变更** | ⚠️ 视情况 | 检查是否伴随 #1 / #2 的格式变化。若只是版本号递增而格式未变，只需更新报告头部指纹行的 schema 名 |
| 6 | **`tools/query_theory.py` 规则 ID 格式变更** | ⚠️ 可能 | 若新 ID 不被 `RULE_RE` / `RULE_CN_RE` 匹配，更新正则与样本；否则无需同步 |

#### 3.5.3 契约失效时的预期行为

引擎变更但 Linter 未同步时，`lint_human_touch(text)` 对**任何**输入都返回：

```
[检查4] Linter 契约失效（ADDRESS_SCHEMA_VERSION=addr/v1）：地址样本 'Y.s' 失配；边号样本 'e001' 失配。引擎地址/边号 schema 可能已变更，请按 docs/analysis_human_touch.md §3.5.2 同步更新本文件的样本常量与正则后再运行。
```

**这是设计意图，不是 bug**：宁可让所有报告同时报同一个错（响亮失败），也不准静默放过（假阴性）。

> 任何人不准为了「让某份报告通过」而删除 `_contract_health()` 或清空样本常量。正确做法是按 §3.5.2 同步正则。

```bash
python -m tools.human_touch_linter <报告文件>
```

须零 ERROR 方可交付。

## 5. 收尾：给命局一个温度

结尾不用「综上所述」。用几句人话回答「这个人这辈子到底在忙什么」：

- 点出命的主题（开库、输出、和解）；
- 指出最需要注意的那一年及理由；
- 一句定调式的判断（「不是苦命，是命紧」）。
