# Opus v6 裁决要点（2026-10-29）

> 依据：Opus 对 Gemini v5 / WB v4 的回复；中枢核验。
> 结论：**Opus 改口选 A+**；三方收敛。

## 1. 为什么从 D 改 A+

三条新事实改变了 D 的前提：
- 引擎党势方向公式结构性反向（PF-018/PF-008 同因）；
- fresh-40 答案有错标（PF-003/023 actor 应未/戌；PF-025 未→戌）；
- T-184 R5 mutual 判错。

在“错信号 + 错答案”上强制裁决只会放大错误；A+ 不发射引擎方向、ambiguous 单列、封 locator，正好砍掉三处病灶。

## 2. 阈值（一条线）

| 项 | 数 |
|---|---|
| pass | ≥32/40，且基线增量 ≥+8 |
| 灰 | 28–31/40；或分数够但增量 <+8；只允许复测一轮，再灰按 kill |
| kill | **≤27/40 硬 kill**，不再分 24–27 |
| nj 逃票 | ≤4/40；**≥5 直接 kill**；11–15% 不设灰区 |
| 基线增量 | **只用 +8**；§7 的 +6 作废 |
| fixed 10 | **10/10**（Opus 比 WB/Gemini 的 9 更严） |

ambiguous 10 条不计入 40，只检查是否带正反冲突双引文。

## 3. 第一证明点

答案改对、输入干净、引擎不给方向时，Agent 在 decidable 40 上比纯规则基线高 ≥8 条。

## 4. 4 步

1. 冻结 anchor-40：按原书改正 PF-003/023/025/018；双人复核；新 hash；旧 hash 只挂勘误；输入只给 target_relation，剥 locator。
2. 修引擎：不发射党势方向；刑只留 mutual 候选；自刑边不进做功候选；fixed 10 门禁 10/10 才往下走。
3. 盲跑一次：纯规则基线 40 + Agent 全层 40。
4. 精确匹配 actor→target/mutual 计分；统计 nj；按表裁决。

## 5. 产品不该存在的两种情况

- 双人复核在 decidable 40 上一致率 **<75%**（>10 条分歧）：原书判不出方向，“裁决器”定位不成立。
- 修正后的 anchor-40 **复测仍 ≤31/40，或增量 <+8**：Agent 相对规则无增量；退回事实引擎 + 理论检索，取消 Agent 裁决层。

## 6. 与 WB/Gemini 的差异

| 项 | WB/Gemini | Opus v6 / v1.3 |
|---|---|---|
| fixed 10 | ≥9/10 | **10/10** |
| 24–27 | 红/≤27 kill（Gemini） | ≤27 硬 kill |
| 复测 | 28–31 换新盲集一次 | 复测 ≤31 也 kill |
| 双人复核 | 未设 kill | **<75% kill** |

v1.3 采更严：fixed 10/10、≤27 kill、复测≤31 kill、双人复核 <75% kill。
