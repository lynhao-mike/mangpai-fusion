## 2. 已确立的架构决策（可被推翻，但要知道它们存在）

| 编号 | 决策 | 一句话 |
|---|---|---|
| ADR-001 | 引擎 / Agent 边界 | 引擎只产确定性事实与候选，综合推理与裁决归 Agent（LLM） |

ADR 全文在 `docs/adr/`。**注意 ADR-006 是本文件最该被挑战的一条**（见 §7-D9）。

### 核心设计意图（ADR-003）

诊断是：我们把「理论」当成了检索关键词和图算法，而命理师用的是「象 + 成败」的推理。因此定案：

- **事实引擎**只产确定性盘面事实（排盘、十神、藏干、旬空、冲合穿刑、墓库、做功候选）
- **断语条件化**：散文断语 → 可求值条件表达式
- **三值逻辑**：真 / 假 / **未知**。未知绝不能折成假
- **Agent** 在未知上追问、在冲突上裁决、在流派间路由

**推理顺序原则**（很重要）：命理师自上而下——先看日主强弱、格局、宫位、十神 → 找象 → 论成败（制得住/制不住）→ 才落事与应期。引擎里的原子布尔求值是**验收顺序**，不是推理顺序。断语必须写成「象 + 成败」两段式，不能写成一堆条件的与或非。

### 6.2 中枢判断的两条病根

**病根一：推理不可复用，一条断语一个模块。**
60 条婚姻断语就要 60 个模块。这是「做了几个月只推进到 20 条试点」的结构原因。

检验句：*一个真命理师会这么做吗？* 不会。真命理师只有一个框架：**看象 → 论成败 → 落应期**，六十条断语是同一框架的不同取值。

**病根二：系统不会算「什么时候」。**
42 个原子里，管岁运的只有 5 个，其中 **3 个是空壳**，直接返回未知：

- `atoms.py:558` `suiyun_edge` → `_u("岁运关系边未接入（pilot 不启用）")`
- `atoms.py:562` `sanhe_with_suiyun` → `_u(...)`
- `atoms.py:566` `chong_kai_muku` → `_u(...)`

另有 `atoms.py:518` `binzhu` → 恒返回未知（从未实现）。
且**没有任何「比较力量」的原子**（段派核心判据是「制得住/制不住」）。

所以系统能说「你婚姻怎样」，**说不出「哪一年」**。而「预测」的本质就是应期。

**病根三：三值逻辑从未真正开火。**
`META/claim-condition-pilot-v1.md` 记录试点指标：**未知率 0.0**、可求值率 1.0。ADR-003 的整个立论是「在未知上追问」，但试点里一条未知都没产生。同时 `M1-D-298`（段派婚姻）开火率 **0.0**（20 盘全假；扩到 481 盘后为 6/481 ≈ 1.2%）。
