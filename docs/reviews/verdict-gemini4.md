## 0. 一句话结论

**方向对了一半，零件选错了，证明点在数学上不可达。**

「先补完机器再扩样本」是对的。但机器缺的不是第 ⑤ 步「论成败」，是第 ⑥⑦ 步「取象 → 落事」——把结构翻译成「哪件事、哪个选项」的那一步。补 ⑤ 不补 ⑥⑦，等于给一台没有输出口的机器换更好的发动机。

而 §5.4 的第一个证明点（改造 3 条断语，要求 n ≥ 10 且 p ≤ 0.05）在现有零件下**达不到 n ≥ 10**：`can_control` 在 36 盘上的可裁率是 15/36，落到真实用法「夫妻宫被冲，谁制谁」是 **4/36**，且这 4 例里 **0 例判「制不住」**。

### 1.2 修正四点

#### 修正一：机器缺的不是 ⑤，是 ⑥⑦

§3.2 自己列了 8 步，§5.2 只补第 ⑤ 和第 ⑧，把 ⑥「取象」和 ⑦「落事」跳过去了。而铁口箓考的是第 ⑦ 步的输出（「婚姻状况 = 一婚」），不是第 ⑤ 步的输出（「制得住」）。

硬证据：**引擎从不输出一个选项。** 断语求值只返回四态 `candidate / rejected / needs_fact / evidence_only`（`engine/claims/condition_ir/ir.py:173-207`）。「命中 → 选 B」这一层翻译是评测工具里手写的常量表：

```python
# tools/tiekoulu_eval.py:70-90
PREDICTION_MAP = {
    "G-SP-130": {"category": "婚姻", "predict": ("B",),
                 "why": "配偶星守宫→不离不弃，方向=一婚"},
    ...
}
```

**「算不出来」不是因为断语缺成败，是因为系统里没有「把结构算成一个答案」的代码。** 这段代码目前写在评测脚本里，是人写的，不是引擎算的。补 ⑤ 不会凭空长出 ⑥⑦。

#### 修正二：`can_control` 建模的不是盲派的「制得住」

原文有两条限制，实现一条都没有：

```
面授讲义:4109   ①夫妻宫的宫位制去夫妻星的字为好婚姻（夫妻宫为用的情况下，
               并且只有伤官制官、比劫去财。男命财官食伤为用，女命财官为用。）
               制不住为坏婚姻。
中级命理学:3367  男命比劫能制财 女命用伤官能制官 如夫妻宫制夫妻星 但制之不住 反为坏婚姻
```

- **限制一（十神特定）**：「制」只认 **伤官制官** 与 **比劫去财**。`can_control` 按五行判，会把「印克食」「官克比」也算成制得住——这些在段派里不构成这类「制」。
- **限制二（宫位方向）**：「夫妻**宫**制夫妻**星**」是有方向的宫位作用。`can_control(actor, target)` 只比较两个五行侧的力量，不知道谁在谁的宫里。

实现本身对 `MinerU_22:1762`（以多则为旺／寡则为衰／得令为旺／失令为衰／成局为旺／受克为衰）是忠实的，这点记功。问题在**口径从「冲神双方」扩成了「两党五行」**：`_side_addrs()`（`atoms.py:945-946`）把全盘同五行的字都算进一侧。测「亥能否制巳」时，它实际算的是「水党能否胜火党」。在「成党」说下勉强成立，但已经不是原文那句「冲神之旺衰」。

#### 修正三：选来改造的 3 条断语，本身不含「制」关系

| 断语 | 前置条件 | 加 `can_control` 会怎样 |
|---|---|---|
| `G-SP-130` 配偶星守配偶宫 | `palace_holds(配偶星, 日支)` | 宫与星是**同一个字**，没有相对方向，加进去是自指 |
| `M1-D-298` 夫妻宫为用且不受刑冲穿破合 | 已用 `not` 排除冲/刑/穿 | 前提就是「没有作用」，再加「制得住」直接矛盾 |

真正需要 `can_control` 的是 **`M2-Y-395`「夫妻宫被冲，谁制谁定婚姻好坏」**——它现在 `compile_state: needs_human`，`conditions_v2` 里连 `preconditions` 都没有（只有 invalidators）；`compile_note` 写着「触发条件可编译」，实际一行都没写。

**方案要补的，正是它没列进名单的那一条。**

#### 修正四：样本不是不足，是「带性别的样本」不足，而大样本在仓库里躺着

见 §2-Q1。

「扩样本到 284 期」**在数据层就不通**：

| 项 | 数 |
|---|---:|
| 铁口箓总期数 | 284 |

3. 证明点不可达 → 见 Q3 实测

这不等于 `real_cases_990` 能直接当五分类标签集——它是**逐条事件 + 年份 + 吉凶**，不是「婚姻状况」五选一。但它恰好是**应期**（第 ⑧ 步）的现成标签集，而第 ⑧ 步正是 §5.2 说要补的两件事之一。

### Q2（盲派建模准确性）—— **基本成立，4 处偏差，其中 1 处是硬伤**

骨架（宾主 → 体用 → 做功 → 成败 → 应期）与原文对得上；`d01:106`、`:110`、`:175`、`:309-319` 逐字核对无误。偏差如下：

**偏差 1（硬伤）：把「有势有功」当成了通用成败判据。**

`d01:175` 的语境是**富贵**，`d01:172` 小标题就写着「富贵命的 2 个必要条件」：

> 「所以这类八字必须具备两点，一是有势，二是有功。只有势没有功不行，只有功没有势不能有大作为。」

它不是婚姻成败、子女成败的判据。婚姻的成败判据在 `面授讲义:4109①`，是**十神特定**的（见修正二）；子女、学历各有各的判据。

§3.2 把「论成败」写成一个统一步骤，会导致后面所有域都用「势 + 功」去判——这正是「拿一个框架套所有事」。

**偏差 2：应期漏了第 3 态和前置条件。**

`d01:309-319` 是 3 态，不是 2 态：

```
1. 原局逢合   → 大运/流年逢冲为应期
2. 原局有冲   → 大运/流年逢合为应期
3. 原局不合不冲 → 大运/流年逢合为应期      ← §3.2 漏了这条
```

且有前置：「但原局必须是与夫妻星和夫妻宫有关系。」（`d01:318`）漏掉这句，任何合冲都会被当成婚姻应期。

**偏差 3：漏了「党」的中神判定。**

`d01:190-196`：「成党之后……可弃日主不看，看结党中的主要一字，即中神。」

「势」不是数五行个数，是找中神。`can_control` 的 `_side_profile` 数的是「显性字数 ≥ 3 为多」——这是**兵力统计**，不是**中神识别**。两者在「三合局缺一」「两党对峙但有主从」时会给不同答案。

**偏差 4：`can_control` 够不够？不够，差三样。**

1. **十神限制缺失**（伤官制官 / 比劫去财）→ 修正二
2. **宫位方向缺失** → 对称力量比较，不知道谁在谁宫里制谁
3. **距离/位置缺失** → 隔位不制、遥冲力减，`can_control` 完全没看位置

该补的原子不是「更强的 `can_control`」，而是 **`zhi_by_god(palace, god, mode)`**：给定宫位、给定十神、给定制的方式，返回三值。这才是 `4109` 那句话的直接翻译。

### Q3（`can_control` 是否重蹈覆辙）—— **会。84.3% 判未知，关键场景 0 例判「制不住」**

36 盘全跑，穷举每盘 8 字的所有有序字对（1474 对）调 `can_control`：

| 结果 | 数 | 占比 |
|---|---:|---:|
| True（制得住） | 116 | 7.9% |
| False（制不住） | 116 | 7.9% |
| **None（不可裁）** | **1242** | **84.3%** |

每盘可裁对数（True+False，满分 20 对）分布：

```
0 对：21 盘   4 对：3 盘   8 对：4 盘   16 对：1 盘   20 对：2 盘   24 对：3 盘   30 对：2 盘
```

**36 盘里 21 盘（58.3%）一对都裁不了。**

再看真实用法——`M2-Y-395`「夫妻宫被冲，谁制谁」：

| 项 | 数 |
|---|---:|
| 夫妻宫被冲/穿的盘 | 19 / 36 |
| 「谁制谁」调用数 | 25 |
| 判 True | **4** |
| 判 False | **0** |
| 判 None | **21** |

**最要命的是 `False` 为 0。** 也就是说，「制不住 → 坏婚姻」这半边教义在这 36 盘上**一次都触发不了**；断语只能预测「好婚姻」，且只有 4 例。

对照 §5.4 的成立标准「n ≥ 10 且 p ≤ 0.05」：4 < 10，**门都进不去**。

**结论**：三值设计**在方法论上是对的**（力量相当即不可裁，`MinerU_22:1812/:1824` 有原文依据），但把它当断语前置条件是**结构性不可验证**的。不是「可能会」，是「一定会」。

`needs_fact` 会不会下降？不会上升，但也没意义——因为 `candidate` 会掉到个位数。

### Q4（断语粒度）—— **问题成立，但「把断语改写成多选题」的解法是错的**

问题成立：`G-SP-130` 说「不离不弃」，题库问「未婚/一婚/一婚离丧/…」。一条二元命题提供 1 bit，5 选 1 需要 ~2.3 bit。**信息量不够，不是映射失真。**

解法错在哪：让每条断语直接输出选项集，会**退化成全选**。这不是推测，是已经发生过的事：

```
M2-Y-014 财富：预测 (A, B)，而财富类实际只出现过 A/B 两个值
→ 基线必然同为 100%，增益恒为 0 → T-146 已作为退化项剔除
```

`META/tiekoulu-eval-v1.md` §5 的 ⚠︎ 就是这个。断语越想「直接给答案」，越容易覆盖全部可能值。**准确率 100%、增益 0**，比 50% 更没用。

正确的位置关系是三层，不是两层：

```
断语（1 bit，可判真假）× N
        ↓
   落事层（把 N 条 1 bit 合成 k 路分布）   ← 现在缺的就是这层
        ↓
      选项
```

直接改造断语去当输出层，等于取消中间层，结果是每条断语都说「可能是 A 或 B」——正是退化项的成因。

### Q6（整体性）—— **批评成立，但两个候选根因都不是根因**

跑一遍生产链路（`run_v5`，1980-02-15 02:30 乾造）：

| 流派 | structure_claim | event_claim | timing_claim |
|---|---:|---:|---:|
| 子平 | **269** | 0 | 2 |
| 滴天髓 | 14 | 0 | 0 |
| 高德臣 | 0 | 15 | 0 |
| 杨清娟 | 1 | 14 | 0 |
| 段建业 | 5 | 10 | 0 |
| 任付红 | 0 | 0 | 1（abstain） |

**一张盘 331 条 claim，269 条是子平结构命题，全部 support。** 事业域裁决结论长这样：

```
结构裁决（240条支持）：子平规则参与：我克者为财，正财阴克阳、偏财阳克阴。
财喜食神生、官星护，忌比肩劫财夺财。财旺身弱，难任财帛；身旺财弱，财薄清贫。…
```

这不是对本盘的判断，这是**十神定义**。再看性格域：

```
段建业规则参与：任何八字判定 conclusion: 保留: - 禄 - 羊刃 - 墓库 - 驿马 - 空亡
作废: 传统神煞 50+ 在段派中不参与做功判定
```

这是**目录**，不是结论。原因在代码里：

```python
# engine/v5/runner.py:1000-1001  结论 = 该域得分最高那条规则的文本
conclusion=structure_verdict
# engine/v5/runner.py:314-316    打分 = 触发器命中 × 后验置信度
base = float(rule.confidence.posterior)
# engine/v5/gao_runner.py:63     断语正文 = 规则模板，不是渲染后的本盘结论
statement=rule.conclusion_template,
```

所以：**不是缺流水线**（`run_v5` 有三段仲裁），**也不是断语只覆盖局部**（331 条不少）。根因是 **claim 的 `statement` 是规则原文，不是本盘算出来的那句话**。

「240 条支持」本身就是证据：一个域的触发规则能同时成立 240 条，说明触发器约等于没筛。support/oppose 计数在这种密度下不携带信息。

对照一下：`condition_ir` 那套（pilot-20）是**真在逐盘求值**——每盘平均 1.75 条命中（0 条×3、1 条×14、2 条×11、3 条×6、4 条×1、5 条×1）。**唯一真在算的那套，没接进报告；报告用的是不算的那套。**

这才是「流于形式」的机制。

## 3. 我认为本文提错的问题

**① Q3 提错了。** 「三值设计是否成立」是伪问题——设计成立（有原文依据），不成立的是**把它当断语前置条件**。该问的是「制得住的判据应该是什么十神对、什么宫位方向」。`can_control` 是错的答案，但它错在**问题本身没问对**：先定了用力量比较，再回头找能支持力量比较的原文。

**② Q5 提错了。** 「该不该先做流派路由」预设了「路由没做」。实际做了，而且做的是别的事。该问的是「路由粒度是盘还是域」。

**③ Q6 提错了。** 「缺统一流水线」与「断语只覆盖局部」二选一，但都不是。该问的是「claim 的 `statement` 是算法输出还是语料检索」。

**④ 全文有个未言明的前提：「扩样本 = 用满 284 期」。** 这让 §4.3 的功效分析看起来像在描述资源约束，实际是一个数据缺口（87.3% 无性别）；同时遮住了 `real_cases_990`（992 例 / 3379 事件）的存在。

**⑤ §4.2 的表格有一处会误导读者的地方。** 「命中」列是 `命中数/总期数`，「准确率」列的分母却是 `命中数`：

| 断语 | 文中写 | 实际含义 |
|---|---|---|
| `G-SP-130` | 10/36，50.0% | 命中 10 期，其中 5 期答对 → 5/10 = 50% |
| `G-SP-165` | 6/36，33.3% | 命中 6 期，其中 2 期答对 → 2/6 = 33.3% |

分母在行内从 36 跳到 10（6），没有标注。不算错，但会让读者把 50% 读成「36 期里对了 50%」。建议写成 `5/10（命中 10/36）`。

**⑥ 一个现在不该解决的问题**：Q5 的「盘级 vs 域级路由」现在不该动。路由即使改成域级，下游 claim 仍输出规则原文；先动路由等于给检索器换个排序键。

## 4. 我的方案

### 4.1 主张

**不做「给断语补成败」，做「给域做落事表」；证明点从成败移到应期。**

理由链：

1. 引擎没有输出层（`PREDICTION_MAP` 手写在工具里）→ 补 ⑤ 不产生输出
2. 输出层需多因素合成，单条断语的 1 bit 不够（`M2-Y-014` 退化已证）
3. 合成要有固定结构 → 需要「按域的结构事实向量 + 判别表」
4. 这张表能否被验，取决于标签是否有**尖锐的预测目标**
5. 应期天然尖锐（某一年），且仓库里有 3379 条带年份事件

### 4.2 它让哪一条断语从「算不出来」变成「算得出来且能验证」

**`G-CY-008`「发财应期六条铁律（岁运引动）」**——现在 `uncompilable`，`unmapped_prose` 为空，连条件都没写。

以及 **`M2-Y-019`「寻根基三步法」**——现在 `uncompilable`。

两条的共同点：**都是应期类，而应期有唯一正确的答案形式——年份。**

改造路径：

```
输入：原局 + 大运序列 + 流年
规则：d01:309-319 三态
  原局有合（涉财/官）→ 岁运冲该合成员之年 = 应期
  原局有冲（涉财/官）→ 岁运合该冲成员之年 = 应期
  原局无合无冲       → 岁运合夫妻星/夫妻宫之年 = 应期（限婚姻域）
原子：suiyun_edge / suiyun_arrives / chong_kai_muku   ← T-145 已建，当前 0 条断语在用
输出：候选年份集合（通常 1–2 个）
```

这就把「算不出来」变成了「算得出一个集合」——**而集合可以被判分**：命中 / 未命中 / 不在窗口内。

### 4.3 必须设的基线（这条比方案本身重要）

只跟「均匀猜」比，应期会**假赢**。婚姻事件有极强的年龄先验：

| 基线 | 婚姻事件命中率（n=587） |
|---|---:|
| 均匀猜一年（11 年窗口） | 9.1% |
| 猜「26 岁」 | 7.8% |
| 猜「24–30 岁」7 年窗口 | **37.0%** |
| 猜「20–30 岁」11 年窗口 | **54.0%** |

**任何应期模型必须先赢「猜 24–30 岁」这条线（37%），才有资格说自己算出了东西。** 否则测出来的全是「人一般在这个岁数结婚」。

这条应写进任务卡，与 T-146 的「同基数基线」同等地位：T-146 做对了「预测 k 个字母就要对 k 字母基线」，这里要做的是「预测年份就要对年龄先验基线」。

### 4.4 与 §5 方案的关系

不是替代，是**换顺序**：

| §5 的顺序 | 本意见的顺序 |
|---|---|
| 1. 改造 3 条断语补 `can_control` | 1. 建应期评测（992 例 / 587 婚姻事件 / 年龄基线） |
| 2. 同一把尺子重测 | 2. 用 `suiyun_edge` 等已有原子编 3 条应期规则 |
| 3. 成立则推广 | 3. 赢了年龄基线，再做落事表（⑥⑦） |
| 4. 扩样本 | 4. `can_control` 降级为落事表的一个输入特征，不做断语前置 |

`can_control` 不是废掉，是**换位置**：从「断语的 AND 前置条件」（会把 n 砍到 4）改成「落事表的一个特征列」（不影响 n）。同一个原子，位置不同，可验证性天差地别。

## 5. 执行顺序

### 第一步（必须先做，不做后面全是噪声）

**把 `real_cases_990` 做成应期评测集，并冻结年龄基线。**

- 抽取：`cases/raw_feedback/parsed/real_cases_990.jsonl`
- 婚姻域 587 条事件 / 340 例；事业域 986 条；健康域 677 条
- 每例给一个观测窗口（出生年+16 到 min(出生年+60, 最后事件年)）
- 标签：窗口内哪些年发生了该域事件
- 基线三条：均匀 / 最佳单岁 / 最佳年龄带（带宽与模型预测数相同）
- **套 `career_event_replay_harness.py` 的 freeze/reveal 隔离**，不用自觉约束

验收：新增评测工具退出码 0，输出「无模型基线」三行数字。此时**还没有任何模型**，只有尺子。这一步的产物是尺子，不是分数。

### 第一个可证伪的证明点

**规则**：`d01:309-319` 第 1 态 ——「原局有合（涉财/官）→ 岁运逢冲该合成员之年为应期」。

**预测**：对每个婚姻域案例输出 1–2 个候选年份。

**成立标准**（三条全满足才算）：
1. 命中率 > **37%**（24–30 岁年龄带基线）
2. 预测年份数与基线带宽相同（不许用「多猜几年」占便宜）
3. 在留出集上成立——按出生年代分层抽 30% 做 holdout，规则冻结后才看

**推翻条件**：命中率 ≤ 37%。此时说明「原局合 → 岁运冲」在真实数据上不成立，或岁运原子实现有误。**任一种都不该继续加断语**，应回去查 `suiyun_edge` 的边构造。

### 第二步（只在第一步成立后）

把 `M2-Y-395` 补成可编译：新增原子 `zhi_by_god(palace, god, mode)`，按 `面授讲义:4109①` 的十神限制（伤官制官 / 比劫去财）实现，`can_control` 作为它的一个特征。此时它才可能产生 True/False 两侧的样本。

### 现在不该做的

- 盘级/域级路由改造（下游还在输出规则原文，换排序键没用）
- 把 12 条断语全部补成败（其中 3 条恒 `needs_fact`，补了也没用）
- 扩铁口箓样本（248 期无性别，扩不动）
