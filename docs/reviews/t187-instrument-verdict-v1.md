# T-187 复核裁决：kill 判的是量具，不是产品（2026-10-29，中枢核验）

> 依据：Opus 5.5 的 T-187 复核（2026-10-29）；中枢用 `META/p1-system-run-v1.json` + fresh-40 答案逐条重算，数字一致。
> 结论：**T-187 的 kill 是“量具无效”的 kill，不是产品假设被证伪。** 不改写成 pass，也不当产品 kill 用。

**真实负面发现（不能归咎于协议）**：只给一张盘、不指定边时，系统只有 **12/40** 找到专家锚定的那条做功边。这是 E2（选边）的基线，不是 E1（给边定向）。

## 2. 五条量具错误（Opus 指出，中枢核验成立）

1. **盲测输入只给盘、不给目标边**：运行人只能自己选边；28/40 选的不是答案那条。把“给定边判方向”和“给一张盘找做功边”混成一道题。
2. **Agent 层没上场**：T-187 运行人执行的是 T-184 引擎规格；25 条 nj 是规格原始输出，不是 Agent 裁决。所谓“系统级”名不副实。
3. **nj 不计错 + coverage 线**：abstain 成了合法退路；T-184 把穿、合绊、表外寅申巳亥冲都路由成 nj，规格本身 coverage 上限约 27/40，根本到不了 75%。
4. **刑一律 mutual 过头**：原文只说“戌未刑两个都坏”；答案 PF-023/024（丑刑戌，actor=丑）、PF-025/026（未刑戌，actor=未）都有 actor。把特例推成整类规则。
5. **寅申巳亥冲划到表外**：原文“子午卯酉寅申巳亥之冲一定要形成势力”已覆盖；PF-001（Δ=+4，答案巳）、PF-005（Δ=−4，答案申）按党势能出方向，却被路由成 nj。

## 4. 下一轮：D（强制裁决双层）+ E1/E2

- 最小产品：**一张盘 + 一条目标边 → 一条断言**（边 ID、方向、成败、source_ref 原文锚点、党势回执）；**必须表态**，`needs_judgment` 不再是合法终态。
- 引擎冻结 T-184：只出事实 + 克/生/化/墓方向；冲/合/刑/穿/合绊的 nj 与 mutual 都只是候选，Agent 必须给 actor→target 或 mutual。
- **E1（给边定向）**：盲输入给目标两端地址 + 关系名；排除选边误差。主指标 correct/60，nj 计错。
- **E2（选边）**：同一批只给盘，看 top-3 是否命中专家边；T-187 的 12/40 是基线，目标 ≥50%。
- fresh-60：全部新盘，与 dev-20/fresh-40 零重叠；换人策展；固定五行 ≥20 条、冲/合/刑 ≥25 条、穿 ≤15 条；不给 source locator；答案先 hash。
- 预注册：pass 45/60（75%）；kill <36/60；固定五行子层 ≥18/20；比两条笨基线（Δ 符号、五行克方）至少高 6 条；同一 prompt 3 次方向一致率 ≥90%；评分器先过地址归一合成测试。
- 不调 T-184 阈值；不在 dev-20/fresh-40 上宣称；不复活 5 例 spike；不扩岁运。
- 3 张真实盘卡：direction_known 3/3、rescue 有判定、断言移植到随机另一盘 ≥90% 被拒。
