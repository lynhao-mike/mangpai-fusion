## 0. 一句话

**接受**：产品最小存在单元不是「10 条规则」，也不是「一张模板报告」，而是
**一条带完整盘面地址链、成败/救应三态、可回溯原文锚点的结构化断语**。
产品应重构成「可复核的结构化命理推演引擎」；第一个证明点是 **golden-20 盲推复原**（75% 通过 / 60% 止损），
不是再刷统计 p 值。

## 1. 接受的核心判断

1. **最小单元**：Address-Grounded Structural Verdict（地址锚定结构断语），五元组缺一不可：
   原局象（宫位+十神+边）/ 体用宾主与施力方向 / 成败救应三态 / 落事与岁运引动 / 双重锚点（盘面地址 + 原文行号）。
2. **这不是分类器问题**：仅凭八个字、无现实锚点，预测「哪年结婚/负债/创业」并打赢人口学基线，
   在信息论与经验科学上不可形式化到统计显著。产品应是「结构推演 + 人机定锚」，不是「盲算吉凶」。
3. **旧层是产品负债**：聚合规则（`claim-rules-v1.yaml`）、46 原子 `condition_ir`、
   测量脚手架（大量 labels/timing/eval 工具与测试）不构成分析能力，应退出产品主路径。
4. **事实层不完整**：481 盘 0 错只证明万年历 + 六冲六合；880 对地支克 0 条边、523/3179 制用候选
   `actor=None`、藏干无独立地址——这些是分析原语的硬缺口。
5. **第一证明点**：golden-20 教材真盘盲推复原；四条硬标准（零幻觉 / 主功一致 / 成败救应不错位 /
   岁运机理同构），≥15/20 通过，<12/20 止损。

## 3. 对「物理删除 85%」的修改：先归档，后删除

外部审计给的是「物理清除**或**归档封存」。我选择**归档封存**，理由：

- `engine/facts`、`engine/api`、`engine/cli` 可能 import 被点名的 `engine/energy`、`engine/decision/models`、
  `engine/asof` 等；未做依赖审计就删，可能直接打破 481 盘 0 错——那会毁掉唯一硬资产。
- 测试同理：`tests/facts`、`tests/api` 是尺子；`tests/governance`/`v5`/`f09` 可归档，但不能一刀切。
- 删除不可逆；归档可逆。先冻结（不再投入）、再审计依赖、再分批归档；确认无引用后才删。

**做法**：
1. 立即**冻结**（不再新增/修改）Kill List 里的模块；文档标 `DEPRECATED`。
2. T-171 做依赖审计：谁 import 谁、facts/api/cli 依赖哪些、测试哪些是尺子。
3. 审计通过后，按「安全 → 有引用 → 不可判」分批移动到 `archive/`；不直接 `rm`。
4. `engine/facts`/`api`/`cli`、`sources/`、`theory/`、`tools/query_theory.py`、facts/api 测试保留。

## 5. 第一证明点与 Kill Criterion

沿用外部审计：

- **通过线**：20 盘中 ≥15（75%）四标准全过，0 排盘/关系事实幻觉。
- **止损线**：<12（60%）→ 停止「自动断语研发」，降级为排盘/检索工具。
- **产品失格**：为了体感拿掉「地址 + 三态 + 原文锚点」，退回模板/自由编造。
- **预测型止损**：单一窄机制满功效预注册后仍 p>0.20 或低于人口基线 → 关停预测型产品，不换特征/K/标签续命。
