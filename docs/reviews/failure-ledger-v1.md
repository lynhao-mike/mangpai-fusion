# 失败档案 v1（2026-10-29，中枢）

> 用途：把本项目**已经走过的错路**逐条钉死，避免后续 Agent / 大模型在同一个地方再摔。
> 读法：先看 §0 的「派活前 12 问」，再查对应条目；每条都带「杀死它的证据」和「现在的守护」。
> 维护：中枢。新错必须追加，不许删旧条目；若某条被新证据推翻，追加「更正」，不覆盖原文。

## 0. 派活前 12 问（每次写卡/派活先过一遍）

1. **这活在产品路径上吗？** `grep` 调用点；没有 product call 的东西不是产品。
2. **当前覆盖率是多少？** 「扩/补」之前先 measure；可能本来就是全的。
3. **断语的 conditions 里到底有没有这个 fact？** 没有就别接这个原子。
4. **结果变量匹配断语语义吗？** 「婚姻形态」≠「婚姻质量」，「克向」≠「制」。
5. **计数单位是什么？** 一条边、一期、一个人？有无聚类？CI 会不会被低估？
6. **基线同 K / 同宽度 / 同分母吗？** Top-3 不能用 7 年窗口的 45.3%。
7. **n 与 power 够吗？** 预注册前先算 MDE；n<50 一律「样本不足」。
8. **标签错误率多少？** >20% 停；语义问题（第三人称/否定/跨句）不是词表问题。
9. **`null` 会被折成负例吗？** 无证据 ≠ 阴性；`1/null` 不能当 `0/1`。
10. **改的是判据还是实现？** 判据若错，先给原文/代码证据，再改。
11. **测试寄生生产数据吗？** 测试要用 fixture，别拿会变的生产 YAML 当夹具。
12. **子代理说「通过」——我自己跑了吗？** 只认退出码与现场数字。
