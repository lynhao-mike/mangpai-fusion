# P1 pre-fix 基线裁决 v1（2026-10-29，中枢）

> 对象：T-177 评分器 + `META/p1-holdout-baseline-v1.json`（`artifact=pre_fix_baseline`）
> 结论：**基线成立；但三处修复的范围不够，P1 关系覆盖 90% 在现范围里不可达。先改范围，再写代码。**

## 0. 一句话

当前引擎在 frozen hold-out 上：**边 8/20=40%、muku 等价边 12/20=60%、候选 14/20=70%、
方向 1/20=5%**（剔墓后 1/16=6.25%）。
边未中 12 条里 **8 条是支克/支生（G3）**、4 条是墓不是边——而独立 Agent 的「不补 880 支克边」
是用 dev 0/23 推出来的；hold-out 用 8/20 把它证伪了。

## 2. 边未中的构成（决定修复范围）

12 条边未中：

- **支克/支生（G3）8 条**：H06/H07/H19（支克支、支克干）；H09–H12/H18（化=sheng，支-支无 sheng 边）。
- **墓不是边 4 条**：H13–H16（引擎只有 `relations.muku` + 墓用 muku 候选）。
- 候选未中 6 条：H02/H06/H07/H12/H13/H19（两端皆体、支-支克、体用不交）。

**这 8 条支克/支生，正好是独立 Agent 说「不补」的 880 对支克边。** 它的依据是 dev 33 条里
0/23 需要支克；但 hold-out 20 条里 8 条需要（40%）。dev 的 0/23 是**样本缺口**，不是全局事实。
**P1 关系覆盖 ≥90% 在「不补支克/支生边」的前提下不可达**（最多 12/20=60%）。

## 3. P1 口径 v2（冻结，先于修复）

1. **关系覆盖主口径 = edge OR muku-equivalent**，分母 20，目标 **≥90%（≥18/20）**。
   strict edges 8/20 作为次级诊断；否则 4 条墓用会让 90% 结构性不可达。
2. **方向召回主口径分母 = 16**（剔除 H13–H16 四条墓用，等待墓的 actor 约定审计）；
   目标 **≥80%（≥13/16）**；raw 20 作为次级，也报。
3. **不把墓的 `a=库` 与引擎 `actor=入库方` 直接算 reversed**：这 4 条标
   `definition_conflict`，先由第三人核对原文；在约定定稿前不进方向主分母。
4. **`制` 保持不过滤 kind**（dev 口径）；H01 是唯一依赖此口径的命中，若规则表定 `制=ke`，
   报 sensitivity 7/20，不改主口径。
5. 口径 v2 在修复前冻结；修复后不得再改分母/阈值；post-fix 另存
   `META/p1-holdout-postfix-v1.json`，不覆盖 pre-fix 基线。

## 4. 修复范围必须扩大

独立 Agent 的三处（方向、去体-体过滤、柱内/邻柱生）**不够**：

1. **支克/支生关系原语**：补 G3（不是 per-case 补边；是通用 primitive）。这是 8/20 边未中的主因。
   加边会改 `edge_id` 编号；所有卡/答案必须带 snapshot；481/0 与既有测试必须保住。
2. **墓用关系等价 + actor 约定**：`relations.muku` 与 muku 候选要能当“关系覆盖”；
   墓的施力方约定（入库方 vs 库）必须先定，再算方向。
3. **原三处**（合/冲/刑/穿方向、去体-体/双属过滤、柱内/邻柱生）仍做，但排在 1/2 之后。
4. **actor 规则表**必须覆盖 化/墓，不只 合/冲/刑/穿；否则 7 条 reversed 里 4 墓 + 化 仍会挂。

## 5. 方向 5% 的含义

- **不是“模型不会”**：是边/候选/施力方三处同时缺。
- 7 条 reversed 是**约定对立**（墓 4、化 3），不是数值噪声；6 条 actor_none 是 G2；5 条 no_edge 是 G3/墓。
- 先补关系原语 + 定 actor 约定，再谈方向召回；否则修完三处，方向仍可能 <60%。
