# ADR-005 · 排盘口径：案例必须声明 `time_basis`，引擎不做换算

- **状态**：accepted（已接受）
- **日期**：2026-10-27
- **决策人**：中枢指挥官（依 [ADR-004](ADR-004-hub-commander-authority.md) 授权代决；人类可一句话推翻，推翻成本为重跑一次口径普查）
- **取代**：原任务清单 A1 中「31 个带精确出生时间的案例」这一错误口径与「0 例口径不明」这一不可验证的验收标准
- **影响**：案例元数据（`cases/*/input.md`）、`tools/` 层新增普查器；`engine/` 零改动

## 背景

A1 长期卡住，原因是问题被表述成「案例按真太阳时排，还是只记钟表时间」这个二选一。2026-10-27 现场核查后，这个表述与仓库实际不符：

1. **引擎本来就是口径无关的。** 四处代码已明文声明引擎不做真太阳时换算，时刻由调用方提供：
   - `engine/facts/chart_facts.py:462`：「引擎不做经度/真太阳时换算」
   - `engine/asof/birth_to_bazi.py:4`：「只做历法排盘，不做出生地、经度、时区或真太阳时换算」
   - `engine/asof/qiyun_calculator.py:168`：「`birth_dt` 应为调用方已校正（优先真太阳时）的公历时间」
   - `engine/predicates/cycles.py:136`：「调用方负责时区与真太阳时校正」

   所以「引擎用哪种」是个伪问题——引擎用调用方喂进去的那种。真正没有定义的是**案例元数据里声明的是哪种**。

2. **案例元数据有三种互不兼容的写法，且大量沉默。** 现场统计 `cases/*/input.md` 共 485 例：

   | 写法 | 形态 | 例 |
   |---|---|---|
   | 表格注记 | `\| **公历生日** \| 1992-04-01 03:15（真太阳时） \|` | C-2026-008 |
   | 结构化字段 | `真太阳时校正: true / false / 未知` | C-2026-016、C-2026-028 |
   | 导入器字段 | `真太阳时字段优先: false` + `经度校正说明: "本模块未做…换算"` | C-2026-RF000100 系列 |

   其中 `真太阳时校正` 字段只覆盖 **119 例**（true 104 / false 14 / 未知 1），其余 **366 例完全沉默**。沉默不等于「用了钟表时间」，但现在读不出区别——这就是「口径不明」的真正来源。

3. **原任务清单的「31 例」与实测不符**，且「0 例口径不明」在数据缺失时不可达（无出生时刻的案例不可能有口径）。旧验收标准作废。

## 决策

### 1. 引擎保持「口径无关」，不做任何换算

理由：排盘与校正耦合会让「同一个四柱由哪个时刻得到」不可追溯，且 485 例中绝大多数无出生地经度，换算无从做起。校正属调用方职责，引擎只记录结果。

### 2. 每个案例必须且只能有一个 `time_basis`，三值

| 值 | 含义 | 时柱可否用于断语 |
|---|---|---|
| `true_solar` | 已按出生地经度做真太阳时校正（或案例直接给出校正后的具体时刻） | 可信 |
| `clock_beijing` | 仅钟表时间（东八区 120°E），未校正 | 有跨界风险，仅用于时柱不敏感断语 |
| `unknown` | 无可用出生时刻，或无法判定 | 不得用于任何时柱相关断语 |

### 3. 沉默一律记 `unknown`，不得默认 `clock_beijing`

默认成钟表时间，等于把「没写」伪装成「写了钟表时」——正是当前 366 例的病根。宁可标低，不许标高。

### 4. 另设独立字段 `basis_evidence`，记录判定证据强度

`time_basis` 回答「是按哪种排的」，`basis_evidence` 回答「凭什么这么说」：

| 值 | 含义 |
|---|---|
| `longitude_calc` | 有出生地经度 + 可复现的换算过程 |
| `explicit_time` | 案例内直接给出校正后的具体时刻（如 C-2026-010「16:37 申时」、C-2026-030「公历真太阳时 1999-07-03 23:04:00」） |
| `label_only` | 只有「真太阳时校正: true」字样，无经度、无校正后时刻 |
| `none` | 无证据 |

`label_only` 的案例**保留在 `true_solar` 层但标低可信度**，不直接丢弃，避免把可回溯的历史判断一次性作废。

### 5. 断语验证分层报告，跨层合并必须报混合比例

涉及时柱的断语（宫位、穿、合、时支藏干、时柱十神、时柱长生）只允许在 `true_solar` 层验证；`clock_beijing` 层只验证与时辰无关的断语（日主强弱、日支、年月柱、十神结构）。跨层合并统计时，报告必须写明两层的样本数与混合比例。

这一条与 B4「验证三分法」的分层要求一致，不另立标准。

## 依据

- 命理依据：真太阳时决定时柱。盲派断语大量依赖时支（宫制星、穿、合、时柱做功），时柱错的盘用于验证时柱类断语会系统性污染命中率统计。这是命理师的常识前提，不是工程取舍。
- 代码依据：见「背景」第 1 条四处声明，引擎边界已明确，无需改动。
- 数据依据：485 例实测分布，见「背景」第 2 条。

## 后果

- **A1 验收改为**：485 例全部落三值之一，`basis_evidence` 全部落四值之一；`unknown` 的例数须与「确实无出生时刻」的案例数吻合（由普查器输出清单，人工抽核）。旧的「31 例、0 例口径不明」作废。
- **引擎零改动**，基线四项（pytest / engine_audit / relations_audit / zuogong_probe）无退步风险。
- **B4 分层验证**可直接消费 `time_basis`，不再另建口径。
- **可逆**：将来补齐出生地经度，只需把 `clock_beijing` 升级为 `true_solar`、`basis_evidence` 改为 `longitude_calc`，字段语义不变，断语无需重编译。

## 未决

- 「跨界风险」目前只定方向（经度每偏离 120°E 一度，真太阳时差 4 分钟；偏离约 15° 即一小时），**不设具体阈值**：是否阻断某案例进入时柱类验证，等普查跑出实际分布再定，不在本 ADR 里编造数字。
