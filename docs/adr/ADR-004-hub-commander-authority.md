# ADR-004 · 中枢指挥官授权：完全自主重构及其边界

- **状态**：accepted（已接受）
- **日期**：2026-10-27
- **决策人**：项目所有者
- **取代**：无
- **影响**：`AGENTS.md` §5「保护区」清单中对 `tests/` 与已实现逻辑的冻结要求

## 背景

本项目由零编程基础的作者用 AI「氛围编程」搭建，初版由 ChatGPT 5.5 生成，结构上存留大量历史遗留问题。2026-10 的底层体检（`tools/engine_audit.py`、`tools/relations_audit.py`，481 盘）证明**排盘与关系图本身是干净的**，故障集中在上层结构：事实层与候选层边界模糊、`engine/v5` 与现行实现双轨、测试大量只断言「不抛异常」。

此前的工作方式是「先要授权再动手」，导致每修一处都要人类逐个批准，无法成体系地清除结构性故障。人类决定改为：**设一个中枢指挥官会话，授予完全自主的重构权限，由它统一拆分、派发、验收。**

## 决策

### 1. 授予完全自主重构权限

中枢指挥官可以**无需额外许可**地：

- 重写任何已实现、已验证的逻辑，包括但不限于：宫制星藏干派生（`structure_check._derived_canggan_ke`）、条件 IR 的原子与求值器（`engine/claims/condition_ir/`）、四段协议 L0–L6 的分层与流派路由、关系图的全部建边规则、事实层与候选层的模块边界。
- 删除、合并、拆分模块；退役 `engine/v5`；推翻现有分层。
- 修改或重写 `tests/` 下的任何测试文件。

「已验证」「已修复」不构成豁免。已修复的逻辑若与目标架构冲突，可以重做。

### 2. 三条不可协商的红线

**红线一：不得改断言让失败变绿。**
可以重写整个测试文件，但不能为了让红变绿而删除或放宽判据。若判据本身有错，须先给出依据（命理原文锚点或代码事实）再改，并在提交信息中写明「判据为何错」。

**红线二：原文语料只增不改。**
`theory/_ir/` 与 `sources/` 下的八字原文、摘录、页码锚点不得修改。那是全部断语的证据底座，改一个字引用链即断。新增语料须走 ingestion-protocol。

**红线三：重构前后用同一把尺子。**
动手前先跑基线并记录；重构后跑同一批命令对比。任一指标下降，必须在汇报中写明原因，不得静默放过。基线由 `tools/verify_baseline.py` 一条命令产出。

### 3. 验收权不下放

中枢指挥官对子代理的结论只有「待核」一种状态。**子代理说通过不算数，中枢必须亲自执行命令并读取退出码。**数字必须现场跑，不得引述二手结论（含中枢自己上一轮的结论）。

### 4. 重构的判据

重构不是目的。每一次重构必须能回答：

> 这次重构让**哪一条断语**从「算不出来」变成「算得出来」？

回答不了的，不重构。

## 后果

- `AGENTS.md` §5 的保护区清单中，`tests/` 一项的冻结效力本条降级为「可改，但受红线一约束」；其余保护区（`pyproject.toml`、`requirements*.txt`、`theory/_ir/`、`sources/`、`templates/report-v7-human.md`、`docs/analysis_human_touch.md`、`META/project-state.json`、`AGENTS.md`、`CLAUDE.md`、`tasks/*/PROMPT.md`）保持不变，除非人类另行明确授权。
- 中枢指挥官须以 `tools/verify_baseline.py` 作为开工与收口的标准动作。
- 一个指挥中枢 + 多个执行子代理成为默认工作模式；不再逐条向人类请示实现细节。
