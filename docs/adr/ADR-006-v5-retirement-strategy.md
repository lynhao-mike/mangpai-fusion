# ADR-006 · `engine/v5` 退役方式：冻结 + 闸门 + 按功能消解，不做一次性大迁移

- **状态**：accepted（已接受）
- **日期**：2026-10-27
- **决策人**：中枢指挥官（依 [ADR-004](ADR-004-hub-commander-authority.md) 授权代决）
- **取代**：`tasks/T-128/PROMPT.md` 中「P1 渲染路径去 v5 / P2 度量链接管 / P3 归档」这条「先迁移后退役」的路径
- **影响**：`engine/v5/` 保留；新增边界闸门；三个报告入口的改造降级为独立小任务

## 背景

A3 一直被表述为「全部迁到新链，还是保留一层适配」，两种说法都要动几十个文件。2026-10-27 现场实测（主工作区，排除 `.worktrees/`、`.venv/`、`_archive/`）后，这个二选一的前提是错的：

| 范围 | 引用 `engine.v5` 的 `.py` 文件数 |
|---|---|
| `engine/` | 36 |
| `tools/` | 12 |
| `tests/` | 53 |
| 其他 | 1 |
| **合计** | **98** |

关键结构：**98 个文件里 53 个是测试**，真正对用户可见的只有 `tools/` 的 12 个。

这带来两个结论：

1. **迁移的成本几乎全在测试上。** 53 个测试文件跟着新链重写，是数周工作量，而它**不产出任何一条断语能力**。按 ADR-004「这次重构让哪条断语从算不出来变成算得出来」的判据，这不合格。
2. **双轨的真实危害不是「代码多」，而是「Agent 可能走上第二条推理链」。** 这个危害用一道闸门就能止住，不需要动 98 个文件。

## 决策

### 1. `engine/v5` 定性为「历史度量链」，不是候选推理链

v5 可以继续存在、继续被白名单内的旧代码调用，但它**不是**答案的来源。任何新代码、任何断语编译、任何 L0–L6 协议实现，都不得引用 v5。

### 2. 建立机器闸门，白名单只减不增

新增 `tools/v5_boundary_check.py`，把当前 98 个文件登记为白名单快照。规则：

- 白名单外的任何 `.py` 文件 import `engine.v5` → 退出码 1，pytest 门禁红。
- 白名单内文件消失（被改造掉）→ 必须同步从白名单删除；**白名单条目数只许下降**。
- 闸门自带一项断言：白名单条目数不得大于快照数，防止有人「加一条豁免」绕过。

这一条把「不许新增双轨」从口头约定变成可执行的判据。

### 3. 不做一次性大迁移

明确放弃「先全迁到新链、再删 v5」的路径。理由见背景第 1 条：成本集中在 53 个测试，收益为零条断语。

### 4. 退役路径绑定功能替换，而不是绑定日期

每完成一个断语编译模块（B 组），就删除它对应的 v5 调用点，白名单同步减少一条。v5 随功能被取代而自然萎缩，不设「某月某日删完」的里程碑——那只会逼出一次性大改。

### 5. 三个报告入口单独立项，不绑定 v5 退役

`tools/render_report.py`、`tools/domain_analysis_cli.py`、`tools/domain_capability_status.py` 改为内部走新链，对外参数与输出不变。这是独立任务，做完不等于 v5 能删（引擎侧 36 个文件仍在），所以不与退役进度互相绑死。

`tests/test_project_metadata.py` 对 `active_report_entrypoints` 的断言**不得修改**——入口清单不变，只换内部实现。

## 依据

- 现场计数：见背景表，命令为排除 `.worktrees/` 后对 `engine.v5` 的全文匹配。
- 判据：ADR-004 §4「重构必须回答让哪条断语从算不出来变成算得出来」。
- 风险判断：双轨的实际危害是路由歧义，闸门可止；删除文件的收益是整洁，不是能力。

## 后果

- `engine/v5/` 短期保留，文件数不变；新增 `LEGACY` 标记与闸门。
- 白名单条目数成为一条可跟踪的下降曲线，替代「阶段表」。
- 需要新增任务 T-134 实现闸门；需同步修正 `tasks/T-128/PROMPT.md` 的阶段表（由中枢改，Worker 不碰任务卡）。
- 若将来发现 v5 确实在被生产路径用于出结论（而非仅度量），本条决策需重审——届时的判据是「找到一条从 v5 走到用户可见断语的路径」，而不是「文件还在」。
