# ADR-002 · 交付与指标的双层记分（解决「交付优先 / 指标优先」）

- 状态：`accepted`（已接受）
- 日期：2026-10-26
- 决策人：产品负责人（用户）
- 记录：Agent
- 相关：[ADR-001](ADR-001-engine-agent-boundary.md)

## 1. 背景

项目里同时存在两版「重设」，一直没合并成一句话：

| 版本 | 主张 | 出处 |
|---|---|---|
| 10-14 版 | 产品目标回到**命理师咨询交付**；盲测是内部底座；准确率门槛「以后再定」 | `plans/product-architecture-review-handoff-2026-10-14.md` |
| 10-20 版 | 北极星（最高目标）换成两个可测指标：A 盲断准确率 45.3%（77/170，18 例）、B `balanced_accuracy` 0.3625（门槛 0.425 / 0.60） | `META/REFACTOR-BRIEFING-2026-10-20.md` |

两个指标都窄：A 只测「年份吉凶」，样本 18 例；B 只测职业二分类。任何单指标都不足以代表「分析准确」。

## 2. 选项

| 选项 | 内容 | 风险 |
|---|---|---|
| A1 | 指标驱动：一切按 A/B 排序 | 产品被压成「猜年份」；18 例样本易过拟合 |
| A2 | 交付驱动：以可用性为主，准确率只监控 | 回到「看起来像报告」的老路，无法证伪 |
| **A3** | **双层记分 + 一票否决 + 明确排序规则** | 需要命理师每份报告打一次分（约 1 分钟） |

## 3. 决定

1. **主指标（交付）**：每份报告由命理师打 3 项 1–5 分——可面谈性、证据可核性、结论敢拍板；同时记**返工次数**。
2. **副指标（准确）**：
   - 盲测严格口径准确率，按批累积，**必须同时报样本量与置信区间**；
   - 规则级命中与证伪记录；
   - 事项级选择题准确率（铁口箓题库，单独记分，不与年份盲测混算）。
3. **一票否决**：出现下列任一项即判不合格，不论指标多高——编造事实、悬空引用（引用的地址/规则不存在）、假阳性证据、结果泄漏。
4. **排序规则**：先过否决线 → 再比交付分 → 交付分持平时看准确率。
5. **禁止**：用单一准确率数字宣布「系统可用」；用「报告像样」代替准确率。

## 4. 理由

- 交付与准确并不天然同向：报告写得漂亮但方向错，是最危险的失败（假阳性比没有功能更糟）。
- 双层记分把「准确」保留为北极星，同时不让一个 18 例的小样本指标绑架路线。
- 否决线先在，避免「指标漂亮但证据造假」的局部最优。

## 5. 后果

- 需要一张固定的评分表（3 项 × 1–5 分）随报告一起交付；评测记录进入验证题库目录。
- 任何「提升准确率」的改动，必须先声明它改的是哪一层（事实/候选/裁决/表达），再报对应指标。

## 6. 证伪条件

若交付分与准确率长期负相关（越「好看」的报告越不准），说明评分表失效，需重新设计评分维度。
