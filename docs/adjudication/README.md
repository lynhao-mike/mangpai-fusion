# 裁决过程记忆（adjudication log）

本目录保存**裁决过程**，不是当前契约、也不是错误清单。

- 当前契约：`docs/specs/adjudication-a-plus-v1.md`（A+ v1.3）等
- 错误记忆：`docs/reviews/failure-ledger-v1.md`
- 过程记忆：`docs/adjudication/log-v1.md`（本目录）

## 制度

1. 每次裁决/重大转向（换目标、换指标、换架构、kill/复活、预注册冻结）后 **24h 内**追加一条 `AD-xxx`。
2. **append-only**：旧条目不改；更正另起一条；被推翻的旧结论保留“当时为什么像对的”。
3. 每条必须含：问题、选项、各方意见、现场证据、决定、否决理由、后果、链接。
4. 中枢负责写；子代理可起草，但中枢验收并提交；**不写日志的裁决不算完成**。
5. 新裁决前先读 `log-v1.md` §2「老路/反模式」，避免重复。
6. 日志与 failure-ledger 双向引用：错误条目给日志锚点，日志给错误 ID。

## 为什么

过去把过程散在任务卡/裁决书/对话里，重构时只看到“现在的结论”，看不到“为什么否掉 A/K、为什么杀党势、为什么 T-187 不算产品 kill”，会重复走老路。日志是**过程的可复现证据**。
