# 第三方裁决：新开对话 vs 续聊（standing rule，2026-10-29）

> 来源：人类指令——「以后如果给第三方 Agent 一些裁决类的任务，如果以前让他裁决过，或者有类似的，
> 必须告诉我新的裁决任务是否需要新开对话，还是在原来的对话继续进行。」

## 1. 触发条件

任何给第三方 Agent/模型（Gemini、Opus、外部强模型等）的**裁决类任务**，只要满足任一：

- 它以前裁决过本项目；
- 它看过本项目的旧结论、旧 hold-out、旧失败档案；
- 当前任务与它之前的裁决主题相似；

中枢必须在派发前明确写：

> **建议：新开 / 续聊；理由：……；需要携带的最小上下文：……**

不得默认续聊，也不得默认新开。

## 2. 默认新开

- 要**独立判断/盲测**，防止 anchoring 到旧结论；
- 事实/目标已 materially changed（例如 hold-out 被看过、P1 定义改了）；
- 旧对话很长，旧结论可能被维护；
- 被裁决对象已经看过答案/hold-out（污染），需要未受污染的视角；
- 需要它对“当前事实”而不是“它自己的旧建议”负责。

## 3. 可以续聊

- 要它为自己之前的建议**负责/修订**（它必须知道旧结论）；
- 直接 follow-up/澄清，不需要独立视角；
- 连续推演，换新会丢关键上下文；
- 旧对话里的具体原文/代码引用是本次裁决的必要输入。

## 4. 输出格式（派发前给人类）

```text
【第三方裁决对话建议】
- 对象：<模型/Agent>
- 建议：新开 / 续聊
- 理由：<anchoring / 污染 / 连续性 / 问责 / 事实变化>
- 携带上下文：<最小包；不贴全文>
- 若续聊：需要它先确认的旧结论：<...>
- 若新开：需要明确告诉它「不要假设你见过旧对话」
```

## 5. 当前案例（2026-10-29）

- **Gemini**：它之前给过方向审计；这次是**复审它自己的建议** → **续聊**合理。
  但它已经看过 dev-20 的答案，后续盲测不能再让它当唯一裁判。
- **Opus.5**：首次裁决本项目，没有旧上下文 → **新开**；携带最小上下文 +
  「不要假设你见过旧对话」。
- 任何后续模型：若已看过 dev-20/答案 → 只能做**校准/解释**，不能做盲测裁判；
  盲测裁判必须是没看过答案的新对话/新模型。

## 6. 与 goal/policy 的关系

- 本规则不改变 goal 的 blocked/active 状态，只约束「派给第三方的裁决任务」。
- 每次派发前，中枢先给建议，再等人确认或直接按建议执行（若人类已授权）。
