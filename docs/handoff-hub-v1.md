## 二、项目是什么

八字（四柱）分析系统，融合四派盲派（高德臣、段建业、杨清娟、任付红）与子平、滴天髓。

**产品目的（人类原话）**：

> 「我希望像一个真正的命理师一样，能熟练运用各流派八字理论，用于真实八字的分析。」
> 「分析八字，不管使用哪个流派，最终目的还是为了能真实进行命理分析预测。」

**唯一重构判据**：这次重构让**哪一条断语**从「算不出来」变成「算得出来」？

技术栈：Python 3.11.16 / Windows / 解释器 `.venv\Scripts\python.exe`。

### 关键认知：盲派不用「用神」

原文（`theory/raw/duan/d01-deep-read.md:106`）：

> 「**用是什么？用是我的目的、我的追求**……需要注意的是，**这个『用』与传统命理中的用神是有区别的**。」

同文件 `:110`：「**体用之『用』≠ 子平传统『用神』。这是 M1 与 M2/M3 划清界限的核心。**」

**所以「补用神层」是错的提案（已撤销）。** 不同流派的第一性判断不同：

- **盲派**：体用 + 宾主 + 做功成败
- **子平**：格局 + 用神
- **滴天髓**：气势流通 + 寒暖调候

### 盲派分析链（原文依据）

```
① 排盘 → ② 宾主（4层）→ ③ 体用（体=日主/印/禄/比劫；用=财/官杀；食伤双属）
→ ④ 做功（制用/化用/生泄/合用/墓用/复合）→ ⑤ 论成败（有势+有功、制得住/制死）
→ ⑥ 取象（宫位象+十神象+宾主象）→ ⑦ 落事 → ⑧ 应期
```

原文（`d01-deep-read.md:175`）：「只有势没有功不行，只有功没有势不能有大作为。」（注意：这是**富贵命**判据，不是通用成败判据）

## 十、2026-10-28 重大核实结果（两份复审意见的交叉验证）

中枢已逐条复现 ChatGPT 6 复审（`docs/reviews/verdict-chatgpt6.md`），以下**五条全部成立**，且都影响后续所有工作：

### 10.1 `can_control`（能否制住）是关系盲的（**严重缺陷**）

实测：盘 `丁卯 癸卯 丁卯 癸卯`，`can_control(卯 木, 丁 火)` 返回 **True**，note 写「制得住」。
但**木生火，木不克火**——它根本没检查五行相克关系，只比较了谁的旺项多。

- 36 期 1578 个异五行对：True 169 / False 169 / **None 1240（78.6%）**
- 169 个 True 里 **135 个（79.9%）是非克对**

中枢在 T-145 验收时只测了两张标杆盘（水克火，恰好是真克），**没有测非克对**，所以漏掉了。

### 10.2 `condition_ir`（断语求值器）不在产品路径上

`engine/` 内部**零调用**。只有测试与 4 个工具脚本 import 它：`claim_condition_corpus.py`、`claim_condition_report.py`、`tiekoulu_eval.py`、`education_label_sheet.py`。

`engine.cli all` 走 `engine/api/facade.py`，只返回事实，**不返回任何断语裁决**。

**含义**：T-142/T-143 在 `pilot-20.yaml` 上做的所有改进，**不改变任何一份真实报告的产出**。

### 10.3 产品层有反条件，但算了就丢（**最容易修的一处**）

- 生产规则在 `theory/production/claim-rules-v1.yaml`（10 条），由 `engine/v5/{duan,gao,yang}_runner.py` 通过 `engine/claims/rule_loader.py` 求值
- `rule_loader.py:352` 算出 `matched_counters`，`:358` 存进结果
- **但 `:354` 的 `matched = not failed_conditions and not matched_exclusions` —— 不含反条件**

⚠️ 不能直接改：至少 3 条规则的正/反条件阈值重叠（正 `>=0.35`、反 `<=0.4`），直接拦会把命题变成「同时成立且不成立」。要先消除重叠。

### 10.4 `META/baseline-v1.json` 已过期（**尺子有洞**）

文件里存的是 `pytest_passed: 220`、`zuogong_day_branch: 350`；实际是 **1040 / 346**。
所以 `verify_baseline --compare` 一直在和一个一个月前的基线比，**「同一把尺子」这条红线实际没守住**。

### 10.5 「力量相当」判成未知，违背原文

原文（`MinerU_markdown_22...:1812`）：「戌辰力量相当，**互相制不了**」——「制不了」是确定的否定结论，不是「不知道」。
现行实现返回 None（未知），把原文唯一给出的裁决点丢掉了。应返回 **False**。

### 10.6 两份复审的共同结论

| 项 | Gemini 4 | ChatGPT 6 | 中枢裁决 |
|---|---|---|---|
| pilot-20 是断语层 | 未直接说 | **明确否定**：产品断语在 `claim-rules-v1.yaml` | ✅ 采纳 |
| `can_control` 不能当成败判据 | 成立（口径偏离原文） | **成立（关系盲，79.9% 非克对）** | ✅ 采纳，且已实测 |
| T-147 的 3 条断语 + n≥10 证明点 | 数学上不可达 | 数学上不可达（功效 17%） | ✅ 采纳，T-147 已作废 |
| 先补成败再扩样本 | 修正 | 修正（应同批做） | ✅ 采纳 |

**下一步方向**：先修度量契约（触发器/结果分离）+ 修 `can_control` + 刷新基线，再谈建模。
