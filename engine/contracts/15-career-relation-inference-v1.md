# 职业柱关系推断契约 v1

## 1. 目的与边界

本契约把高德臣职业五步法表达为可执行、可审计、无权重的数据结构与离散选择过程。实现入口为 [`career_relation_contract.py`](../asof/career_relation_contract.py)。

本层只负责：

- 表达四柱、我宫/他宫、五步候选阶段、柱间关系及证据；
- 校验候选是否满足所属步骤的必要关系；
- 按五步顺序选择唯一最高优先级候选；
- 显式保留无候选、关系不足、平级冲突和左柱缺失；
- 生成确定性 JSON，供后续关系引擎、回放与审计使用。

本层不负责：

- 从命盘计算十神、藏干、通根、入库或柱间关系；
- 推断任职、经营或具体职业；
- 计算力量、概率、置信度、浮点评分或经验权重；
- 读取 occupation、known facts、标签、反馈或其他职业答案；
- 修改 v1-v3 职业分类器或切换生产默认入口。

## 2. 冻结类型

所有领域枚举均为稳定字符串枚举；所有记录均使用冻结、slots 数据类。

### 2.1 柱位与宫位

柱位固定为：

1. `year`：年柱
2. `month`：月柱
3. `day`：日柱
4. `hour`：时柱

职业语义宫位固定为：

- `self_palace`：我宫，即日柱、时柱；
- `other_palace`：他宫，即年柱、月柱。

### 2.2 五步选择阶段

优先级只由下列离散顺序决定，不得增加分数打破平级：

1. `step_1_self_officer_killing`：我宫官杀；
2. `step_2_self_officer_killing_tomb`：我宫官杀库；
3. `step_3_other_officer_killing_linked_to_hour`：他宫官杀，且与时柱有关系；
4. `step_4_wealth_or_wealth_tomb`：财星或财库；候选发现层必须先我宫、后他宫；
5. `step_5_formation_star_linked_to_self`：成格星，且与我宫有关系。

第 4 步“先我宫后他宫”属于候选发现器必须提供的语义。v1 契约不虚构第六档权重，也不在同一步内用经验分数排序；若调用方同时提交多个第 4 步候选，契约将其视为平级冲突。

### 2.3 关系类型

冻结关系集合为：

- `combination`：合；
- `clash`：冲；
- `punishment`：刑；
- `harm`：害，适配现有谓词时包含仓库中的“穿”术语；
- `hidden_revealed`：藏透；
- `adjacent`：邻柱；
- `rooted`：窄义原字根存在；
- `enters_tomb`：入库。

关系必须连接两个不同柱位并携带至少一个非空证据引用。`adjacent` 只允许连接年—月、月—日、日—时。关系计算是否成立由上游关系发现器负责，本契约只校验结构不变量。

当前上游图构建器对 `rooted` 采用最小语义：某柱天干原字出现在另一柱地支的标准藏干（主气、中气或余气）中。它不把同五行异阴阳天干视为根，也不表达根的强弱、受损、得令、来源质量或库的开闭。由于本契约禁止同端点关系，同柱原字根不生成图边，但可由纯谓词独立查询；完整通根强弱仍为 unresolved。

## 3. 候选、状态与原因码

每个职业柱候选必须包含柱位、宫位、五步阶段、证据引用以及零个或多个关系。输入候选状态必须为 `proposed`。

推断后的候选状态：

- `selected`：唯一最高优先级候选；
- `conflict`：最高优先级存在多个候选，全部保留；
- `rejected`：关系/宫位不满足，或被更高优先级候选压后；
- `proposed`：仅用于尚未执行推断的输入。

否决原因：

- `palace_stage_mismatch`：柱位宫位不一致，或步骤要求的宫位不符；
- `missing_hour_link`：第 3 步候选没有与时柱的关系；
- `missing_self_palace_link`：第 5 步候选没有与我宫的关系；
- `lower_priority_stage`：候选有效，但已有更早步骤获胜。

弃权原因：

- `no_candidate`：调用方没有提交候选；
- `no_eligible_candidate`：有候选，但全部被必要条件否决；
- `multiple_top_priority_candidates`：最高优先级有多个候选，禁止静默任选。

## 4. 左柱边界

左柱严格按年→月→日→时的展示顺序取职业柱紧邻左侧：

| 职业柱 | 左柱 |
|---|---|
| 年柱 | 显式缺失 `null` |
| 月柱 | 年柱 |
| 日柱 | 月柱 |
| 时柱 | 日柱 |

因此，时柱的左柱必须是日柱；“时柱无左柱”不是本契约语义。唯一没有左柱的是年柱。即使左柱缺失，已选择年柱时仍必须存在左柱记录，其中 `career_pillar=year`、`pillar=null`，不得省略整层。

## 5. 选择算法

1. 拒绝非 `proposed` 的推断输入；
2. 校验柱位和声明宫位一致；
3. 校验第 1、2 步位于我宫；
4. 校验第 3 步位于他宫且至少一条关系连接时柱；
5. 校验第 5 步至少一条关系连接我宫；
6. 在剩余候选中取编号最小的阶段；
7. 该阶段只有一个候选则选中，并构造显式左柱；
8. 该阶段有多个候选则全部标记 `conflict`，整体以 `multiple_top_priority_candidates` 弃权；
9. 其余有效候选标记为 `lower_priority_stage`，不得以分数重新竞争。

## 6. 确定性序列化

schema 固定为 `career-relation-inference/v1`。规范序列化遵循：

- 枚举输出稳定字符串值；
- 数据类字段按声明顺序展开；
- JSON 对象键按字典序输出；
- 候选按步骤、柱序、状态规范排序；
- 关系按源柱、目标柱、关系类型、证据引用规范排序；
- 证据引用去重并按字典序排序；
- 使用紧凑分隔符且保留 Unicode；
- 不序列化集合、对象地址、哈希值或运行时顺序。

同一语义输入即使候选、关系和证据引用顺序不同，也必须得到逐字节一致的规范 JSON。

## 7. 评估隔离与证据缺口

本契约遵循 [`14-career-path-evaluation-protocol-v1.md`](14-career-path-evaluation-protocol-v1.md)：P 系列 40 案只可用于开发回放，不能作为晋级证据；当前真实未见 holdout 尚未就绪。关系模型在标签揭示前只能消费命盘结构和冻结规则证据。

当前谓词可实现性结论：

| 主题 | 当前结论 | 阻塞原因 |
|---|---|---|
| 原字根存在 | 已实现最小纯谓词与异柱 `rooted` 边 | 只证明标准藏干原字存在，不证明强弱 |
| 完整通根强弱 | unresolved | 缺少离散、可审计且经理论/专家确认的强弱定义；不得用浮点聚合替代 |
| 墓库 / 官杀库 / `enters_tomb` | unresolved | 十二长生之墓、五行库、十神库、入库方向及开闭状态尚无统一通用算法 |
| 力量四态 | unresolved | 缺少状态枚举、边界与冲突裁决；现有连续强度值不是等价定义 |
| 成格星 | unresolved | 缺少契约级构造、候选与平级裁决规则，需要理论补足或真实专家裁决 |

因此当前仍存在以下证据缺口：

- 尚无真实未见 holdout 可验证职业柱定位一致性与轨迹完整度；
- v1 只定义关系记录，不验证每种干支关系的完整命理真实性；
- 第 2 步官杀库和第 5 步成格星不得生成候选，`enters_tomb` 不得生成边；
- 第 4 步目前只实现财星的“先我宫后他宫”，未实现财库；
- 五关注法、完整通根强弱、力量四态、制化与大运时序属于后续推理层；
- 墓库、力量四态、成格星需要理论定义补足或真实独立专家标注，agent 不得制造专家真值。
