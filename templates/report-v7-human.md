## 模板使用说明

1. **单报告架构**：只生成这一份人话主报告；边号 / 理论 ID 全部收拢到节末简注（`（依据：M.b、e013、M1-D-029）`）与文末《附》。历史存量 v6 `*-analyst-report.md` 保留兼容，**新分析不再强制产出 v6**。
2. **三级声明词**（`板上钉钉`、`大概率`、`我不编`）必须**原样**出现在《先把话说死》。
3. 《先把话说死》是全文**唯一**允许集中写「不测 / 缺项」的位置；除此之外，只有文末 `> 边界声明：` 引用块可含声明性表述。
4. 第三节标题按命主所问替换重点事项；命主未问婚育六亲时，可改题为「六亲健康 / 其他重点事项」，**或整节省略**——若省略，须在《先把话说死 · 我不编的》中声明「本次未问婚育/六亲，故第三节略」，其余节号不顺延。
5. 模板头部**不设 `run_id` 字段**：引擎不返回该字段，禁止要求执行者提供不存在的数据。
6. **头部第二行是契约指纹**（`盘面 schema` + `地址契约`），必须按下列规则填写，不得留空或臆造：
   - `盘面 schema`：优先取本次 `engine.cli relations` 输出的 `schema_version`（实测为 `relation-graph/v1`）；
   - 若所用子命令不返回 `relations.schema_version`，则取 `chart.schema_version`（实测为 `chart-facts/v1`）；
   - **两者是两个不同值，不得互相顶替**；仅当两次取值都失败时才写 `relation-graph/v1` 作为兜底；
   - `地址契约`：填 `tools/human_touch_linter.py` 里 `ADDRESS_SCHEMA_VERSION` 的当前值（`addr/v1`）。
   - 它的作用是让读者知道这份报告的边号 / 地址是按哪个引擎契约写的；引擎变更后，旧报告不会与新盘混用。
7. **写作纪律**见 [`docs/analysis_human_touch.md`](../docs/analysis_human_touch.md)：三大病灶禁令、干支→人话翻译表、流年断法三要素、裁决义务。
8. **交付前必过门禁**：`python -m tools.human_touch_linter <本文件>` 零 ERROR 方可归档。
