Behavior covered
----------------
- Four pillars, sex marker, valid dayun ranges, and a matching explicit target
  year are L0 canonical observations.
- No target year means no liunian fact, even with ledger liunian rows or a
  captured_at value that names a year.
- No system clock, as_of_date, or captured_at input is consulted.
- Versioned ChartFeatureVector day-master signals are L1 only; with no feature
  vector, no L1 fact is created.
- Fact payloads exclude school, conclusion, confidence, and role.
- Same input/version is deterministic in-process and across separate Python
  processes. The focused suite executes the separate-process case.
- L0 fact identities remain stable across calculator versions while content
  digests and snapshot content bindings change.
- Adding dayun cannot modify the natal four-pillar fact.
- Malformed dayun/liunian records are skipped rather than projected.
- raw_source_hash mismatch is rejected as stale state.
- Raw prompt-like text cannot be projected into fact payloads.
- The implementation is pure, opens no resources, has no mutable module state,
  and has no asynchronous work; cancellation, interruption cleanup, and hung
  process paths are therefore not applicable to this adapter.

Rework: Fail-Closed Liunian Admission
======================================

Reason
------
Independent acceptance found that the original adapter admitted a target year
outside declared dayun coverage and silently accepted both conflicting and
identical duplicate liunian rows.

Decision
--------
- A requested liunian now requires at least one valid declared dayun range.
- The requested year must fall within one of those ranges.
- Exactly one valid ganzhi row may exist for the target year.
- Missing dayun context, out-of-range target years, conflicting duplicates, and
  identical duplicates raise FactBuilderError with distinct issue codes.

Second-round rework: Dayun integrity and L1 chart binding
===========================================================

Reason
------
Acceptance review required fail-closed validation of declared dayun intervals
and proof that a supplied L1 feature vector belongs to the current chart.

Decision
--------
- Each declared dayun row now requires a nonempty ganzhi and an inclusive,
  valid year range; malformed rows raise FACT_BUILDER.DAYUN_STEP_INVALID.
- Declared dayun ranges must not overlap; overlaps raise
  FACT_BUILDER.DAYUN_OVERLAP.
- A supplied ChartFeatureVector is rebound through the established feature
  builder using its schema version. A mismatched chart_id raises
  FACT_BUILDER.FEATURE_VECTOR_CHART_ID.
- raw_source_hash remains an independent stale-source integrity check because
  the established feature-vector chart_id intentionally excludes that hash.

Third-round rework: Duplicate-range characterization and L0 projection typing
===============================================================================

Reason
------
Final acceptance required explicit regression coverage for identical and
conflicting values declared over the same dayun interval. It also identified
the six-parameter, raw-dict _l0_fact helper as an avoidable typed-boundary
violation.

Decision
--------
- The existing parameterized dayun-admission test now includes both identical
  and conflicting same-range rows. Both characterize the intentionally single
  FACT_BUILDER.DAYUN_OVERLAP admission result.
- _l0_fact was removed. Frozen _L0Projection owns typed L0 metadata and a
  CanonicalValue payload; its build method accepts only calculator version.
- The test parameter is represented as typed range tuples and projected to the
  legacy ledger row shape only at the test fixture boundary.
