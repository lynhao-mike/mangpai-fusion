# 双核盲测与规则沉淀阶段性设计

> 状态：阶段性设计已确认，尚未实施案例验证。
> 确认日期：2026-10-14
> 本文记录当前已确认边界，不修改 [`AGENTS.md`](../AGENTS.md) 的现行规则，也不改变生产代码、规则库或历史数据。

## 1. 目标

系统同时支持命理师的实战分析交付和底层规则有效性沉淀：

- 案例交付以最后一轮封存结论为准。
- 规则沉淀单独保留每条规则的触发、事实对照、独立命中和仲裁推翻记录。
- 两条统计线互不覆盖。

## 2. 模式入口

每次分析开始前必须选择以下之一：

- 盲测：封存前，Agent 不得读取履历、反馈和结果。
- 普通咨询：从开始即可使用已知事实，但记录永久不能改标为盲测。

命理师本人此前是否知道事实，不作为 Agent 盲测是否成立的判断标准。只有这些事实被提供给 Agent，才破坏 Agent 盲测。

## 3. 盲测记录

盲测期间每轮变更都保留，每轮至少记录：

- 结论。
- 所用断语。
- 推理理由。

不把命盘事实重复列入每轮最低依据。首次向 Agent 提供本次全部履历、反馈和结果时，封存全部盲测记录；此后禁止修改。

## 4. 揭示后的分析

首次提供核验资料后，可以补充或更正事实，但后续分析不再称为盲测：

- 对已发生事项的重新分析称为“复核结论”。
- 对未知或未来事项的推断才称为“预测”。
- 事实保留更正前后版本。
- 更正后的事实用于重新形成复核结论或预测，不改变已封存盲测记录。

## 5. 机器可判定记录

盲测轮次和核验记录的最低结构、分组键、去重单元、错杀率、纠偏率及轮次职责，以 [`engine/contracts/22-dual-core-blind-validation-v1.md`](../engine/contracts/22-dual-core-blind-validation-v1.md) 为准。

## 6. 统计口径

- 案例最终准确率只计算封存前最后一轮。
- 较早轮次可以单独保留和对照，但不能替代最终结论。
- 一条规则在较早轮次符合事实、最终结论却未采用时：案例最终准确率不算命中；规则统计同时记录“独立命中”和“仲裁推翻”。
- 规则记录形成后不可覆盖。发现错误时新增更正记录。
- 规则统计保留原快照，并并列生成按更正后记录重新计算的当前统计。

## 7. 规则修改

真实案例可以产生规则修改标记，但标记不自动生效：

- 按同一规则、同一结论方向分组；具体修改点留到复核时再拆。
- 多个一致案例仍只是待确认积累。
- 只有命理师确认后，修改才生效。
- 生效范围仅限确认后的新案例分析，不回写历史盲测记录、历史案例准确率或原规则统计快照。

## 8. as-of 裁决

保留“盲测必须先封存、后核验”。

取消 as-of“核验后必须继续进行状态推演”的默认优先地位。未来预测仅在命理师选择时进行。

这是产品裁决，已同步到 [`AGENTS.md`](../AGENTS.md) 第 6 节。未来预测仅在命理师明确选择时进行。

## 9. 首批验收

首批使用固定的 3 个真实案例，只验证流程正确性，不设定准确率门槛。

每个案例开始前由命理师指定一个或多个已发生事项类别。指定时只给事项范围，不提供该事项的真实结果。Agent 只分析指定事项。

每个案例至少检查：

- 模式选择正确。
- 盲测期间没有向 Agent 泄露履历、反馈或结果。
- 每轮结论、断语和理由被保留。
- 首次揭示时完整封存盲测记录。
- 复核结论、预测和盲测记录相互分离。
- 事实更正与规则更正均新增记录，不覆盖原记录。
- 指定事项均有可对照的真实资料。

指定范围内任一事项无法对照，即该案例流程失败。3 个案例必须全部通过。任一失败则整批不通过；先修正流程，再使用原来的 3 个案例全部重新验证，不得替换案例或只重测失败案例。

全部通过后，暂停扩大样本和设定准确率门槛，再汇总正式规格。
