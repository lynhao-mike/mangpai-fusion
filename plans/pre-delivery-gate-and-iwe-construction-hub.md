# 交付前拦截与 IWE 驱动构建枢纽

## 核心判断

反馈统计只能校准跨案例先验，不能认证当前个案。系统的第一目标应是在断语出口前标记事实错误、证据不支持、派别分歧、越界断言和结果泄漏。

LLM 可以成为语义推理主持人，但不能成为事实源、冻结记录或反馈原文的修改者。代码负责确定性事实、证据寻址、结构性护栏和不可变账本；语料提供原文与适用边界；多派分歧用于触发降级、竞争假设、追问或弃权，不用于数值投票抹平。

## IWE 已核证的仓库证据

- [盲断批次报告](../reports/as-of-life-state-blind-judgment-batch-report) 显示盲断验证必须区分命中、替代命中与 MISS，不能仅以总体命中率证明个案可靠性。
- [盲态表格注释检测合同](as-of-life-state-blind-judgment-probe-table-annotation-detection-contract) 记录了表格行内嵌真实履历导致的实际盲态污染，并明确探针只覆盖已观测模式，不代表所有泄漏均已拦截。
- [as-of 根因报告](../reports/as-of-life-state-blind-judgment-root-cause-report) 记录了规则存在但未被推理现场消费的案例，说明优先级应是证据接入与交付前校验，而不是先扩充规则数量。
- [引擎总契约](../engine/contracts/00-OVERVIEW) 记录了当前“引擎产骨架结论、AI 仅润色”的旧边界；该边界是待验证的历史契约，不应直接当作终局架构。
- [项目进度仪表盘](../progress/PROJECT_PROGRESS) 记录了工程能力已较完整但真实 prospective cohort 尚未就绪、生产准入仍关闭的事实，因此本枢纽不授权未经验证的生产切换。

## 三层交付前防线

### 第一层：事实硬边界

排盘、岁运、藏干、合冲刑害、空亡、神煞和冻结输入由确定性代码生成。LLM 只能引用，不得计算、改写或混入 known facts、反馈和结果。事实层还必须保留输入快照、来源路径和不可变校验结果。

### 第二层：独立多源收敛

不同学派围绕同一结构事实独立产生证据和解释。收敛可以提高可交付性；分歧必须成为警报，触发条件化表达、竞争假设、追问或弃权，而不是被权重矩阵压成一个赢家。分歧记录应保留来源、冲突命题、未决条件和采取的降级动作。

### 第三层：断语自带证伪条件

没有事实引用、证据引用、适用理由、时间窗和证伪条件的断语不得直接出口。结构性 linter 可以校验字段完整性、引用存在性和越权；原文是否真正支持断语必须由独立语义抽样复核。高风险事项默认采用条件化表述或弃权，而不是伪造确定性。

## IWE 在项目中的职责

IWE 是 Markdown 事实图谱，不是新的命理推理引擎，也不是 YAML 规则数据库。它维护架构契约、根因报告、验证合同、案例证明物及其依赖关系，帮助每个构建决策回溯到真实失败、明确边界、最小验证产物和证伪条件。

IWE 不承担运行时事实计算、理论规则匹配、LLM 推理、反馈运行时存储或预测账本替代。IWE 的图谱关系用于设计追踪、变更影响分析和证据导航；运行时仍由代码、结构化语料、冻结输入与预测账本各自负责。

## 最小构建顺序

1.  先定义 chart-only 冻结输入和事实硬边界，确保 LLM 无法读取或改写结果字段。
2.  再定义证据包：事实引用、规则 ID、原文定位、适用条件、排除条件、时间窗、证伪条件和分歧记录。
3.  将现有理论检索接入受控推理现场；规则 ID 存在不等于原文语义支持，必须保留人工或独立评审入口。
4.  建立结构性出口 linter，拦截事实越权、引用缺失、时间窗缺失、证伪条件缺失和未处理的多派分歧。
5.  在 C-2026-020 至 C-2026-025 六个有反馈案例上重跑三层防线，比较已知 miss 的事前标记率、漏拦率、误拦率、弃权率与证伪条件完整性。
6.  六案例通过后再做十案双轨对照；只有验证达到门槛，才考虑降低旧权重、路由和仲裁链的生产权力。

## 指标与禁止推断

必须同时报告已知错误事前标记率、漏拦率、误拦率、弃权率、证据直接支持率、事实泄漏率、规则引用有效率、规则引用语义支持率、重放稳定性、人工审核时长和返工次数。不能只报告拦截率，因为全面弃权会制造虚假的高拦截率。

历史命中率、Beta 后验、星级和百分比只能描述跨案例先验，不能直接认证当前个案。盲断测试通过也不能证明所有未来输入模式安全；必须保留探针覆盖范围和未覆盖模式。

## 第一个不可逆决策

在任何生产切换或旧引擎删除之前，先冻结“交付前证据包 + 结构性出口门”的协议版本，并让六案例复跑产出可审计的对照物。旧引擎暂时保留为基线、回放器和审计资料，不承担新架构的语义主裁判；未经证据支持不得物理删除。

## 证伪条件

若六个案例中已知 MISS 大多数无法在交付前被标记，或误拦率、弃权率高到使输出无法使用，则本路线的当前实现不成立，需要回退并拆分事实、证据、分歧与语义支持问题。若 linter 通过率上升但独立语义复核显示规则引用普遍不支持断语，则证明结构完整性不能替代语义证据审查。

## 当前推荐路线

采用分阶段抵达干净目标：终局由 LLM 主持语义推理、代码提供事实与证伪；当前第一刀只做交付前防线、证据包和 IWE 可追溯构建，不做全仓删除、复杂向量化或未经验证的生产切换。IWE 图谱作为架构事实层持续记录证据、依赖和证伪条件，并在每次扩大构建范围前提供追溯入口。
