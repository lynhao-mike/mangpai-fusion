# 第一部分：geju 格局审核结论

## Thesis

原提示词的核心方向是正确的，而且正中本仓库当前最大的认识论缺口：

> 系统必须先在不知道答案的情况下形成可冻结、可证伪的历史盲断、当前判断与未来预测；命主反馈只能进入独立核验与校准通道，不能反向污染原始预测。

这与仓库已经锁定的 as-of 求测方向一致。现有设计已明确“先盲断、后核验、再从核验后的现实位置推演”，并已实现事业主领域、财富显式传播的旁路原型、冻结链、核验裁决、事实/假设状态与状态后推演。

因此，本次任务不应被定义为“从零发明双模式”，而应定义为：

> **审计并完成现有 as-of 原型，使其真正支持无反馈也能完成基础预测、反馈后可选择进行分层校准、两类结果可独立复现，并在证据达标前保持与正式生产入口隔离。**

## The Trap

### 陷阱一：把已有能力当作不存在，重复建设

仓库已经存在：

- as-of 会话状态机；
- 盲断冻结与哈希绑定；
- Verification / Adjudication；
- VerifiedState / HypothesisState；
- 事业未来状态推演；
- 事业到财富的显式传播；
- 历史截止点回放与生产隔离测试。

原提示词使用“建立、实现、开始真正重构”等措辞，容易诱导 Agent 忽略现有实现并另建一套平行系统。

### 陷阱二：把“现实状态更新”和“命理模型校准”混为一谈

命主确认“2021 年换工作”后，至少有两种不同变化：

1. **现实状态更新**：命主的职业路径、身份、资源与后续可达路径发生变化；
2. **解释模型校准**：系统对格局、对象映射、取用、事件映射或应期机制的理解是否需要修订。

二者不能共用一个模糊的 `Calibration State`。现实事实优先，但不自动证明某个命理解释正确；命理解释改变也不能篡改出生事实与冻结盲断。

### 陷阱三：一次性要求全仓重构并立即改代码

原提示词同时要求：

- 产品模式重构；
- 核心引擎统一；
- 状态与版本系统；
- 反馈隔离；
- 命局校准；
- 未来重算；
- 准确率体系；
- UI 支撑；
- 全量测试。

这会形成大爆炸式任务，Agent 很容易“新增几个类 + 测试通过”后宣称完成，却没有证明无反馈路径真的成立，也没有证明校准后未来结论来自重新推理。

### 陷阱四：把“过去和未来共享引擎”误解为完全相同的执行过程

过去盲断与未来预测应共享：

- 原局承载模型；
- 大运阶段模型；
- 流年作用模型；
- 事件语义；
- 领域路由；
- 理论证据链；
- 反证与弃权机制。

但二者的观测状态不同：过去事件可以在冻结后被核验，未来事件只能等待到期观察。正确目标是“共享核心结构与候选生成机制，分离观测和评分阶段”，而不是强迫 past/future 使用完全相同的 I/O 流程。

### 陷阱五：用 `Prediction v1 / v2` 混淆产品版本

仓库已有产品版本、schema 版本、run snapshot 版本和多类 v1/v2 契约。继续使用泛化的 `Prediction v1 / v2` 会造成版本语义污染。

建议改用：

- `BLIND_BASELINE`：冻结的无反馈基线；
- `VERIFIED_STATE_REVISION`：仅吸收已核验现实状态；
- `CALIBRATED_REVISION`：在显式校准差量后重新推演。

产品界面仍可展示“首次预测 / 修正后预测”，内部不使用含混的 v1/v2。

## High-Level Direction

推荐采用“**双模式产品、三层内部状态、分阶段证据门**”：

```text
产品 Mode A：基础预测
  └─ BLIND_BASELINE
       ├─ 历史重大事件盲断
       ├─ 截止日当前状态假设
       └─ 无反馈未来预测

产品 Mode B：可选修正
  ├─ Verification
  ├─ VERIFIED_STATE_REVISION
  │    └─ 用现实位置重新计算未来
  └─ 可选 Interpretation Calibration
       └─ CALIBRATED_REVISION
            └─ 用校准后的解释模型 + 已核验现实状态重新计算未来
```

产品层仍是两种模式；内部必须区分：

1. 事实核验；
2. 现实状态更新；
3. 命理解释校准。

最高杠杆点不是继续扩充规则，而是补上当前原型最关键的断口：

> **现有会话编排以 Verification / Adjudication 为必经路径；需要证明并实现“无反馈也可以冻结当前状态假设并生成未来预测”的基础路径。**

## Bold Takes

1. **原提示词不是方向错误，而是“正确观点堆叠过多、缺少执行分层”。** 27 节中大量内容重复表达“不泄漏、先预测、再核验、可选修正”，应压缩成少量架构不变量。
2. **“命局校准”不能默认允许修改用神、格局或理论权重。** 单案反馈首先只能形成 case-scoped 的解释差量或竞争假设；跨案例生产规则变化仍必须走独立治理。
3. **第一阶段不应扩展六大领域。** 先让事业主领域与财富传播形成完整的无反馈基线—冻结—核验—状态更新—可选校准—未来重算闭环。
4. **当前最需要的不是新的 Calibration 类，而是两个可证伪证明：**
   - 不提供任何命主历史反馈，能否生成可归档的过去、现在、未来基线？
   - 提供同一组冻结反馈后，未来差异能否逐条追溯到现实状态变化或解释校准差量？
5. **“过去盲测准确”不是未来准确率代理。** 它只能作为解释模型获得有限支持的证据；未来必须建立独立到期观察账本。

## What Not To Do

- 不要另建一套与 [`engine/asof/`](../engine/asof/) 平行的 calibration 子系统。
- 不要先切换正式生产入口。
- 不要先做 UI。
- 不要先扩充六大领域规则。
- 不要把核验事实直接写回冻结盲断。
- 不要把现实状态更新伪装成命理结构被验证。
- 不要因单案反馈修改全局规则、派别权重或生产路由。
- 不要以“测试通过”替代真实流程证明。
- 不要把历史回放数据冒充真正 prospective future accuracy。
- 不要为了提高命中率，在结果揭晓后新增事件落点或扩大时间窗。

# 第二部分：原提示词结构审核

## 应保留的核心

1. 不知道真实经历也必须能够独立预测。
2. 历史盲断、当前判断与未来预测必须在第一次运行同时成立。
3. 第一次结果必须冻结，反馈不得覆盖。
4. 核验与校准是可选增强，不是预测前置条件。
5. 过去与未来共享核心命理结构和事件模型。
6. 修正后必须重新执行推理，不得只改报告文字。
7. 局部校准优先，禁止一次反馈推翻整个模型。
8. case-specific 校准与 global rule learning 必须隔离。
9. 历史盲测、未来预测、校准后未来预测必须分账评价。
10. 反馈泄漏与事后圆断必须失败关闭。

## 应合并的重复部分

原第 1、2、4、5、6、10、11、18、22、23、26、27 节都在反复表达：

```text
先独立预测
→ 冻结
→ 可选核验
→ 可选校准
→ 重算未来
```

建议合并为：

- 产品模式；
- 状态机；
- 不可变与泄漏边界；
- 校准语义；
- 验收标准。

## 必须澄清的矛盾

### 1. “同一核心引擎”与“校准改变命局理解”

校准后仍应使用同一推理框架，但允许输入一个版本化、case-scoped 的 `InterpretationDelta`。不能通过复制另一套“校准后引擎”实现。

### 2. “不修正也能预测”与“未来从事实状态出发”

无反馈时不存在完整的 `VerifiedState`。因此基础模式的未来预测必须从：

```text
结构轨
+ 冻结的截止状态假设
+ 最多两个关键条件分支
```

出发，并明确它是盲态预测，不得伪称事实主线。

核验后才可从 `VerifiedState` 形成正式现实主线。

### 3. “修命局理解”与“不得迎合命主”

需要证据门：

- 单个反馈默认只允许事件落点、时间或现实状态层的局部差量；
- 改变结构主判、对象映射或取用，必须有多个相互独立的冻结命题证据或命理师显式裁决；
- 所有差量必须附反证、范围、理由与可回滚父版本。

### 4. “准确率”与开放式命理文本

必须先冻结事件 taxonomy、中心落点、有限替代落点、时间窗和反证条件，否则所谓 accuracy 不可比较。

## 二、最高第一性原则

### 原则 A：独立预测先成立

系统必须在不知道命主真实历史经历时，仅依据：

- 出生与命盘信息；
- 显式 `as_of_date`；
- 大运、流年及必要岁运信息；
- 命主当前问题；
- 冻结的理论与规则快照；

独立生成：

1. 截止日前的重大历史事件候选；
2. 截止日当前状态假设；
3. 截止日后的未来预测。

命主历史事实不得作为基础预测的输入。

### 原则 B：核验和校准是可选增强

用户可以停留在基础预测，也可以进入核验/校准模式。基础预测不能依赖核验流程才能完成。

### 原则 C：原始结果不可变

首次盲态输出必须内容寻址、冻结、可复现、不可覆盖。后续反馈、裁决、校准和新预测只能创建新制品并引用父制品。

### 原则 D：事实更新与解释校准分离

必须区分：

```text
Verification
= 现实发生了什么

Reality State Update
= 已核验事件如何改变当前现实位置和后续可达路径

Interpretation Calibration
= 对格局、对象映射、结构主次、取用、事件映射、应期或理论适用域的 case-scoped 解释差量
```

三者不得合并成一个模糊步骤。

### 原则 E：未来必须重新推演

核验或校准后产生的未来预测必须重新经过共享核心推理链，不能由旧报告文字改写得到。

## 三、产品模式与内部运行种类

### Mode A：基础预测模式

输入不含命主历史反馈。

输出制品类型：`BLIND_BASELINE`。

至少包含：

- 历史重大事件盲断；
- 截止日当前状态假设；
- 未来主预测；
- 最多两个会实质改变未来结论的条件分支；
- 每项判断的证据链、时间窗、中心落点、有限替代落点、反证、弃权状态与置信度；
- 输入快照、规则快照、代码/模型标识与内容哈希。

Mode A 完成后可以直接结束，不得强迫用户核对前运。

### Mode B：可选核验与校准模式

Mode B 只能引用已冻结的 `BLIND_BASELINE`。

内部至少区分两个阶段：

#### B1. `VERIFIED_STATE_REVISION`

只吸收现实核验与影响裁决，更新事实状态和路径，不自动修改命理解释模型。

#### B2. `CALIBRATED_REVISION`

在满足校准证据门并形成显式 `InterpretationDelta` 后，使用：

```text
原始命盘事实
+ 冻结理论/规则快照
+ 已核验现实状态
+ case-scoped InterpretationDelta
```

重新执行未来推理。

产品层可统称“修正模式”，内部不得混淆 B1 与 B2。

## 四、共享核心与时间分账

历史、现在、未来必须共享：

- `NatalCapacityGraph` 或等价原局承载模型；
- `DaiyunContext`；
- `AnnualInteractionTrace`；
- 事件 taxonomy 与功能—落点词典；
- 领域与问题路由；
- 理论证据、反证与弃权机制；
- 事件候选生成与应期推理。

但必须分离观测阶段：

```text
Past candidate
→ freeze
→ retrospective verification

Future candidate
→ freeze
→ wait until due
→ prospective outcome observation
```

不得把历史核验后的重跑结果计为原始盲测命中。

## 六、Verification 语义

核验状态至少区分：

```text
CONFIRMED
PARTIALLY_CONFIRMED
CONTRADICTED
UNCLEAR
UNVERIFIED
WITHHELD
```

每条核验至少记录：

- 冻结命题 ID；
- 预测时间窗；
- 实际时间；
- 预测领域与事件功能；
- 冻结中心落点与替代落点；
- 实际落点；
- 匹配类型；
- 时间偏差；
- 证据来源；
- 核验范围；
- reviewer；
- 是否足以影响现实状态；
- 是否仅揭示 taxonomy gap。

结果揭晓后不得新增替代落点并计作命中。

---

## 七、Reality State Update 语义

已核验事件根据以下维度决定是否改变未来起点：

- 现实影响等级；
- 持续时间；
- 影响领域；
- 截止日是否仍有效；
- 打开、关闭或降低的现实路径；
- 显式跨领域传播边。

未核验、已否定或过期事件不得进入事实状态。

现实事实可以改变后续可达路径，但不能回写出生事实或覆盖冻结盲断。

---

## 八、Interpretation Calibration 语义

校准对象采用局部差量，不重写整个命盘：

```text
InterpretationDelta
├── ObjectMappingDelta
├── StructuralInterpretationDelta
├── PrimarySecondaryDelta
├── YongshenDelta
├── EventMappingDelta
├── TimingDelta
└── DomainApplicabilityDelta
```

每个差量必须包含：

- 原假设；
- 新假设；
- 支持它的独立冻结命题；
- 反证；
- 适用领域；
- 影响范围；
- 证据强度；
- 是否需要人工批准；
- 父版本；
- 回滚方式；
- 会改变哪些未来结论。

默认策略：

1. 单条反馈优先修正事件落点、时间或现实状态；
2. 多条独立证据才允许调查结构主判、对象映射或取用；
3. 高影响校准必须人工批准；
4. 所有校准仅作用于当前 case；
5. 全局规则、派别能力、权重与路由变更走独立跨案例治理，不能由本流程自动触发。

允许最终结论为“原判断错误”，禁止为了保住理论进行事后圆断。

## 九、问题模型

命主当前问题必须成为显式输入，并参与：

- 领域路由；
- 时间范围；
- 事件候选优先级；
- 当前状态摘要；
- 未来输出筛选；
- 弃权或最小消歧问题。

问题模型不得反向改变出生事实或为迎合提问而创造无结构依据的事件。

---

## 十、比较与解释

每次 Mode B 必须生成结构化差异：

```text
Blind Baseline
→ Verification Findings
→ Reality State Changes
→ Interpretation Deltas（如有）
→ Recomputed Future
```

逐条说明：

- 哪个输入事实改变；
- 哪个现实状态改变；
- 哪个解释假设改变；
- 哪条推理路径改变；
- 哪个未来结论改变；
- 哪些未来结论保持不变；
- 为什么。

如果未来结论变化无法追溯到现实状态或解释差量，视为验收失败。

---

## 十一、评价体系

禁止只报告一个 accuracy。

至少分账：

### 1. Blind Historical Evaluation

评价冻结后的历史盲断：

- 中心落点命中；
- 允许替代落点命中；
- 部分命中；
- 时间窗偏差；
- 领域错配；
- 方向错误；
- 假阳性；
- 弃权率；
- taxonomy gap。

### 2. Blind Future Evaluation

只评价结果揭晓前已冻结、到期后才观察的未来预测。

### 3. Verified-State Future Evaluation

评价仅吸收现实状态后的未来预测。

### 4. Calibrated Future Evaluation

评价显式解释校准后的未来预测。

校准是否改善，必须在相同冻结 cohort、相同评分协议和未来到期结果上比较，不能用历史核验结果直接证明。

在事件边界与样本不足时，输出 `NOT_READY`，不得制造伪精确百分比。

---

## 十二、实施顺序

### Phase 0：事实审计与决策包

只读，不改代码。

交付：

- 当前状态图；
- 已实现/部分实现/未实现矩阵；
- 现有 as-of 数据对象与本提示词概念映射；
- 无反馈路径缺口；
- 校准语义缺口；
- 最小变更方案；
- 风险与迁移策略。

必须等待用户批准。

### Phase 1：无反馈基础预测证明

目标：不提供任何命主历史反馈，也能生成并冻结：

- 历史重大事件候选；
- 截止状态假设；
- 未来预测；
- 条件分支。

优先复用现有冻结、结构轨、假设状态与未来投影对象。

### Phase 2：核验与现实状态修订

目标：复用现有 verification / adjudication / verified state 链，允许部分核对，未核对领域保持未验证，不强迫完整前运核对。

### Phase 3：解释校准差量

目标：新增或收敛 case-scoped `InterpretationDelta`，建立证据门、人工门、父版本和回滚，不触碰全局生产规则。

### Phase 4：未来重新推演与差异证明

目标：分别从 blind hypothesis state、verified state、calibrated interpretation + verified state 重新推演，证明输出不是文案改写。

### Phase 5：评价与无泄漏 harness

目标：建立历史盲测、未来到期观察和校准后未来比较的独立账本与评分协议。

### Phase 6：旁路集成

目标：先接入手动/旁路入口与归档，不切换正式生产默认入口。

### Phase 7：生产切换评审

只有在证明物和回归门全部通过、用户显式批准后，才讨论默认入口切换。

---

## 十三、首个范围

首个完整闭环限定为：

- 主领域：事业；
- 显式传播领域：财富；
- 支持当前问题路由；
- 支持历史盲断、当前状态、未来预测；
- 支持部分核验；
- 支持现实状态更新；
- 支持 case-scoped 解释校准；
- 支持修正前后差异。

家庭、学业、婚姻、健康在该阶段允许明确 `ABSTAIN` 或 `NOT_IMPLEMENTED`，不得以占位文本伪装完成。

---

## 十四、验收证明物

不能只以测试通过作为完成标准。至少提交：

1. 一个完全不含命主历史反馈的 `BLIND_BASELINE`；
2. 该基线的冻结哈希与可复现证明；
3. 不进入 Mode B 仍能产出未来预测的演示；
4. 同一基线的部分核验记录；
5. `VERIFIED_STATE_REVISION`；
6. 至少一个合法局部 `InterpretationDelta`，或明确证明该案例证据不足而拒绝校准；
7. 重新计算的未来预测；
8. 修正前后结构化差异；
9. 原始基线未被覆盖的证明；
10. 反馈泄漏负向测试；
11. 未核验候选污染事实状态的负向测试；
12. 单案反馈不得修改全局规则的隔离测试；
13. 历史与 future outcome 分账测试；
14. 现有生产入口未被意外切换的隔离测试；
15. 全量回归测试结果。

---

## 十五、最终不变量

1. 无反馈也能预测。
2. 核验和校准都是可选项。
3. 原始盲态结果不可变。
4. 反馈不得泄漏到基线。
5. 现实状态更新与解释校准分离。
6. 校准是局部、可解释、可回滚、case-scoped 的。
7. 修正后未来必须重新推理。
8. 过去与未来共享核心结构，但观测与评分分账。
9. 历史命中不能冒充未来准确率。
10. 单案反馈不能自动修改全局规则。
11. 证据不足时必须弃权或保持未校准。
12. 在证明物达标并获得用户批准前，不切换生产默认入口。

---

# 第四部分：建议讨论后锁定的决策

## 决策 1：产品层是“两模式”，内部是否接受“三种预测制品”

推荐：接受。

- `BLIND_BASELINE`
- `VERIFIED_STATE_REVISION`
- `CALIBRATED_REVISION`

这样可以避免把现实状态更新和命理解释校准混在一起。

## 决策 2：第一阶段范围

推荐：只做事业完整闭环，财富仅走显式传播；其他领域明确弃权。

## 决策 3：单案校准权限

推荐：默认只允许 case-scoped 差量；改变结构主判、对象映射或取用必须满足多证据门并经人工批准；永不自动修改全局规则。

## 决策 4：无反馈未来的表达

推荐：从冻结的 `HypothesisState` / 盲态截止状态假设出发，输出主预测与最多两个条件分支；不伪称 `VerifiedState`。

## 决策 5：实施授权方式

推荐：按 Phase 逐阶段批准。当前只批准 Phase 0 审计，不一次性授权 Phase 1–7。
