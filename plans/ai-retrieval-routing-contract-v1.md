# AI 检索路由与证据取用契约 v1

## 目标

在不降低决定性证据召回和盲态隔离的前提下，避免模型为了回答一个问题读取整库 Markdown 或大段理论语料。检索分为“候选定位”和“定向取证”两阶段；每次只取回答当前问题所需的最小证据。

## 资料路由

| 问题对象 | 首选入口 | 返回目标 |
|---|---|---|
| 代码符号、调用链、依赖、影响范围 | Graft MCP | 文件、符号、关系与精确代码 span |
| 架构决策、契约、案例结构与文档关系 | IWE MCP | 文档 key、标题、相关章节及必要的有限关系 |
| 理论规则及其适用语义 | `tools/as_of_theory_lookup.py` 与 `theory/*/index.yaml` | 规则 ID、派别、来源文件及候选文本；随后核验来源原文 |

IWE 是 Markdown 导航与证据图谱，不是理论 YAML 规则库的替代品。规则关键词命中只代表候选，不代表该规则适用于当前判断。Graft 图不可用时必须明确标记能力缺口，再对已定位的代码文件做窄范围检索；不得声称已经完成图检索。

## 两阶段检索协议

### A. 候选定位

只返回候选的来源、key/path、标题或符号、章节/span、命中原因和风险标记。默认不读完整正文、不扩展 references/referencedBy、不批量展开案例。默认最多 5 个候选，候选阶段输出预算 1,200 tokens。若无命中或定位不可靠，停止并报告缺口，不用扩大无关搜索补足。

### B. 定向取证

从候选中选择与问题直接相关的最多 3 个来源，只读取精确章节、代码 span 或规则条目。输出短原文、适用条件、排除条件/未知项，并明确该证据支持、部分支持还是不支持待证断言。默认阶段输出预算 1,800 tokens。IWE 单次检索默认不扩关系，且上限为 `max_documents=6`、`max_tokens=6000`、`max_document_tokens=1800`；这些是硬上限，不是目标用量，应按问题进一步收紧。

## 盲态与引用边界

- 盲态问题的检索白名单必须排除 feedback、结果报告、已揭示事实及任何会泄露答案的文档；不能因预算、召回或便利而放宽。
- 证据不足时停止扩展，标记 `insufficient_evidence`，说明还缺哪一类来源或定位信息。
- 引用必须保留可复查的来源与精确定位。规则 ID 存在、文档标题相关或图谱有边，都不能单独证明语义结论。

## 最小证据包

```yaml
question: "待回答的问题"
route: "graft | iwe | theory"
candidates:
  - key_or_path: "唯一来源"
    locator: "章节、符号或规则 ID"
evidence:
  - source: "来源路径"
    locator: "精确定位"
    excerpt: "短原文"
    supports_claim: true
    applicability: "适用条件"
    exclusions_or_unknowns: "排除条件或未知"
status: "supported | partial | insufficient_evidence | contradicted"
```

## 首批验证题

1. **代码定位**：定位理论关键词检索 API 的定义及其匹配语义；优先尝试 Graft，图不可用时记录缺口并以精确文件取证。
2. **Markdown 职责**：分别定位 IWE/理论 YAML 的职责边界，验证是否能仅用少量候选与精确章节回答。
3. **规则检索**：用一个明确关键词查询结构化规则，记录命中规则 ID/来源，再检查来源支持范围；不可把候选命中当成结论。
4. **盲态隔离**：设计一个涉及案例的检索白名单，确认反馈、结果报告和已揭示事实未进入候选或证据。
5. **规则未接入根因**：区分“规则库存在”与“推理现场消费”所需证据，不扩展成全库审计。

## 验收与记录

每题记录：检索路由、候选数、实际读取的来源/片段数、决定性证据是否召回、引用是否被原文支持、是否触及禁止资料、可观测的输入 token/输出量，以及失败属于召回、定位、取证还是判断。不能取得宿主真实 token 计数时标记 `not_measured`，不得用文档数或字符数冒充 token。

目标门槛：在决定性证据召回不下降且盲态题零次触及禁止资料的前提下，后续对照实验的平均输入 token 较宽泛读取基线下降至少 30%。该门槛在完成对照测量前保持“未验证”，不得宣称已经达成。
