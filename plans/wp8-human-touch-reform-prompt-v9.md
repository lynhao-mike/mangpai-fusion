2. **禁正文逐段自我拆台**：正文分析区（第一至五节）禁用下表所列话术（v9 已按实战高频补齐）：

   > 注：**`不宜` 类不入本表**。"不宜"在正常建议里合法（如"不宜加杠杆"），它由检查 3d 的虚词黑名单按上下文管；检查 1 已单独拦截"不宜妄断"。

### 3.3 流年断法三要素

每一年必须明确回答：① **动在什么事**（岗位 / 大额收支 / 合同 / 感情 / 身体）；② **主倾向是什么**（进账还是垫资、升权还是换岗、成局还是摩擦——不准写"机会与成本并存"）；③ **怎么操作**（一句具体可执行动作）。

### 3.4 裁决义务

展示各派分歧后必须给出"我采信 X 为主、Y 为辅，理由是……"的明确站队；写"各有道理 / 尚难定论"视为任务未完成。举证与呈现分歧不等于骑墙和稀泥。

| 类别 | 内容 | 引擎变更后 |
|---|---|---|
| **永续层** | §3.1 三大病灶禁令、§3.2 翻译表、§3.3 流年三要素、§3.4 裁决义务、Linter 检查 1/2/3a/3b/3c/3d、v7 模板的节结构与写作纪律 | **永久有效，无需任何改动**。这些约束的是"怎么写人话"，不是"盘面数据长什么样" |
| **契约层** | Linter 检查 4 的地址正则、边号正则、规则 ID 正则；报告头部的 schema 指纹行 | **必须同步**。且由 `_contract_health()` 自检 + 契约测试双重保证"忘了同步会被发现" |

**判断口诀**：一条规则如果只在**文字的写法**上作判断，它属于永续层；如果它需要**认识引擎输出的具体格式**，它属于契约层。

#### 3.5.2 引擎变更同步清单

当 `engine/` 或 `tools/query_theory.py` 发生下列变更时，按表同步：

| # | 引擎变更类型 | 是否影响契约层 | 必须同步的事项 |
|---|---|---|---|
| 1 | **地址格式变更**（如 `Y.s` → `year.stem`，或 `DY5.b` → 其他） | ✅ 严重影响 | ① 更新 `tools/human_touch_linter.py` 的 `ADDR_RE`/`DY_RE`/`LN_RE` 与 `SAMPLE_ADDRESSES`；② bump `ADDRESS_SCHEMA_VERSION`（`addr/v1` → `addr/v2`）；③ 跑 `pytest tests/tools/test_human_touch_linter.py::test_linter_contract_matches_live_engine` 确认转绿；④ 在报告头部指纹行使用新契约号 |
| 2 | **边号编号规则变更**（新增边类型导致整体后移；或边号格式由 `e\d{3}` 改为其他） | ✅ 严重影响 | 同 #1（更新 `EDGE_RE` 与 `SAMPLE_EDGE_IDS`）。**注意：边号无独立版本标记，`RelationGraph.schema_version` 不变也可能整体后移——这是最危险的静默失效场景，只能靠契约测试发现** |
| 3 | **新增边类型 / 关系种类，但编号格式不变** | ⚠️ 通常无害 | 契约测试应仍通过（新边号仍匹配 `e\d{3}`）。但需人工确认：旧报告引用的边号**语义是否漂移**（同号是否还指向同一关系）。若有漂移，旧报告须加注或重跑 |
| 4 | **新增事实字段**（如新的 strength 指标、新的 structures 状态） | ❌ 不影响 | 无需同步。报告可选择性引用新字段；Linter 不强制 |
| 5 | **`schema_version` 字符串变更** | ⚠️ 视情况 | 检查是否伴随 #1/#2 的格式变化。若只是版本号递增而格式未变，只需更新报告头部指纹行的 schema 名 |
| 6 | **`tools/query_theory.py` 规则 ID 格式变更** | ⚠️ 可能 | 若新 ID 不被 `RULE_RE`/`RULE_CN_RE` 匹配，更新正则与样本；否则无需同步 |

#### 3.5.3 契约失效时的预期行为（写进 Linter docstring）

引擎变更但 Linter 未同步时，`lint_human_touch(text)` 对**任何**输入都返回：

```
[检查4] Linter 契约失效（ADDRESS_SCHEMA_VERSION=addr/v1）：地址样本 'Y.s' 失配；边号样本 'e001' 失配。引擎地址/边号 schema 可能已变更，请按 docs/analysis_human_touch.md §3.5.2 同步更新本文件的样本常量与正则后再运行。
```

**这是设计意图，不是 bug**：宁可让所有报告同时报同一个错（响亮失败），也不准静默放过（假阴性）。

## 6. T4：防骑墙门禁 `tools/human_touch_linter.py`

### 6.1 硬性要求

- 新建文件，**零第三方依赖**：仅用标准库（`re` / `sys` / `pathlib` / `argparse`）。
- 入口锁定 UTF-8：`if hasattr(sys.stdout, "reconfigure"): sys.stdout.reconfigure(encoding="utf-8")`（stderr 同理）。
- 可 import：`from tools.human_touch_linter import lint_human_touch`。
- 函数签名：`def lint_human_touch(text: str) -> list[str]`——返回 ERROR 字符串列表，**空列表 = 通过**；对任意输入不得抛异常（内部 try/except 兜底，异常时返回一条 `[检查0] 内部异常: …`）。
- ERROR 字符串格式：`[检查N] L{行号}: {说明}`（无法定位行时用 `[检查N] {说明}`）。
- CLI：`python -m tools.human_touch_linter <file.md> [more.md ...]`；支持多文件；全部通过 exit 0，任一文件有 ERROR 则逐条打印到 stderr 并 exit 1；无参数打印用法 exit 2。
- 读文件用 `utf-8-sig`（`errors="replace"`），兼容 CRLF 与 BOM。

### 6.2 检查 1（全局禁用词）—— 永续层

- 禁用词表：`或许`、`可能`、`也许`、`不宜妄断`、`难以定论`、`仅供娱乐`。
- 作用域：全文，**豁免三处**：
  1. 《先把话说死》节正文——从匹配 `^##\s*先把话说死` 的标题行起，到下一个 `^##\s` 标题行之前（不含该标题行）；
  2. **《附：关键依据索引》节**——从匹配 `^##\s*附` 的标题行起，到文档末尾。**豁免理由（实测）**：`theory/_light_index.json` 共 3471 条记录，标题含禁用词的有 2 条——`M2-Y-113`「满盘泄克无生助=**难以**成就」、`ZP-SAMPLE-010`「四吉神失宜也**可能**破格」。若不豁免，《附》中引用这两条即误报。**该节仍受检查 4 严格约束**（必须含地址/边号/规则 ID），防止用豁免区掩盖引用缺失；
  3. 文末边界声明引用块——从文档末尾向前找最后一个连续 `>` 行组，整组豁免。
- 豁免区外命中任一禁用词即 ERROR（按子串匹配，"不可能"一并命中，属预期）。

### 6.3 检查 2（正文反拆台 / 反骑墙）—— 永续层

- 作用域：匹配 `^##\s*一、` 的标题行**之后**，到 `^##\s*六、` 标题行**之前**；若无 `## 六、`，则延至 `^##\s*附` 标题行或文档尾。
- 禁用话术表（命中即 ERROR，v9 已按实战补齐）：
  `不能据此直接断`、`不能据此断`、`不能直接裁成`、`不能只凭`、`不作单向`、`不等于必然`、`不代表必然`、`不决定吉凶`、`不足以直接定为`、`不足以断`、`尚不能确认`、`尚不认定`、`宜核验是否`、`机会与调整成本并存`、`机会与挑战并存`、`吉凶参半`。
- **不入本表的类别**：`不宜` 构成的正常否定（如"不宜加杠杆""不宜冲动"）。理由：这类表达是**有立场的判断**，正是本改造要的保护对象；"不宜妄断"已由检查 1 单独拦截，虚词化的"宜重视/注意防范"等由检查 3d 管。**不得把 `不宜` 加入本表**——那会误杀正文的正当否定式结论。

### 6.4 检查 3（结构缺陷）—— 永续层

- **3a**：必须存在 `^##\s*〇、一句话定调` 标题，且其下（至下一个 `^##\s`）有非空正文行；否则 ERROR。
- **3b**：全文必须同时出现三个标记词 `板上钉钉`、`大概率`、`我不编`；缺一即 ERROR。
- **3c**：第五节（`^##\s*五、` 至下一个 `^##\s`）必须出现裁决标记词之一：`我采信`、`我的最终裁决`、`我的裁决`、`站队`。**无条件要求**（不限于"出现分歧时"），防止用近义词绕流；缺节同样 ERROR。
- **3d**（建议 / 流年行实断检查）：
  - 目标行定义（满足其一）：
    - (i) 行内含 `建议：` 或 `建议:`，且该行不是标题行，且**剔除所有 `**...**` 粗体片段后**仍含 `建议` + 冒号；
    - (ii) 表格数据行：整行以 `|` 开头（允许前导空白），且**第一个单元格剔除 `*`、`` ` ``、`~` 等行内修饰符后**匹配 `^\s*20\d\d`。
      > 说明：去掉修饰符是为了不漏检 `| **2026 丙午** |` 这类加粗写法。
  - 目标行命中禁用虚词即 ERROR：`宜重视`、`注意防范`、`谨慎行事`、`不宜盲目`、`注意风险`、`宜谨慎`。
  - 目标行还必须至少包含一个动作动词，否则 ERROR。动词表（模块级常量 `ACTION_VERBS`，共 30 个，允许后续扩充但须同步测试）：
    **核心 15**：`签约`、`立字据`、`锁死`、`止损`、`盘点`、`体检`、`竞聘`、`考证`、`深耕`、`暂缓`、`分批`、`核查`、`留存`、`剥离`、`主攻`；
    **扩充 15**：`挂靠`、`转岗`、`回款`、`隔离`、`复查`、`领证`、`兑现`、`落袋`、`立规矩`、`砍掉`、`嫁接`、`报备`、`续约`、`退出`、`申遗`。
  - 不参与 3d 的行：表格分隔行（含 `|---` 或 `---`）、表头行（第一个单元格含 `流年` 或 `年份`）、`#` 开头的标题行。

### 6.5 检查 4（依据索引非空）—— 契约层（含契约自检）

**先做契约自检，通过后才判定报告内容**：

```python
ADDRESS_SCHEMA_VERSION = "addr/v1"      # 与 engine.facts 地址体系对应；引擎改格式时必须 bump

SAMPLE_ADDRESSES = ("Y.s", "M.b", "D.s", "H.b", "DY5.b", "LN2026.s")
SAMPLE_EDGE_IDS   = ("e001", "e013")

def _contract_health() -> list[str]:
    """验证正则仍能匹配样本。返回问题列表，空=健康。"""
    problems = []
    for a in SAMPLE_ADDRESSES:
        if not (ADDR_RE.search(a) or DY_RE.search(a) or LN_RE.search(a)):
            problems.append(f"地址样本 {a!r} 失配")
    for e in SAMPLE_EDGE_IDS:
        if not EDGE_RE.search(e):
            problems.append(f"边号样本 {e!r} 失配")
    return problems
```

**契约失效时（`_contract_health()` 非空）**：立即返回一条 ERROR 并**中止检查 4 的其余判定**：

```
[检查4] Linter 契约失效（ADDRESS_SCHEMA_VERSION=addr/v1）：地址样本 'Y.s' 失配；边号样本 'e001' 失配。引擎地址/边号 schema 可能已变更，请按 docs/analysis_human_touch.md §3.5.2 同步更新本文件的样本常量与正则后再运行。
```

**这是设计意图**：宁可让所有报告同时报同一个错（响亮失败），也不准静默放过（假阴性）。

**契约健康时**，才继续判定报告内容：

- 必须存在标题匹配 `^##\s*附` 且标题含 `依据索引` 的节；否则 ERROR。
- 该节内必须至少各出现一次：
  - **盘面事实标识**（任一）：地址 `\b[YMDH]\.[sb]\b`、大运地址 `\bDY\d+\.[sb]\b`、流年地址 `\bLN\d{4}\.[sb]\b`、边号 `\be\d{3}\b`；
  - **理论条目引用**（任一）：
    - 拉丁规则 ID：`\b(?=[A-Z0-9-]*[A-Z])[A-Z0-9]{1,6}-[A-Z0-9]{1,6}-\d{2,}\b`（覆盖 `M1-D-012`、`M3-R-105`、`M2-Y-098`、`ZP-ZPZQ-20260619-032`、`G-XF-020` 等式样；前置正向前瞻要求至少含一个英文字母，避免把 `1986-07-31` 误判为规则 ID）；
    - 中文规则 ID 变体：`\b[A-Z]{1,4}-[甲乙丙丁戊己庚辛壬癸]-[子丑寅卯辰巳午未申酉戌]\b`（覆盖 `QT-癸-戌`、`QT-壬-寅` 等式样）；
    - 或出现 `source_ref` 字样；
    - 或出现 `文件名:行号` 式出处（如 `d02-theory.md:512`）。

### 6.6 建议实现常量（供执行参考）

```python
ADDR_RE     = re.compile(r"\b[YMDH]\.[sb]\b")
DY_RE       = re.compile(r"\bDY\d+\.[sb]\b")
LN_RE       = re.compile(r"\bLN\d{4}\.[sb]\b")
EDGE_RE     = re.compile(r"\be\d{3}\b")
RULE_RE     = re.compile(r"\b(?=[A-Z0-9-]*[A-Z])[A-Z0-9]{1,6}-[A-Z0-9]{1,6}-\d{2,}\b")
RULE_CN_RE  = re.compile(r"\b[A-Z]{1,4}-[甲乙丙丁戊己庚辛壬癸]-[子丑寅卯辰巳午未申酉戌]\b")
FILELINE_RE = re.compile(r"[\w\-.]+\.md:\d+")
```

### 6.7 已知取舍（写进模块 docstring，避免后续"优化"破坏语义）

1. `可能` 按子串匹配会一并拦截"不可能"——这是规范选择（用"不会/绝不"替代），不是 bug。
2. 检查 1 的豁免区为三处（《先把话说死》《附》依据索引节、文末引用块），**不豁免正文中的行内引用**——防止用行内引用绕过禁令。其中《附》节豁免的理由是"客观出处索引中可能含古籍/规则原标题"，该节仍受检查 4 约束。
3. 检查 3d 只覆盖"含 `建议：` 的行"与"流年表首列为年份的行"两类，不覆盖散文段落里的建议句——后者由 Step 6e 人工纪律约束。
4. `不宜` **不得**加入检查 2 禁用表：正常否定式判断（"不宜加杠杆"）是有立场的结论，正是本改造要保护的；"不宜妄断"已由检查 1 拦截，虚词化的"宜重视/注意防范"由检查 3d 拦截。
5. **契约自检失败时报"契约失效"而不是放过**——这是抗引擎变更的核心设计。任何人不得为了"让报告通过"而删除 `_contract_health()` 或清空样本常量；正确做法是按 §3.5.2 同步正则。

```python
def test_linter_contract_matches_live_engine():
    """契约哨兵：Linter 正则必须匹配当前引擎真实输出。

    引擎若变更地址格式或边号编号规则，本测试失败 → 强制同步 Linter。
    缺 PyYAML 等引擎依赖、或探针执行失败时 skip（不阻断门禁）。
    """
    import json as _json
    import subprocess as _sp
    import sys as _sys
    from pathlib import Path

    ROOT = Path(__file__).resolve().parents[2]
    if not (ROOT / "engine" / "cli.py").exists():
        pytest.skip("engine/cli.py 不存在")

    try:
        import yaml  # noqa: F401
    except ImportError:
        pytest.skip("缺 PyYAML，跳过引擎契约测试")

    # 带 --dayun-index/--liunian，一次运行覆盖原局(Y.s/M.b)、大运(DY4.*)、
    # 流年(LN2026.*) 三类地址与边号(e001)正则。
    cmd = [
        _sys.executable, "-m", "engine.cli", "relations",
        "--pillars", "庚申 戊寅 壬子 辛丑", "--gender", "乾",
        "--dayun-index", "4", "--liunian", "2026", "--json",
    ]
    try:
        proc = _sp.run(cmd, cwd=ROOT, capture_output=True, encoding="utf-8", timeout=180)
    except Exception as exc:          # 超时 / 启动失败等
        pytest.skip(f"engine.cli 探针执行失败: {exc}")
    if proc.returncode != 0:
        pytest.skip(f"engine.cli 探针退出码 {proc.returncode}")

    data = _json.loads(proc.stdout)

    # 地址来源：优先 edges[].members（必然存在且直接对应边引用）；
    # members 元素一律 str，非字符串元素过滤掉，避免 re.search 抛 TypeError。
    addrs = sorted({
        m for e in data.get("edges", [])
        for m in e.get("members", ())
        if isinstance(m, str)
    })
    # 兜底：若 edges 未提供地址，退回 nodes（兼容两种输出形态）
    if not addrs and "nodes" in data:
        addrs = [n[0] for n in data["nodes"] if isinstance(n, (list, tuple)) and n]

    edge_ids = [
        e["id"] for e in data.get("edges", [])
        if isinstance(e, dict) and isinstance(e.get("id"), str)
    ]

    from tools import human_touch_linter as mod
    assert addrs, "engine.cli relations 未返回任何边成员地址"
    assert all(
        mod.ADDR_RE.search(a) or mod.DY_RE.search(a) or mod.LN_RE.search(a)
        for a in addrs
    ), (
        f"契约失效：引擎地址 {addrs} 存在不被 Linter 正则匹配的项。"
        f"请按 docs/analysis_human_touch.md §3.5.2 同步 "
        f"ADDRESS_SCHEMA_VERSION={mod.ADDRESS_SCHEMA_VERSION!r}、SAMPLE_ADDRESSES 与正则。"
    )
    assert edge_ids and all(mod.EDGE_RE.search(e) for e in edge_ids), (
        f"契约失效：边号 {edge_ids} 中有不被 EDGE_RE 匹配的项。"
    )
```

> **v9 澄清（纠正 v8 的错误论断）**：实测 `engine.cli relations` 顶层键为 `['schema_version','chart_id','profile','nodes','edges','pair_index','muku','variants']`，**`nodes` 键存在**，因此 `data["nodes"]` 不会 KeyError。改用 `edges[].members` 的理由是它**必然存在**且直接对应边引用的地址，比 `nodes` 更贴近检查 4 的语义；`nodes` 保留为兜底。探针命令补 `--dayun-index 4 --liunian 2026` 的目的是让单次运行同时验证 `DY4.*` 与 `LN2026.*` 正则，覆盖更全。
